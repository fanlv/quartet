# iOS AGENTS.md

本文件描述 iOS 客户端当前的架构与开发约定。工程目录为 `ios/`，产品显示名为 Sophia。已实现的功能清单、未完成项和验证边界见 `ios/README.md`，不要在本文重复。

客户端只连接用户自己运行的 Quartet 后端，不在设备上运行 Agent，也不直接访问后端机器的文件系统；所有能力都由后端 HTTP API 与 SSE 提供。

## 工程与构建

- 环境：macOS、Xcode 26 或更新版本、iOS 26 部署目标、CocoaPods 1.15 或更新版本。最低系统版本以项目文件中的 deployment target 为准。
- 打开 `Quartet.xcworkspace`，不要直接打开 `Quartet.xcodeproj`。当前应用只使用 Apple 系统框架，CocoaPods 仅用于维护 workspace 和后续依赖接入。
- 构建与测试命令都在仓库根目录的 Makefile 里：`make pod-install` 同步依赖，`make build-ios` 真机 Debug 构建，`make test-ios` 模拟器无签名构建，`make e2e-ios` 在模拟器跑原生 UI 测试；模拟器机型由 `IOS_TEST_DESTINATION` 覆盖，派生数据统一放在临时目录。
- Xcode 工程使用手工维护的文件引用，没有启用文件系统同步组。新增或删除源文件、资源文件时必须同步改动工程文件里的四处登记：构建文件条目、文件引用条目、所属分组的子项列表、对应构建阶段的文件列表；标识符沿用现有的连号十六进制风格。只把文件放进目录而不登记，构建会以找不到符号失败。
- 打包资源（字体、字符串目录）除登记进资源构建阶段外，字体还需在 Info.plist 的字体列表中声明。
- 本目录的 Xcode 构建只能在 macOS 环境验证；Linux 上仅进行静态工程检查与 Go 契约测试。

## 测试与验证

- `ios/` 下有 Go 契约测试，用子串和正则断言 Swift 源码中的关键不变量：登录不落地密码、缓存不写入分享令牌、刷新与分页的世代守卫、工作空间按版本号做局部更新、聊天历史加载与幂等发送的关键分支等。改动这些区域后先在 Linux 上跑它；测试失败时修代码，不要为了通过而放宽断言。
- 原生 XCUITest 覆盖首次连接、运行台筛选与搜索、对话、Graph、Agent 管理、统计和设置主路径，另有截图用例。启动参数进入 Debug 专用的预置数据模式，用固定数据驱动界面，不读写真实 Job；少数标注为 live 的用例才连真实后端。
- 预置数据模式下语言固定为简体中文（另有专门的英文用例），并使用独立的 UserDefaults 套件与缓存目录，避免污染真机数据。
- UI 测试依赖稳定的无障碍标识定位控件：新增可交互控件时一并给出标识，重命名标识要同步改测试。
- 开发过程中不主动新增单元测试，除非明确要求。
- 真机 Keychain、相机与照片权限、弱网、锁屏与长时间后台挂起、Web 与 iOS 的并发一致性仍需真实环境单独验收，不能以模拟器结果代替。

## 分层与目录

- `Quartet/App` — 应用入口与根视图。根视图按连接阶段切换启动页、连接页和主界面，并统一挂载全局主色、全局键盘收起、全局错误浮层。主界面是自绘的底部五栏（最近任务、定时任务、文件、统计、设置），栏高与安全区高度通过环境值下发给各页滚动内容；推入聊天或键盘弹出时隐藏该栏。
- `Quartet/App/AppModel` — 唯一的全局状态对象，主线程隔离。负责连接阶段与登录会话、权限集合、工作空间与 Job 快照及分页、Graph 运行状态观察、缓存与陈旧标记、乐观执行态、场景切换、Job 完成通知，以及预置数据模式的全部假数据。视图不自建网络客户端，统一从它获取。
- `Quartet/Core/Networking` — HTTP 客户端（值类型，按服务地址构造，统一鉴权头、超时与错误包装）、SSE 事件流、分片上传、聊天图片加载。
- `Quartet/Core/Models` — 全部请求与响应结构体集中在一个文件里，与后端共享结构一一对应。
- `Quartet/Core/Persistence` — 仪表盘快照的磁盘缓存与已发送消息历史。历史按服务地址加工作空间分作用域并限长；草稿、最近选中的工作空间等偏好项也按服务地址（必要时再加账号）分作用域，换服务器或换账号不串数据。
- `Quartet/Core/Security` — Keychain 读写封装。当前登录状态完全由系统 Cookie 存储持有，此处只用于清理历史版本残留的令牌，不再写入任何凭据。
- `Quartet/Core/Localization` — 语言选择（跟随系统、简体中文、英文）与字符串取值入口。
- `Quartet/Core/Design` — 主题色、排版入口与字体栈、共享控件与共享的导航栏/弹窗修饰，是所有视觉参数的唯一来源。
- `Quartet/Features/<领域>` — 按页面领域分组：连接、运行台与 Job 详情、聊天（含消息渲染、Markdown、附件、图片标记、应用内 Web 预览）、Graph（运行监控、工作流启动、路径选择）、定时任务、文件浏览、统计、设置（Agent 目录与管理、默认值、环境变量、角色、消息预设、技能、工作空间、用户配置）。领域内的视图模型与视图放在一起。
- `Quartet/Resources` — 随包字体。字符串目录与资产目录在 `Quartet/` 下。
- `QuartetUITests` — 原生 UI 测试。

新增能力优先落进已有领域目录，不要在 `Features` 下按控件或按技术类型另开分组。跨领域复用的视觉组件放进设计层，跨领域复用的数据能力放进核心层，不要在某个页面里私藏后被另一个页面反向依赖。

## 数据与网络

- 优先复用 Quartet 现有 HTTP API 与 SSE；新增接口前先确认现有接口无法表达该能力。
- 只连接单个可配置后端。服务地址保存在偏好设置，登录用用户名和密码换取 Cookie 会话；密码不持久化、不写入日志。
- 同一时刻只连接一个后端，但偏好设置里另存一份服务地址清单，供设置页与连接页快速切换。清单条目按归一化后的 base URL 去重，只记地址、备注名和上次登录的用户名，不存任何凭据。连接成功会自动把当前地址写回清单。
- 切换服务器不撤销其他服务器的会话，也不清它们的 Cookie：切回去时登录态若仍有效就免密直连。只有用户显式退出，或删除某条清单记录时，才清理对应服务器在本机的会话 Cookie。切换会推进连接世代、清空内存与磁盘上的看板数据，保证两台服务器的数据不串台。
- 服务地址在构造客户端时统一规范化：只接受 HTTP/HTTPS、拒绝内嵌用户名或密码、去掉查询与片段；跟随入口跳转时拒绝 HTTPS 降级到明文地址。
- 所有请求带客户端标识头。除安全方法外，认证请求必须带登录返回的 CSRF 令牌。默认沿用系统超时，只有明确耗时长的操作（如技能安装）才单独放宽。
- 认证失效统一走未授权回调：清理本地会话状态并回到连接页，同时把完整错误交给用户，不静默重试。
- API 错误必须保留请求方法、完整 URL、HTTP 状态和完整响应正文，并允许用户复制；不截断、不改写、不吞掉任何错误信息。
- 列表轮询走条目标签协商，未变更时不重绘列表；分页游标与筛选条件绑定，切换筛选先作废当前可见页再拉新数据。
- 实时更新用 SSE，且同一时刻只保留一条连接：Graph 运行处于活跃状态时订阅 Graph 事件流，运行结束或转入等待输入后切回普通 Job 事件流。断线按次数退避重连，重连成功后重新读取快照与历史再继续增量。
- 发送消息与创建任务必须幂等：消息带客户端消息标识，创建任务带稳定的意图标识；重试冻结整个请求体，只有语义载荷变化才换新标识。服务端回显的标识与本地不一致时按错误处理，不静默接受。
- 应用从后台返回时重新读取服务端快照，不假设 SSE 在后台持续存活；进入后台时记录是否存在待同步内容。
- Job 完成通知只在应用处于后台时发出，前台由界面自身反映状态变化。通知权限只在首次需要时申请，申请失败要把原始错误暴露给用户。
- 附件上传有明确的体积上限，超限图片先按质量递降压缩再上传，压缩后仍超限则报错而不是静默截断。
- 应用内 Web 预览只加载 HTTP/HTTPS 地址，并把当前 Cookie 会话注入 WebView；其他协议一律不打开。

## 状态与并发

- 全局状态对象与各页视图模型都是主线程隔离，网络与解码在异步任务里做，回到主线程再改发布属性。
- 所有可被并发触发的刷新、分页、流式订阅都带世代守卫：切换服务地址、切换工作空间、重新登录都会推进世代，过期任务的结果必须丢弃，不能覆盖新状态。
- 缓存只用于加速首屏和离线展示，不能成为真相来源：缓存里不写任何敏感令牌，也不允许由缓存改写权威的服务地址与身份。
- 流式增量先合并再统一提交，避免每个增量都触发一次列表刷新与滚动锚点变化。

## UI 规范

### 通用原则

- 全 App 只有一套视觉语言。实现或调整控件前先查找同类现有实现，优先复用其组件、布局、间距、颜色、选中态和交互，不为同一语义另造一套样式。
- 颜色、字号这类视觉参数只从统一的设计入口取，不在业务视图里写死；需要整体调整时改入口的一处配置，不逐个页面改调用点。
- UI 状态不能只依赖颜色表达，所有操作需支持 VoiceOver 和动态字体。
- 可点击元素保留至少 44pt 的触摸区域，视觉元素可以更紧凑。

### 主题与颜色

- 所有颜色取自统一的主题入口，每个颜色同时给出浅色与深色两套取值，不在视图里写死色值，也不使用系统语义色替代主题色。
- 颜色按语义使用，不按观感挑选：主色承担品牌与主操作，另有成套的警示、失败/危险、停止/中性、升级提示和终端配色，各自都有配套的前景色用于承载其上的文字。
- 运行状态到颜色的映射由主题统一解析，不在各页面各写一套状态判断。
- 背景分三层：页面底色、卡片、卡片内分组，卡片描边和行分隔线统一用主题分隔色。
- 文本只有主次两级前景色；需要更弱的层级时降低次级色的不透明度，不引入新色值。
- 工作空间等按标识着色的场景走主题提供的取色函数，保证同一对象在各页面颜色一致。

### 排版与字体

- 全部字号只经统一的排版入口取字体，不在视图里写死磅值；聊天页走单独一档整体更小的刻度，其余页面共用全局刻度，两档刻度各自只有一个可调参数。
- 正文字族随 App 打包（思源黑体 SC，SIL OFL，简体常用字子集），中英文同源以保证混排的行高与字重一致；生僻字与繁体自动回退到系统苹方。等宽与圆体场景保留系统字族。换字族只改排版入口的一处配置。
- 需要加粗或强调时在排版入口按字重取字体，不在文本上叠加粗修饰：追加字形特征会丢掉中文回退链，汉字会掉回系统字体。

### 导航栏与返回按钮

- 导航栏标题统一走统一的标题入口：inline 展示、与仪表盘同款字号字重、单行截断，并保留真实导航标题以供无障碍朗读。
- 所有位于导航栈内、需要返回上一级的页面，返回按钮样式必须完全一致，以聊天页那颗为基准：导航栏左侧的纯箭头按钮，跟随全局 tint 着色，不带文字标签、不带按钮底色和分组背景，字号取全局刻度（聊天页也不用它那档缩小刻度），带“返回”无障碍标签。
- 该返回按钮只从统一的导航返回入口获取，不在页面里自造：它同时负责隐藏系统默认返回按钮并保持边缘右滑返回手势可用。禁止使用系统默认返回按钮（会带上一级页面的标题文本）、禁止在调用点改箭头颜色或字号、禁止用“返回”文字按钮代替箭头。
- 新增可被推入导航栈的页面时必须挂上这颗返回按钮，包括逐级下钻的目录、详情等中间页；只有导航栈的根页面例外。
- 导航栏右侧动作统一用纯图标按钮：plain 按钮样式、主色图标、全局刻度字号，横向尺寸由自身布局决定，保留 44pt 高触摸区域；多颗按钮相邻时不额外补内边距，避免撑开间隙、挤压居中标题。
- 弹窗和全屏浮层的根页面不属于导航栈的下一级，用关闭动作而不是返回箭头。

### 弹窗与浮层

- 所有弹窗统一遵循首页“任务操作”弹窗的样式、布局与间距：inline 标题、卡片化的动作分组、行间分隔线内缩、统一的页面底色和左右内边距。
- 自定义弹窗不显示“取消”按钮，支持手势关闭的 Sheet 直接省略该按钮，确认弹窗需要保留退出操作时统一使用“关闭”。
- Sheet 统一套用共享的弹窗样式入口，以获得一致的拖动指示、圆角、背景色和边缘右滑关闭；高度用系统 detent 表达，不靠固定尺寸撑。
- 同一弹窗内的多个步骤（动作列表、重命名、删除确认）在同一个浮层里切换并带过渡动画，不逐级叠加新浮层。
- “从若干项里选一个”统一使用共享的选择弹窗组件，不在各页面另写选项列表；收藏项、不可选项、行内错误与重试都由该组件表达。
- 系统 alert 只用于确认破坏性或不可逆动作：取消位文案用“关闭”，确认位文案写明具体动作，补充说明写清副作用。
- 完整错误详情统一走错误详情弹窗展示，全量显示且可复制；弹窗内触发的二级错误用弹窗自己的浮层，不与根视图的错误浮层争抢。

### 控件与交互

- 布尔选项统一用共享的勾选式 Toggle 样式，按场景选择行尾、紧凑或裸图标布局，不混用系统开关。
- 所有文本输入控件在键盘弹出后，点击界面上输入控件以外的任意位置都必须自动收起键盘，不单独提供“完成”等键盘收起按钮。
- “正在运行”的动效统一复用共享的呼吸圆点和边框流光：动效由时间线的当前时刻推导，列表刷新、前后台切换或关闭动画后都能接着走，不用一次性状态触发的无限循环动画。

## 文案与本地化

- 面向用户的文案一律走本地化入口取值，不在界面上直接显示硬编码字面量。
- 本地化以中文原文作为 key，源语言为简体中文，另提供英文；新增或修改文案必须同时补齐英文，缺失翻译会直接回落成中文 key 显示。
- 语言选择支持跟随系统、简体中文、英文三档；系统语言不在支持范围内时按英文解析，不依赖系统的回落顺序。
