# Agent 统一接入流程

## 用户流程

Agent 管理统一提供“安装 → 按需认证 → 验证可用”。安装状态与可用状态分开显示；只有成功创建 ACP 会话的 Agent 才允许正常执行。

- 新电脑先安装缺失程序，再完成该 Agent 的认证，最后验证。
- 已有电脑保留安装好的 CLI 和适配器，只补缺失组件。升级仍是独立的显式操作。
- 先检查已有凭据；有效则直接复用，不强制重新登录，不重置现有会话。
- 已安装但缺少认证时显示“待认证”，不与程序损坏、网络故障等不可用原因混在一起。
- 自定义 Agent 可以在缺少认证时先保存，再完成登录；其他验证失败仍拒绝保存。

## 认证入口

认证面板按 Agent 实际提供的方式展示，而不是为所有产品硬套同一条登录命令。

- 协议认证：用户主动发起，面板显示授权链接、设备码提示与完整输出；完成后自动重新验证。
- 终端认证：提供在后端电脑、同一系统用户下执行的准确命令。用户在交互终端登录，再回到面板验证；不把终端方式误当成协议认证。
- 环境变量认证：引导配置既有 Agent 环境变量，再验证；密钥不写入项目文件。
- 没有提供登录入口的 Agent：按其官方说明手工登录或配置凭据，再统一验证。

Google 官方 Antigravity ACP server 与 agy CLI 独立认证。已登录 agy 不代表官方 ACP server 已登录，Quartet 不复制两者的凭据。Claude、Codex 由其适配器读取对应 CLI 的已有凭据。

## 行为约束

后台探测不主动发起登录，并抑制自动打开浏览器。认证可以取消，有时间限制，同一 Agent 不允许同时发起多次认证；删除、升级或卸载时取消尚未完成的认证。认证过程中运行定义或环境变量变化时，要求重新验证当前配置，不把旧结果当作可用。

登录成功不等于可用：必须使用新进程重新验证 ACP 会话。失败时保留并完整展示协议错误与输出。

网页发起认证不意味着所有远程 OAuth 都能直接完成：本机回调要求浏览器能访问后端电脑的回调端口；远程部署优先使用设备码、终端登录，或事先配置端口转发。
