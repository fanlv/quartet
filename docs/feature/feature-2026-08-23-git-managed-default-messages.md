# Git 管理的全局 / 项目预置消息

> 状态：已实施
> 范围：Web 设置页、首页输入框、Job 对话输入框、Memory 持久化

## 1. 背景与术语

当前首页和 Job 对话页都提供“本地历史”列表。发送内容按 workspace 保存在浏览器本地，最多保留最近 50 条；用户点击发送后即写入，不依赖消息最终是否发送成功。

这套能力适合临时回看，但存在以下限制：

- 换浏览器或设备后无法复用。
- 不能区分“临时发送记录”和“长期保留的常用内容”。
- 不能为全部项目或某个项目预先维护固定消息。
- 浏览器数据不进入 Memory 仓库，无法通过 Git 审阅、同步和恢复。

本功能把需求中的“默认发送消息”定义为**预置消息**：用户从列表中主动选择后，系统把预置文本填入输入框，用户检查或编辑后再确认发送。它不是进入项目后自动发送的消息，也不会自动注入 Agent 上下文。

文档中的“项目”对应 Quartet 的 workspace。当前实例内的项目配置使用 workspace ID 绑定，不使用容易变化的项目名称或工作目录。

## 2. 目标

- 在设置页维护多条预置消息。
- 每条配置归属于“全部项目”或一个具体项目。
- 当前项目的输入框可以同时使用项目预置消息和全部项目预置消息。
- 预置消息保存到 Memory 的 Git 可跟踪配置目录。
- 保留现有浏览器本地历史及其交互，不把高频历史记录写入 Git。
- 支持识别、清理和重新绑定无法匹配当前项目的配置。
- 配置错误、权限错误和写入错误完整展示给用户，不静默忽略。

## 3. 核心规则

### 3.1 预置消息不会自动发送

选择预置消息后，只把原始文本填入输入框。系统不得在进入项目、创建 Job、切换项目或点击预置消息时自动发出消息。

预置消息可以包含多行文本、斜杠命令和文件引用文本，填入时保持原始内容，不做变量替换或 Prompt 渲染。

预置消息不改变输入框原有的发送语义：

- 首页输入框仍把内容作为新 Job 的第一条普通消息。
- Job 对话输入框仍按现有规则识别斜杠命令。
- 以 `/` 开头的预置消息在列表中显示“命令文本”提示，避免用户误以为它在两个入口中行为完全相同。

### 3.2 作用域与合并规则

| 配置范围 | 生效位置 | 列表位置 |
| --- | --- | --- |
| 全部项目 | 当前及未来创建的每个 workspace 首页和 Job 输入框 | “全部项目”分组 |
| 指定项目 | 仅 workspace ID 完全匹配的首页和 Job 输入框 | “当前项目”分组 |

项目配置采用补充关系，不覆盖全局配置：

1. 当前项目消息排在最前。
2. 全部项目消息排在其后。
3. 浏览器本地历史排在最后。
4. 各分组内部使用设置页中保存的顺序。
5. 不跨分组自动去重。同一文本可能既是预置消息，也出现在最近发送历史中，两者分别保留并显示来源。
6. 项目没有专属配置时，只展示全部项目消息和本地历史。

默认 workspace `ws-1` 也按普通项目处理：它可以拥有自己的项目预置消息，同时继承全部项目消息。

### 3.3 与本地历史的关系

两类内容保持独立：

| 内容 | 保存位置 | 生命周期 | 用途 |
| --- | --- | --- | --- |
| 预置消息 | Memory Git 配置目录 | 长期、可同步、可恢复 | 主动维护的常用文本 |
| 本地历史 | 浏览器 localStorage | 单浏览器、每项目最近 50 条 | 回看最近实际发送内容 |

- 本功能不迁移已有本地历史。历史里可能包含失败发送、图片、临时信息或敏感内容，不能未经确认写入 Git。
- 由预置消息填入并实际发送后，仍按现有规则进入本地历史。
- 键盘 `ArrowUp` / `ArrowDown` 继续只遍历本地历史，不遍历预置消息，保持“上一条已发送内容”的语义。
- 预置消息首期只保存文本，不保存图片、附件或本地文件副本。

## 4. 设置页设计

设置中新增独立的“预置消息”页签，避免把全局配置塞入某个项目的编辑弹窗。

页面包含：

1. **作用域选择**：可选择“全部项目”、一个现有项目或“未绑定配置”。
2. **消息列表**：展示当前作用域下的消息名称、内容预览和顺序。
3. **新增 / 编辑**：名称可选，正文必填；未填写名称时使用正文第一行作为列表标题。
4. **排序**：支持调整同一作用域内的展示顺序。
5. **删除**：删除前确认，保存后形成普通 Git 文件变更。
6. **重新绑定**：把未绑定的项目配置关联到当前实例中的一个现有项目。
7. **保存状态**：明确展示未保存、保存中、已保存、版本冲突或失败。

交互约束：

- 切换作用域或关闭设置页时，如果存在未保存修改，必须提示用户确认。
- 空列表是合法配置，表示该作用域没有预置消息。
- 项目名称相同也不影响选择，列表同时展示名称和工作目录以帮助区分。
- 保存成功后，当前打开的首页和 Job 输入框立即刷新预置消息，不要求刷新整个页面。
- 页面不得只显示“保存失败”；必须展示服务端返回的完整错误。
- 预置消息会进入共享 Git 历史。页面必须提示用户不要保存密码、令牌或其他秘密。
- 新增的页签、分组、确认框、空状态和错误提示必须同时提供中文与英文文案。

页签和操作权限：

- 具有 `config.read` 或 `workspace.read` 任一权限时可看到该页签；无写权限时以只读方式展示可访问的作用域。
- 全部项目作用域的查看需要 `config.read`，修改需要 `config.write`。
- 现有项目作用域的查看需要 `workspace.read`，修改需要 `workspace.write`。
- 没有某个作用域的读取权限时，该作用域不出现在设置页选择器中。

## 5. 输入框中的展示与使用

首页输入框和 Job 对话输入框使用相同的读取、分组和选择规则。现有“本地历史”按钮调整为“预置消息与历史”入口，弹层按以下分组展示：

1. 当前项目
2. 全部项目
3. 最近发送

没有内容的分组不展示；三个分组都为空时展示统一空状态。每一项显示名称或正文预览，并以标签明确来源，长文本可查看完整内容。

用户点击预置消息时：

- 输入框为空时，直接填入预置消息正文。
- 输入框已有文本时，提供“替换”“追加”“取消”三个选择，不得未经确认覆盖草稿。
- 选择“追加”时，在现有文本后以一个空行分隔，再加入预置消息正文。
- 保留输入框中已经选择或正在上传的图片。
- 完成选择后关闭列表并把焦点放回输入框。
- 不创建 Job、不触发发送、不写本地历史。

用户点击最近发送历史时，继续沿用当前的文本和图片恢复行为。

预置消息按作用域独立读取。某个配置文件读取失败时，其他有效分组和本地历史仍然可用，输入框和发送能力不得被禁用；失败分组显示完整文件位置和错误原因。

## 6. Memory 存储与 Git 语义

### 6.1 目录规划

预置消息保存到 Memory 中面向人工维护、可被 Git 跟踪的配置区域：

```text
$LOCAL_MEMORY/quartet/config/message-presets/
├── global.json
└── workspaces/
    ├── ws-1.json
    └── <workspace-id>.json
```

- `global.json` 保存“全部项目”消息。
- 每个项目使用独立文件，文件名采用当前实例的 workspace ID。
- 不写入 `$LOCAL_MEMORY/quartet/data/`；当前 Memory 仓库会忽略该目录，无法满足 Git 管理要求。
- 不写入通用 `settings.json`，避免预置消息与其他设置的整文件保存互相覆盖，也便于 Git 单独审阅某个项目的变更。

每个作用域文件包含格式版本和有序消息列表。每条消息包含系统生成的稳定 ID、可选名称和正文；编辑、排序时 ID 保持不变。项目文件额外保存项目名称和工作目录快照，仅用于在配置失去绑定后帮助用户辨认，不参与自动匹配。

文件不存在与空列表含义相同。删除某个作用域的最后一条消息时删除对应文件，不保留无内容文件；`global.json` 不存在时也按空的全部项目列表处理。

### 6.2 Git 行为

- 设置页保存成功后，文件立即落盘并在 Memory 仓库中表现为普通未提交变更。
- Quartet 不自动执行 `git add`、`git commit`、`git pull` 或 `git push`。提交、同步和冲突处理继续由现有 Memory 管理流程负责。
- Git 切换、拉取或回滚配置后，重新打开列表或显式刷新即可读取新内容，不要求重启后端。
- Git 中出现无法解析、格式版本不支持、ID 重复或字段不合法的配置时，不做静默修复；读取接口返回完整文件位置和错误原因。
- 文件写入采用原子完整替换。保存失败时保留原有效配置，不产生只写入一部分的结果。

### 6.3 跨实例同步与未绑定配置

普通 workspace ID 在创建时生成，而 workspace 业务数据位于不受 Git 跟踪的目录。因此，项目配置通过 Git 同步到另一实例后，系统不能假设相同名称或相同工作目录代表同一个项目，也不能自动关联。

当前实例不存在匹配 workspace ID 的项目文件称为“未绑定配置”：

- 未绑定配置不进入任何项目输入框的有效列表。
- 设置页在“未绑定配置”分组中展示文件记录的项目名称和工作目录快照。
- 用户可以把未绑定配置重新绑定到一个尚无项目预置配置的现有项目。
- 目标项目已经存在配置时禁止直接覆盖或静默合并；用户需先处理目标配置，或手动复制所需消息。
- 重新绑定保留消息内容、顺序和消息 ID，并表现为 Git 中旧文件删除、新文件新增。
- 重新绑定必须以“不丢失源配置”为首要约束：只有目标配置完整落盘后才能清理源文件；任一步失败都展示完整错误，并保证源配置仍可恢复。

该规则支持跨实例手动恢复，但本期不承诺按项目名称或工作目录自动同步项目绑定。

### 6.4 项目生命周期

- 项目重命名和工作目录变更不影响当前实例内的绑定；项目配置下次保存时更新用于辨认的名称和工作目录快照。
- 删除项目时不联动删除 Git 管理的预置消息文件，避免项目多阶段删除与外部配置删除形成不可恢复的部分成功。
- 删除确认信息明确说明项目预置配置将被保留为未绑定配置，可随后重新绑定或显式清理。
- 清理未绑定配置需要单独确认，并表现为可通过 Git 恢复的文件删除。
- 如果 Git 操作恢复了已删除项目的配置文件，它仍按未绑定配置处理，不会自动作用于同名项目。

## 7. 数据校验与并发

- 正文去除首尾空白后不能为空，但保存和填入时保留原始首尾空白、内部换行和格式。
- 同一作用域内消息 ID 必须唯一；名称可以重复。
- 单个作用域最多 100 条消息。
- 单条正文最多 32 KiB，按 UTF-8 编码后的字节数计算。
- 可选名称最多 80 个 Unicode 字符。
- 超限时拒绝保存，并显示具体条目、实际大小和允许上限。
- 保存请求必须携带读取时获得的不透明修订标识。修订标识是读取当时磁盘内容的指纹，并为“文件不存在”定义固定的空状态标识。
- 修订标识不一致时返回冲突和服务端当前修订，不能用旧页面覆盖新内容。
- 如果文件曾被外部操作修改、但保存前已经恢复为与读取时完全相同的内容，则视为当前状态没有有效冲突。
- 全部项目和各项目使用独立修订；编辑某个项目不会阻塞或覆盖其他项目。
- 外部 Git 修改与页面保存发生冲突时不自动合并。用户刷新最新配置后再处理差异。

## 8. 服务能力与权限边界

需要提供以下业务能力，具体接口命名在实施时沿用现有 API 风格：

- 读取当前项目的有效预置消息，同时返回“当前项目”和“全部项目”的来源信息。
- 单独读取、保存全部项目配置。
- 单独读取、保存指定项目配置。
- 列出、重新绑定和删除未绑定配置。

权限规则：

- 输入框读取某个项目的有效预置消息需要 `workspace.read`；返回内容同时包含该项目可见的全部项目消息。
- 在设置页读取或修改全部项目配置分别需要 `config.read`、`config.write`。
- 在设置页读取或修改现有项目配置分别需要 `workspace.read`、`workspace.write`。当前共享实例不做账号级项目隔离，拥有该权限的用户可以操作任意项目。
- 查看和删除未绑定配置分别需要 `config.read`、`config.write`。
- 将未绑定配置重新绑定到现有项目同时需要 `config.write` 和 `workspace.write`。
- 后端必须执行最终权限校验；前端隐藏或禁用按钮不能替代授权。

预置消息使用独立的读写能力，不通过“读取整份设置、修改一个字段、再保存整份设置”的方式更新，避免并发页面相互覆盖。

## 9. 用户故事与验收标准

### US-001：配置全部项目预置消息

**用户故事：** 作为配置管理员，我希望维护所有项目都能使用的预置消息，以便统一复用常用指令。

**验收标准：**

- [ ] 设置页可以选择“全部项目”，新增、编辑、删除和排序多条消息。
- [ ] 保存后内容写入 `$LOCAL_MEMORY/quartet/config/message-presets/global.json`。
- [ ] 现有项目和保存后新建的项目都能看到这些消息。
- [ ] 点击后只填入输入框，不自动发送。
- [ ] 使用浏览器验证设置保存、列表刷新和输入框填入行为。

### US-002：配置指定项目预置消息

**用户故事：** 作为项目维护者，我希望为某个项目配置专属消息，以便快速执行该项目常见任务。

**验收标准：**

- [ ] 设置页可以选择一个现有项目并维护其独立消息列表。
- [ ] 项目配置按 workspace ID 保存，不因当前实例内改名或改变工作目录失效。
- [ ] 专属消息只出现在匹配项目中，不出现在其他项目中。
- [ ] 当前项目消息排在全部项目消息之前。
- [ ] 使用浏览器切换至少两个项目验证作用域隔离。

### US-003：与本地历史共同使用

**用户故事：** 作为聊天用户，我希望在同一入口使用预置消息和最近发送历史，同时能辨认其来源。

**验收标准：**

- [ ] 列表按“当前项目 / 全部项目 / 最近发送”分组，并隐藏空分组。
- [ ] 输入框已有草稿时，点击预置消息可选择替换、追加或取消。
- [ ] 选择预置消息保留已有和正在上传的图片。
- [ ] 选择本地历史继续恢复历史文本和图片。
- [ ] 键盘上下键仍只遍历本地历史。
- [ ] 预置消息发送后正常进入最近发送历史，但不会修改预置消息配置。
- [ ] 斜杠开头的条目显示命令提示，发送时遵循所在输入框的原有语义。
- [ ] 桌面和移动布局均通过浏览器验证。

### US-004：通过 Git 审阅和恢复

**用户故事：** 作为实例维护者，我希望预置消息表现为 Memory 仓库中的普通配置变更，以便提交、同步和回滚。

**验收标准：**

- [ ] 新增、编辑、排序和删除均产生范围明确的 Git diff。
- [ ] 预置消息文件不受 Memory `.gitignore` 排除。
- [ ] Quartet 不自动提交或推送这些变更。
- [ ] Git 回滚后重新打开或刷新列表即可看到恢复内容，无需重启后端。
- [ ] 非法配置返回完整错误，不影响其他有效分组、本地历史和输入框发送。

### US-005：跨实例恢复项目配置

**用户故事：** 作为实例维护者，我希望 Git 同步来的项目配置在无法匹配本机项目时可以被识别和重新绑定。

**验收标准：**

- [ ] 不存在对应 workspace ID 的文件被列为未绑定配置，不进入任何项目输入框。
- [ ] 未绑定配置展示原项目名称和工作目录快照，便于人工识别。
- [ ] 可以重新绑定到尚无项目配置的现有项目，且不会静默覆盖已有配置。
- [ ] 重新绑定任一步失败时不会丢失原配置，并向用户展示完整错误。
- [ ] 项目删除后配置被保留为未绑定配置；项目删除结果不依赖该配置能否清理。
- [ ] 重新绑定和清理均产生可审阅、可恢复的 Git 变更。

### US-006：避免并发覆盖

**用户故事：** 作为共享实例用户，我希望过期的设置页面不能覆盖别人或外部 Git 刚修改的预置消息。

**验收标准：**

- [ ] 两个页面编辑同一作用域时，后保存的过期修订收到明确冲突。
- [ ] 页面打开后由外部 Git 改变、删除或恢复成不同内容，保存旧页面时收到冲突。
- [ ] 同时编辑不同项目时可以分别保存，配置不会相互覆盖。
- [ ] 冲突响应包含完整原因和当前修订信息。

### US-007：按权限访问设置

**用户故事：** 作为共享实例用户，我希望设置页只开放我有权查看和修改的预置消息范围。

**验收标准：**

- [ ] `config.read` 或 `workspace.read` 任一满足时可以看到“预置消息”页签。
- [ ] 只有读取权限时，允许查看对应作用域但不能修改。
- [ ] 全部项目、具体项目和未绑定配置分别按本方案的权限规则控制。
- [ ] 直接调用接口不能绕过权限限制，错误完整返回。

## 10. 功能要求

- **FR-1**：系统必须支持“全部项目”和“指定项目”两种预置消息作用域。
- **FR-2**：系统必须按“项目消息、全部项目消息、本地历史”的固定顺序展示。
- **FR-3**：选择预置消息必须只填充输入框，不得自动发送。
- **FR-4**：输入框已有草稿时，必须由用户选择替换、追加或取消。
- **FR-5**：预置消息必须保存到 Memory 的 Git 可跟踪配置目录。
- **FR-6**：浏览器本地历史必须继续保留，且不得自动迁移到 Git。
- **FR-7**：首页与 Job 对话页必须使用相同的读取、分组和选择规则，并保留各自原有的命令发送语义。
- **FR-8**：配置保存必须使用基于文件实际内容的修订冲突保护，并按作用域独立更新。
- **FR-9**：读取或保存失败必须向用户展示完整错误，同时不得禁用正常聊天。
- **FR-10**：当前实例内的项目配置必须绑定 workspace ID；跨实例不自动按名称或工作目录匹配。
- **FR-11**：系统必须提供未绑定配置的识别、重新绑定和显式清理能力。
- **FR-12**：项目删除不得因预置消息配置清理失败而失败，也不得自动删除该 Git 配置。
- **FR-13**：所有新增私有能力必须按读取和修改动作执行后端权限校验。
- **FR-14**：所有新增 Web 文案必须同时支持中文和英文。

## 11. 非目标

- 不自动发送预置消息。
- 不把预置消息自动注入 Agent system prompt 或每轮上下文。
- 不同步、迁移或 Git 管理现有浏览器本地历史。
- 不保存图片、附件、语音或其他多媒体预置消息。
- 不提供变量、条件、模板渲染、定时发送或工作流触发能力。
- 不记录预置消息的使用次数、最近使用时间或使用人。
- 不根据项目名称或工作目录自动匹配跨实例项目。
- 不自动提交、拉取、合并或推送 Memory Git 仓库。
- 不扩展到 iOS 或 IM 客户端；本期只覆盖 Web 首页和 Job 对话输入框。

## 12. 实施顺序

1. 建立 Git 可跟踪的预置消息存储、校验、内容修订和权限能力。
2. 增加设置页作用域选择、权限状态、消息管理和未绑定配置管理。
3. 统一首页和 Job 输入框的预置消息读取、分组、草稿保护和错误展示。
4. 验证 Git diff、外部修改冲突、跨实例重新绑定、项目删除、项目切换、权限错误和非法文件场景。
5. 完成前端构建，并在桌面和移动浏览器中验收；不由 agent 执行 `make web` 重启后端。
