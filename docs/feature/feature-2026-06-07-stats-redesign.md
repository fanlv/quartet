# 使用统计页面重设计

> 状态：已实现，真实链路验证通过
> 日期：2026-06-07
> 范围：`web/src/components/stats/StatsPage.tsx` + `StatsPage.css` 前端重写；`cmd/web/handler/stats.go` 新增环比支持。后端聚合层与存储层零改动。

## 1. 设计读 (Design Read)

把这个页面读成：**单用户本地 Agent 的「使用统计」数据看板**，受众是产品的唯一使用者本人，对间距 / 层级 / 配色高度敏感，整体产品线对齐克制精致的现代风。语言基调是**克制的数据可视化**，保留现有 React + Vite + 纯 CSS 栈，套用前端品味纪律（反 AI-slop、配色 / 圆角 / 字体锁、动效克制、全状态覆盖），但布局本身按看板最佳实践组织，不套 landing page 的那套结构。

重设计模式：**Overhaul（视觉重做，数据维度与信息架构保留）**。

## 2. 现状问题诊断

当前页面结构是「全屏弹层 + 一排全局指标开关 + 三列卡片 + 一条全宽趋势图」，主要问题：

1. **控制层级太深、作用域太大**：顶部 `Duration / Counts / Tokens` 大开关，旁边再挂一个子指标下拉。要先选大类、再选子类才能看到想要的数，而且一次切换会同时改掉四个图表的含义，认知负担高。
2. **缺少总览**：进入页面第一眼就是四个需要解读的图，没有一条「一眼看懂」的核心数字带（总耗时 / 总轮次 / 总 Token / 工具调用）。
3. **视觉语言碎**：同一批数据切成四片，却用了甜甜圈、横条、横条、折线四种图形语言，整体观感凌乱。
4. **配色发散**：分布图用了约 10 种 HSL 色相，与产品的单强调色基调不一致，偏数据后台风。
5. **半残状态外露**：选中 Tokens 维度时「按工具」直接显示「该版本未采集」之类的技术话术，体验割裂。

## 3. 目标设计

### 3.1 页面结构（自上而下）

1. **顶栏**：标题 + 时间范围（`7天 / 30天 / 90天 / 全部 / 自定义`）+ 关闭。时间范围是页面唯一的全局控制。
2. **KPI 概览带**：五张数字卡，固定展示 总耗时 / 总轮次 / 总 Token / 工具调用 / 活跃工作区数。每张卡带「对比上一等长周期」的环比（↑ / ↓ 百分比，绝对值上升用强调色、下降用中性色，不用红绿对撞）。
3. **主趋势图**：占据主位的一张折线图。指标切换（耗时 / 轮次 / Token）收进图的右上角，**只作用于这张图**，不影响 KPI 带和榜单。按模型分解为多条折线 + 一条总量线。
4. **三个分布榜单**：工作区 / 模型 / 工具，统一用「横条 + 数值 + 占比」语言并排展示。
   - 工作区榜：按耗时排序，支持跳转 / 标记当前工作区 / 标记已删除。
   - 模型榜：按耗时排序，Top N + 「其余 N 项未展示」。
   - 工具榜：**固定按调用次数排序**，不随指标切换变化，彻底消除「未采集」半残态。

### 3.2 控制简化

- 全局只保留「时间范围」一个控制。
- 原 `Duration / Counts / Tokens + 子指标下拉` 两层结构：大类切换降级进趋势图内部、作用域收敛到单图；子指标（assistant / thought / toolCall 等细分）不再占据主控制区，作为 hover tooltip 里的分解项呈现。
- `Thought` 维度从主界面移除，仅在 tooltip 分解中出现，降低噪音。

### 3.3 配色锁

整页只有一个强调色 `#2563eb`（沿用产品现有主色）。

- 多 series 折线 / 分布横条统一用同一蓝色的明度阶梯：`#2563eb → #60a5fa → #93c5fd → #bfdbfe`，超出部分用中性灰 `#94a3b8` 兜底。
- 不引入第二个强调色，解决现状中 10 色相发散的问题。

### 3.4 设计 token（从现有产品审计提取，重设计沿用）

| token | 值 |
|---|---|
| 主强调色 / hover | `#2563eb` / `#1d4ed8` |
| 文字主 / 次 / 弱 | `#1a1a1a` / `#64748b` / `#94a3b8` |
| 边框 / 分隔 | `#e2e8f0` |
| 底色 | `#fff` / `#f8fafc` |
| 危险色 | `#dc2626` |
| 圆角 | 卡片 12px / 控件 6px |
| 字体 | 系统字体栈（保留，不引入新字体） |

### 3.5 全状态

- 加载：骨架屏，形状匹配最终布局（KPI 带 + 趋势 + 榜单）。
- 空数据：优雅空态，给出「该时间范围内暂无使用记录」的引导，不留白板。
- 错误：行内错误信息 + 重试按钮，错误全文展示不隐藏。

## 4. 后端改动：环比支持

KPI 卡的环比需要上一等长周期的合计。实现方式：`GET /api/v1/stats/usage` 新增可选参数 `compare=1`。

- 当前周期为 `[from, to]`，周期长度 `Δ = to - from + 1 天`。
- 上一周期为 `[from - Δ, from - 1 天]`，复用现有取数逻辑得到一份合计。
- 仅把五个 KPI 维度的上一周期合计（总耗时、总轮次、总 Token、工具调用数、活跃工作区数）放进响应的 `previous` 字段；不返回上一周期的明细榜单 / 趋势，避免响应膨胀。
- 不传 `compare` 时响应结构与现状完全一致，旧调用不受影响。
- 「全部时间」范围下没有「上一周期」概念，此时不计算环比，前端 KPI 卡只显示绝对值。

trade-off 记录：环比也可以由前端发两次请求拼接，零改后端；但会多一次往返、且时区 / 边界对齐逻辑要在前端重复一遍。选择后端加参数，更准、更省、边界逻辑只在一处维护。

## 5. 技术约束

- 栈不变：纯 CSS + 手绘 SVG 图表，不引入 Tailwind / 图表库 / 动效库。
- 后端聚合层（`services/usagestats`）与存储层零改动，仅 handler 层增加环比计算与响应字段。
- 国际化：所有新增静态文本走 i18n，中英文都要覆盖。
- 动效克制：仅保留进入淡入、hover 反馈、tooltip，无装饰性循环动画；遵循 `prefers-reduced-motion`。
