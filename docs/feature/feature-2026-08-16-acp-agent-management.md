# ACP Agent 动态管理（内置目录 + 自定义 Agent）

## 1. 背景与目标

当前 ACP Agent 目录由代码中的 `KnownACPAgents` 固定维护，新增或调整 Agent 必须改代码并重新发布。本功能新增「Agent 管理」设置页，将目录分为：

- **内置 Agent**：继续由 `KnownACPAgents` 维护。
- **自定义 Agent**：用户自行添加和持久化，后端验证通过后生效。

最终目标是让 Agent 的安装、添加、编辑、验证、删除、恢复和历史解析都使用稳定的 AgentID，同时保证启动定义变化不会破坏已有 ACP 会话。

## 2. 核心模型

### 2.1 Agent 目录

内置 Agent 必须声明：

- 不可变且全局唯一的 AgentID。
- Bin、ACP 启动程序和有序参数列表。
- 当前稳定环境变量 key（EnvKey），同时用于运行时环境注入和存量迁移解析。
- 当前 ACP 启动命令（Command，由 ACPProgram + ACPArgs 空格拼接），用于兼容旧序列化格式和迁移解析。
- 用于存量迁移的有序历史标识，包括旧 Bin、旧环境变量 key 和旧 ACP 启动命令。
- DisplayName、IconURL。
- 安装方式、安装命令或手动安装指引。
- 是否支持 `bin -p prompt` 一次性文本生成。
- 是否已弃用。

只有确认内置 Agent 的 `-p` 模式可用时，才能将一次性生成能力设为支持。

内置安装方式分为：

1. npm 全局包，可自动安装。
2. 官方安装脚本，可自动安装。
3. 仅手动指引，适用于需要交互、鉴权或项目工具链的安装。`eino-cli` 固定属于此类，只展示项目自带构建指引。

内置条目只增不删。需要下线时保留 AgentID 和展示信息并标记为已弃用；已弃用项不参与安装、探测、新执行或选择器，但历史引用仍可解析。

自定义 Agent 保存：

- 不可变 AgentID。
- DisplayName、IconURL。
- 是否支持 `bin -p prompt`。
- 生命周期状态。
- 当前运行定义修订和仍被引用的历史修订。

自定义 Agent 的 CLI 由用户自行安装，后端不提供自动安装。

### 2.2 AgentID 与运行定义修订

AgentID 是配置和业务引用的稳定标识，创建后不可编辑、不可复用。内置 AgentID 由目录显式声明；自定义 AgentID 在首次验证成功后由后端生成。

Bin、ACP 启动程序和有序参数列表共同组成一套**运行定义修订**：

- 修订不可变且跨重启稳定；相同结构化定义复用原修订标识。修订标识在同一 Agent 内由结构化定义内容确定性派生（内容寻址），不依赖创建顺序；已清理的修订在相同定义再次出现时以同一标识重建，此时其历史引用已不存在（见清理条件），旧验证结果不复活，按当前环境重新验证。
- 只有 Bin、启动程序或参数变化时才创建新修订，并将其设为当前修订。
- DisplayName、IconURL 或一次性生成能力变化不会单独创建运行定义修订。
- 新 ACP 会话和新开始的独立执行使用 Agent 当前修订；已有会话绑定创建时的修订，后续消息、重试、恢复和断线重连不得切换。
- GraphWorkflow 只保存 AgentID。GraphRun 的基线版本和每个后续 GraphRunVersion 在创建时，分别把各 Agent 节点解析为 AgentID 与运行定义修订快照。
- 使用继承会话策略的 Graph 节点不保存自身 Agent 修订快照，执行时始终使用上游会话已经绑定的 AgentID、修订和运行定义。
- Graph 节点实例使用其被调度版本中保存的修订；已经进入执行批次、已经开始或已经创建会话的实例不得因后续 GraphRunVersion 或 Agent 当前修订变化而切换。
- 创建后续 GraphRunVersion 时，AgentID 未变化的节点默认继承上一 GraphRunVersion 的修订快照；更换 AgentID 时按新 Agent 的当前修订生成快照。
- 用户可以对尚未确定执行版本的节点显式选择“更新到当前 Agent 修订”。该操作即使不修改其他节点配置也必须生成新的 GraphRunVersion；不得通过一次普通图保存无提示地更新所有节点修订。
- 仅修改全局 Agent 目录不会自动改变已有 GraphRun。已经进入执行批次、已经开始或已经创建会话的实例不允许执行“更新到当前 Agent 修订”。
- Graph 实例重试或恢复时，已有会话继续使用会话绑定修订；没有会话且按既有 Graph 规则使用新 GraphRunVersion 重新调度的实例，使用该版本保存的修订。
- Schedule 自身不保存 Agent 修订；每次触发读取 GraphWorkflow 并创建新的 GraphRun，由该 GraphRun 的基线版本锁定本次触发使用的修订。
- 不得使用新修订恢复旧修订创建的 ACP 原生 Session，也不得因此自动重建会话或丢弃上下文。
- 可续聊会话指仍存在于存储中的会话记录：会话随其 Job 删除而消失；已删除 Agent 保留的历史会话同样构成引用，因为恢复后可继续续聊。
- 旧修订不进入选择器，但被可续聊会话或未结束执行引用时必须保留，并可按需重新验证和启动。
- 旧修订无法安装、验证或启动时，完整返回 AgentID、修订和实际错误，不自动回退到当前修订。
- 不再被任何现存会话或未结束执行引用的非当前修订可以清理；引用无法完整确认时跳过清理。内置历史修订在旧标识首次被真实历史记录解析时按需持久化，不因目录声明长期常驻；已弃用内置 Agent 的当前修订同样不预置持久化，仅在被真实引用时保留。清理只移除该修订记录及其验证缓存，不影响当前修订或仍被引用的其他修订。

内置运行定义发生变化时同样生成新修订。服务必须持久化仍被引用的旧修订，不能只依赖升级后的代码目录恢复旧 ACP 会话。

### 2.3 ACP 与一次性生成能力

ACP 会话能力和 `bin -p prompt` 能力的声明相互独立：两者可单独支持，内置和自定义 Agent 都必须显式声明是否支持一次性生成，缺失时按不支持处理。可用状态不按能力拆分：一次性生成同样要求当前修订处于「可用」状态（见「3.2 用户可见状态」），ACP 验证失败时即使声明支持 `-p` 也不进入选择器、不在运行时尝试。

设置拆分为三个互不覆盖的配置：

- **标题生成 Agent**：只保存 AgentID，用于 `bin -p prompt`。
- **群聊回复 Agent**：只保存 AgentID，用于 `bin -p prompt`。
- **IM 会话 Agent**：保存 AgentID、ACP model、mode 和 thought level，用于 IM 私聊创建和续聊 ACP Job。

标题和群聊回复只允许选择支持 `bin -p prompt` 且当前可用的 Agent，不展示或保存 ACP model、mode、thought level。执行时使用 Agent 当前修订的 Bin，固定调用 `bin -p prompt`，使用 CLI 默认模型，并注入该 AgentID 下已启用的环境变量。自定义 Agent 是否真正支持 `-p` 以用户声明为准，不额外实测；运行失败时完整展示实际错误。

不支持该能力时不得进入一次性生成选择器，也不得在运行时回退尝试。

## 3. 安装与可用状态

安装状态、ACP 可用性和生命周期相互独立。

### 3.1 安装判定

满足以下条件才算已安装：

- Bin 为裸可执行名时，能从后端进程 `PATH` 找到；Bin 为路径形式（含路径分隔符的绝对或相对路径）时，直接判定该文件存在且可执行，不要求位于 `PATH`。
- ACP 启动程序与 Bin 不同时，启动程序按同一规则判定。
- 启动程序为包运行器（如 npx）时，包运行器存在不代表 Agent 已安装，仍以 Bin 为准。Bin 必须是 `PATH` 可解析的可执行名或可执行文件路径；仅能通过包运行器动态拉取启动、没有对应可执行 Bin 的 Agent 不支持添加，需先全局安装，或由用户提供包装脚本作为 Bin。

裸可执行名的安装目标目录不在后端 `PATH` 时仍判定为未安装，并完整提示需要调整后端运行环境。

### 3.2 用户可见状态

| 状态 | 判定 | 是否可选择或新执行 |
| --- | --- | --- |
| 未安装 | 不满足安装判定 | 否 |
| 待验证 | 已安装，但当前修订与当前环境变量配置版本无匹配验证结果 | 否 |
| 验证中 | 正在验证，且没有可继续使用的结果 | 否 |
| 已安装但不可用 | 当前修订在当前环境变量配置版本下的最近一次完整验证失败 | 否 |
| 可用 | 当前修订在当前环境变量配置版本下的最近一次完整验证成功 | 是 |
| 删除中 | 生命周期为 deleting | 否 |
| 已删除 | 生命周期为 deleted | 否 |
| 已弃用 | 内置条目已弃用 | 否 |

已有有效结果的后台刷新不改变原“可用”或“已安装但不可用”状态，只附加“刷新中”。缓存缺失、迁移废弃、运行定义修订不匹配或环境变量配置版本不匹配时必须进入待验证，不能继承其他修订或其他环境配置的结论。

删除中页面必须展示处理进度，并禁止该 Agent 的其他管理和执行操作。

### 3.3 列表行为

私有 `/api/v1/agent/list`：

- 只返回已安装、生命周期 active 且未弃用的 Agent。
- 内置 Agent 保持目录顺序，自定义 Agent 排在其后。
- 返回 AgentID、当前修订、能力列表和可用状态。
- 待验证、验证中和已安装但不可用项仍返回，并携带完整错误，但必须禁用。
- 不返回未安装、deleting、deleted 或已弃用项。

公开分享不提供 Agent 列表，不允许枚举系统已安装的 Agent、模型、模式或思考等级。分享页对历史引用的展示由当前 Job 的只读响应附带最小身份信息承载（见「7. 历史与公开分享」）。

所有普通选择器只允许选择可用项；一次性生成选择器还要求支持 `bin -p prompt`。已有会话能否续聊由其绑定修订决定，不依赖当前选择器。

Agent 变为待验证、验证中或已安装但不可用时，已有配置和业务引用继续保留，执行时按目标修订返回完整错误，不自动清理或改写。

## 4. 管理流程

### 4.1 安装内置 Agent

新增表单的内置候选只展示未安装且未弃用的 Agent，并展示名称、图标、AgentID、ACP 启动定义、安装方式和指引。

自动安装必须满足：

- 接口只接收内置 AgentID，只执行目录预置流程，不接收前端任意命令。
- 仅手动指引的 Agent 不显示安装按钮。
- 点击安装后按钮进入 loading。
- 每个安装步骤有独立执行超时上限（当前 10 分钟/步）；超时后只允许进入固定且短暂的有界回收阶段，接口总时长不得超过执行上限与回收上限之和。
- 超时上限覆盖该步骤启动的全部子进程；达到上限、请求取消或异常结束时必须终止完整进程树，不能在接口返回后继续下载、安装或修改全局环境。
- 当前步骤的进程树和输出管道全部完成有界回收后才能释放安装占用；回收完成前，新的安装、升级或卸载请求不得与旧步骤并行。
- 完整返回 stdout、stderr、退出状态和错误。
- 安装结束后重新执行统一安装判定；退出成功但 Bin 或独立启动程序未进入后端 `PATH` 时仍为未安装。
- 仅在已安装后进入验证中，执行完整 ACP 验证；成功变为可用，失败变为已安装但不可用。

安装与验证输出默认折叠，可展开查看完整内容。

### 4.2 添加自定义 Agent

表单包含 Bin、IconURL、DisplayName、ACP 启动程序、可增删排序的参数列表、首次验证环境变量，以及必填且默认关闭的 `bin -p prompt` 支持开关。AgentID 不由用户输入。

启动程序和参数必须结构化保存和执行：

- 每个参数保持原值，不做 shell 拆词。
- 空格路径或空格参数作为单个值传递。
- 不支持管道、重定向、变量展开或其他 shell 语义。

提交顺序：

1. 校验必填字段。
2. 原子占用完整启动定义并校验唯一性。唯一性范围同时包含全部内置条目（含已弃用项：其历史修订仍可能被会话引用，启动定义不允许被自定义占用）、全部自定义 Agent 的当前定义（含已删除：其启动定义保留用于恢复引导）和其他正在新增、编辑或恢复的候选定义；同一 Bin 配不同参数允许存在。
3. 按统一规则检查安装状态；未安装时不入库，只提示用户自行安装并展示完整错误。
4. 使用表单中的临时环境变量完成 ACP 连接、initialize 和建会话验证，并设置超时。
5. 验证成功后，在同一次提交中生成 AgentID 和首个修订，持久化 Agent、环境变量及其配置版本和能力结果，注册运行权限，并把候选定义占用转换为正式归属；失败不产生 AgentID、修订或残留权限。

候选定义占用从唯一性检查持续到成功提交或操作失败。校验失败、验证失败、超时、取消和请求中断都必须释放占用；并发请求命中已占用定义时直接返回冲突、占用对象和当前状态，不得再并行验证。最终提交必须再次确认占用仍属于本次操作。

候选定义占用按结构化启动定义隔离，不同定义可以并行管理；同一 AgentID 的编辑、恢复和删除相互排斥。若进程在跨设置与目录的提交中断，服务启动时清理没有 active 目录归属的自定义 Agent 设置，并按删除阶段恢复或继续未完成操作。

启动定义与现有记录重复时按其生命周期区分响应：与 active 自定义 Agent 重复时返回冲突 AgentID 和"定义已被占用"错误；与已删除自定义 Agent 重复时返回冲突 AgentID、显示名和 lifecycle，引导用户明确恢复而不创建新 AgentID。用户也可以从历史记录主动恢复。

添加成功后 AgentID 只读展示，Agent 出现在私有列表的自定义 Agent 区域，并可使用探测得到的 model/mode 发起会话。

### 4.3 编辑自定义 Agent

active 状态可编辑 Bin、启动程序、参数、DisplayName、IconURL 和一次性生成能力。每次提交都执行与新增相同的字段、安装和 ACP 验证；运行定义变化时必须先占用候选定义，唯一性校验排除自身当前定义但不得排除其他并发候选。

- 任一检查失败时保留原配置和当前修订，并完整返回错误。
- 运行字段变化且验证成功后，原子创建并切换到新当前修订，将候选定义占用转换为正式归属，并释放不再作为当前定义使用的原占用。
- 仅展示或能力字段变化时，当前运行定义修订保持不变。
- 仍被会话或执行引用的旧修订不得覆盖或删除。
- 环境变量不随编辑表单修改，继续由现有 ACP 设置页管理。

### 4.4 环境变量与通用设置

环境变量不存入 Agent 定义：

- 首次验证只临时注入，验证成功后才写入现有 ACP 环境变量配置，以 AgentID 为 key；首次环境变量、环境变量配置版本和验证结果必须对应同一份有效配置。
- ACP 会话和一次性生成使用同一组已启用环境变量。
- 环境变量按 AgentID 独立读写，不允许用整张环境变量 map 覆盖保存。同一 AgentID 的环境变量保存与编辑、恢复、删除共用管理互斥，运行定义验证到目录提交期间环境配置不得并发变化。配置记录变化始终可以保存；只有已启用、实际注入进程的键值集合变化时才生成新的环境变量配置版本，禁用项的值变化或纯排序不递增版本。
- 验证结果同时绑定运行定义修订和环境变量配置版本。环境变量实际变化后，当前修订进入待验证并异步刷新，历史修订的旧结果一并失效并在使用时按需验证。
- 环境变量没有实际变化时不清理验证结果、不回收空闲会话、不触发重新验证。
- 环境变量变化不创建运行定义修订，也不改变会话绑定修订。已经取得执行权的运行继续使用启动时环境直至本次执行结束；空闲 ACP 会话进程和探测进程退出，下一次执行使用新环境并按原绑定修订恢复或加载原 ACP Session，不得 reset Session、改用当前修订或丢弃上下文。
- 删除 Agent 时清除对应环境变量；恢复后需要重新填写。
- Agent 目录、单 Agent 环境变量、Agent 默认值、标题生成 Agent、群聊回复 Agent 和 IM 会话 Agent 分别使用各自负责的设置接口，只更新目标字段或目标 AgentID，不得通过通用 settings 快照整体替换。
- 通用 settings 保存不拥有上述 Agent 相关字段，即使旧页面提交了这些字段也不得覆盖服务端当前值。
- 环境变量和 Agent 默认值编辑器必须同时成功加载 Agent 目录与服务端设置快照后才进入可写状态。HTTP 错误、业务错误、网络错误或无法解析的响应必须完整展示，页面只提供重试，不得把失败解释为空配置，也不得发送设置写入请求。
- 环境变量默认模板只在设置快照加载成功且明确没有目标 Agent 配置时展示；加载失败时不得生成或保存默认模板。
- Agent 默认值保存只提交本次打开页面后实际修改过的 Agent；未修改 Agent 不随保存动作写回，部分失败时只保留失败项供重试。
- 每个 Agent 相关设置写入都重新校验 Agent 生命周期和引用有效性。Agent 进入 deleting 后立即拒绝新的环境变量、默认值和角色配置写入；删除流程在同一删除独占权下调用各设置所有者完成清理，旧页面不得重新写回已删除引用。

### 4.5 重新验证

重新验证默认针对当前修订，也可针对被历史会话引用的指定修订：

- 强制绕过探测失败退避。
- 无有效结果时从待验证进入验证中，完成后进入可用或已安装但不可用。
- 使用 Agent 当前环境变量配置版本，返回完整验证结果并只更新目标运行定义修订与环境变量配置版本组合的缓存。

## 5. 运行一致性

### 5.1 引用与执行权

Graph 节点、标题生成 Agent、群聊回复 Agent、IM 会话 Agent、Agent 默认值、工作区默认 Agent 和环境变量保存 AgentID。ACP 会话额外保存绑定修订；GraphRun 的每个基线或后续版本按节点保存 AgentID 与修订快照；Schedule 仅保存 GraphWorkflow 引用，每次触发由新 GraphRun 生成快照。

所有新会话、消息发送、ACP 配置切换、同步或异步验证、继续执行、恢复、断线重连、Graph/Schedule 运行、标题生成和群聊回复入口，都必须原子获取 AgentID 与目标修订的执行权：

- 除已由 GraphRunVersion 锁定修订的 Graph 节点外，新会话和新独立运行使用 Agent 当前修订，要求 Agent active 且当前修订可用。
- Graph 节点尚未绑定会话时使用其执行 GraphRunVersion 保存的修订；已经绑定会话时以会话修订为准。GraphRunVersion 快照对应的修订无有效结果时不得静默改用 Agent 当前修订。
- 已有会话和已开始运行使用绑定修订，要求 Agent active，并要求该修订满足安装和验证要求。
- 历史修订没有有效结果时先验证；失败后完整报错。
- 执行权从入口校验持续到本次执行完全结束，并在成功、失败和取消路径释放。
- 执行权按一次执行持有：交互式消息运行、Graph 节点实例执行、Schedule 触发的运行和一次性生成调用分别持有各自执行的执行权；执行内部的断线重连和会话恢复复用该执行已持有的执行权，不单独获取。
- 没有进行中执行的空闲会话重连不获取执行权，只校验 Agent 生命周期和绑定修订的安装、验证要求，因此也不阻止删除；删除时按删除流程直接终止空闲会话进程。
- 执行权是 AgentID 与修订粒度的运行准入原语，不替代会话级实例租约；会话级实例租约继续管理 ACP 会话进程实例的复用与回收。

Schedule 不直接引用 Agent。每次触发需要穿透其 GraphWorkflow 节点检查，并在创建 GraphRun 基线版本时一次锁定各节点修订。Graph/Schedule 的错误必须包含 AgentID 和具体 Graph 节点位置。

### 5.2 运行权限与进程

服务启动时：

- 加载持久化 Agent、修订和 AgentID 环境变量。
- 只为 active、已安装 Agent 的当前修订注册常驻运行权限；内置 Agent 同样执行安装和弃用判定。
- 历史修订只在被会话或未结束执行引用时按需检查、验证和注册，不进入选择器。
- deleting、deleted、未安装或已弃用项不得注册。

运行权限、ACP 会话和探测进程必须支持按 AgentID 与修订注册、注销、枚举和终止。删除时先终止全部修订的会话和探测进程，再注销运行权限。

### 5.3 探测缓存与重启

内存和磁盘探测缓存以 AgentID 索引，并按运行定义修订与环境变量配置版本隔离，记录最近一次成功能力快照或完整失败：

- 结果只对相同运行定义修订和相同环境变量配置版本有效。
- 新运行定义修订或新环境变量配置版本不得继承旧结果。
- 运行定义修订和环境变量配置版本都匹配时，重启可先展示最近结果，再后台刷新；磁盘结果只补充内存缺项，不得覆盖进程内更新的结果。
- 无匹配缓存时先显示待验证，再异步验证；空缓存或缓存版本重建不得阻塞 Web 服务启动，验证完成前禁止新执行。
- 历史修订的结果与当前修订隔离。
- Agent 添加、编辑、删除、恢复和环境变量实际变化时，内存与磁盘缓存必须同步更新，不能留下只在一侧生效的结果。
- 内置 Agent 后台刷新只更新本轮负责的内置目标，不得清理自定义 Agent 或被引用历史修订的 selector 状态；各 Agent 的缓存回收由环境变更、修订清理和删除流程按 AgentID 与修订精确执行。
- Agent 变为未安装时保留其缓存与最近结果（内存与磁盘），管理目录以未安装为主状态，同时继续展示最近验证结论、时间与完整错误，但不进入选择器；只有删除 Agent 才清除其探测缓存。

自定义 Agent、修订、环境变量和缓存重启后恢复。当前修订正常恢复运行权限；被引用的历史修订保留按需运行能力。已不满足安装判定时标为未安装，不自动删除定义。

## 6. 删除与恢复

### 6.1 删除并发控制

只允许删除自定义 Agent，条目提供删除入口并要求用户确认。删除前展示：

- 将清理的标题生成 Agent、群聊回复 Agent、IM 会话 Agent、Agent 默认值和环境变量。
- 将保留但失效的 Graph、Schedule、Job 和会话引用。

删除流程必须：

1. 按 AgentID 原子取得删除独占权，将 active 改为 deleting，并停止向全部修订发放新执行权。
2. 检查运行中任务和已发放执行权。阻止项包括未终态 Job、进行中 Graph 运行、正在执行的 Schedule 触发；空闲会话进程不阻止删除。
3. 等待已发放执行权归零后再次检查阻止任务，覆盖 Graph/Schedule 在快照创建期间取得执行权、随后才绑定 Job 的并发窗口。
4. 存在阻止项时恢复 active，拒绝删除并完整列出任务。
5. 无阻止项时终止全部修订的空闲会话和探测进程，注销运行权限，清理缓存、环境变量和可自动清理配置，最后标记 deleted。

这保证检查通过后不会再启动新任务。

影响查询、首次阻止项检查和执行权归零后的复查都必须完整读取相关 Session、GraphRun 与历史 Agent 标识。任一记录无法读取或标识解析失败时，不得按“无引用”继续；若尚未开始破坏性清理则恢复 active，并向用户完整返回导致引用无法确认的实际错误。

环境变量、Agent 默认值、标题生成 Agent、群聊回复 Agent 和 IM 会话 Agent 的清理必须通过各自设置所有者完成。Agent 保持 deleting 直到全部清理持久化成功；并发打开的旧设置页面在此期间和删除完成后都不能重新写入该 AgentID。

强制删除先逐项停止全部阻止任务，并完整返回每项结果；Graph 任务必须等待 GraphRun 与绑定 Job 都完成终态落盘后才计为停止成功。任一停止失败就中止，不继续删除。全部停止成功后重新进入标准删除流程。

删除失败时：

- 尚未开始破坏性清理则恢复 active。
- 已开始清理则保留 deleting、完整错误和重试入口，且始终不可执行。
- 服务重启后自动继续同一套幂等清理；成功转为 deleted，失败继续保留 deleting，且不得恢复运行权限。
- 恢复成功时清除上一次删除的清理阶段和错误；恢复后的下一次删除必须重新从未开始破坏性清理的状态执行。

### 6.2 删除结果

删除成功后：

- 保留 AgentID、显示名、图标、删除状态，以及历史会话所需的运行定义修订。
- 移除全部修订的运行权限、环境变量、一次性生成能力配置、空闲进程和探测缓存。
- 从所有 Agent 选择器和 `/api/v1/agent/list` 移除。
- 发起删除的浏览器清理工作区默认、最近使用等 localStorage 引用；其他浏览器加载时惰性清理并回退默认，后端执行校验兜底。
- Graph、Schedule、Job 和会话引用不被静默改写。

历史 Job 和会话仍可读取，但名称显示为「原显示名（已删除）」；前端禁用消息、继续、恢复和重连，后端按 AgentID 与绑定修订独立拒绝，并完整返回状态和错误。

### 6.3 恢复

恢复必须由用户明确选择已删除记录，并沿用原 AgentID：

- 可以更新 Bin、启动程序、参数、DisplayName、IconURL 和一次性生成能力。
- 复用新增流程的字段、唯一性、安装和 ACP 验证；验证期间使用尚未持久化的临时环境变量。
- 运行定义变化时创建新当前修订。
- 环境变量已被删除，需要重新填写。
- 历史会话继续绑定删除前的原修订；续聊时按需恢复并验证该修订。
- 原修订无法启动时完整报错，不切换到当前修订。

## 7. 历史与公开分享

历史 Job、会话、消息、模型和模式正常保留。展示信息不依赖当前可用 Agent 列表，而是按 AgentID 实时读取保留记录：

- 显示记录当前的 DisplayName、IconURL 和删除状态。
- 删除后追加「（已删除）」。
- 恢复时修改名称或图标后，历史展示随当前记录更新，不引入 Job 级展示快照。
- 无法解析的引用显示为未知 Agent；执行时返回完整错误。

公开 Job 和会话响应只附带该 Job 实际引用的 Agent 最小展示信息，覆盖主会话、各 Graph 节点会话及 GraphRun 运行快照并去重。继承上游会话的节点只按实际继承的 Session 绑定解析，不得把节点配置中隐藏且不参与执行的 Agent 字段加入响应。字段仅包含 AgentID、当前显示名、图标和删除状态；不得包含修订、启动程序、参数、环境变量、安装信息、可用性错误、内部错误或其他 Agent 记录。

公开侧不新增可枚举历史 Agent 的接口。

## 8. 一次性生成与错误展示

- 标题生成失败时，将完整错误持久化到对应 Job，并通过现有 Job 事件通知页面；使用回退标题不能覆盖错误。错误只在真实执行生成后记录：熔断开路期间的跳过不视为失败、不写入 Job；重试的中间失败不写入，重试耗尽后写入最终错误。回退标题与持久化错误相互独立，展示回退标题时错误仍完整保留可查。
- 群聊回复失败时，在对应消息渠道完整返回实际错误。
- IM 私聊继续使用 ACP Job 的现有错误链路。
- 安装、验证、编辑、删除、恢复、执行权限校验和一次性生成错误都必须完整返回或记录，不截断、不隐藏。
- Agent 已完成目录或设置提交但探测缓存落盘失败时，接口必须返回完整 warning；不得静默报告为完全成功。
- 管理页面读取失败响应时先保留原始响应正文，再尝试解析结构化错误；反向代理、网关或开发代理返回非 JSON 内容时同样完整展示正文和 HTTP 状态。
- 新页面、状态和错误文案接入现有中英文 i18n。

## 9. 数据迁移

升级时执行一次 best-effort 迁移：

### 9.1 Agent 引用

- 将会话、GraphWorkflow 节点、Agent 默认值、环境变量等后端持有的引用中的已知 serve 命令或 Bin 映射为 AgentID。GraphWorkflow 的可解析引用在读取时持久化为 AgentID；并发编辑冲突时跳过本次迁移，后续读取重试。工作区默认、最近使用等浏览器 localStorage 引用不在后端迁移范围内，按「9.3 缓存与浏览器」处理。
- 每个内置 Agent 在目录中声明确定的旧标识优先级，统一按“已是 AgentID、稳定 Bin 或旧环境变量 key、当前 ACP 启动命令、有序历史启动命令”从高到低解析。历史标识之间也必须有固定顺序，不依赖 map 遍历顺序。目录声明的全部解析标识（稳定 Bin、稳定环境变量 key、当前与历史启动命令）必须全局唯一，任何标识不得被两个内置条目声明；迁移解析命中重复声明时保留原值、历史显示未知 Agent 并完整报错。
- 多个旧 key 映射到同一 AgentID 时，ACP 环境变量按变量名合并：高优先级来源的值和启用状态整体胜出，低优先级来源中不冲突的变量继续保留。
- 多个旧 key 映射到同一 AgentID 时，Agent 默认值中的默认模型、mode 和 thought level 分别取最高优先级的非空值；收藏模型按优先级从高到低有序合并并去重。
- 合并结果只写 AgentID key。目标值成功持久化后才清理旧 key；重复执行迁移必须得到相同结果，不得重复追加或改变优先级结论。
- 存量会话根据其保存的 serve 命令匹配或创建历史修订。
- 未结束或可恢复的 Job/Graph 运行根据运行快照和已有会话锁定同一修订。
- 新业务配置映射为 AgentID 后使用升级时的当前修订。
- 无法完整还原 Agent 或修订时保留原值，历史显示未知 Agent，执行完整报错；不得猜测修订或使用当前修订恢复旧 ACP Session。

### 9.2 标题与 IM 配置

- 原消息 Agent 的 AgentID、model、mode、thought level 完整迁移到 IM 会话 Agent。
- 原消息 Agent 支持 `bin -p prompt` 时，以同一 AgentID 初始化群聊回复 Agent；否则留空并展示完整迁移提示。
- 原标题 Agent 支持 `bin -p prompt` 时，迁移为只含 AgentID 的标题生成 Agent；否则留空并展示完整迁移提示。
- 群聊回复未配置时提示“未配置 Agent”，不再提示“未配置模型”。

### 9.3 缓存与浏览器

- 旧命令 key 的探测缓存全部废弃。
- 已安装 Agent 先进入待验证，再按 AgentID、当前修订和迁移后的环境变量配置版本异步重建；迁移期间不得用旧缓存标记可用。
- 浏览器 localStorage 中的旧 Agent 引用（包括工作区默认、最近使用等）在加载时惰性迁移或清理。

除上述映射和配置拆分外不做更多兼容。

## 10. 功能接口

接口命名以实现为准，但必须提供以下能力：

- 查询管理目录：返回全部内置项（含弃用）和未删除自定义项，包含 AgentID、当前修订、安装方式、一次性生成能力、安装/可用状态、最近结果和完整错误；历史修订只在单 Agent 详情中展示。
- 查询未安装内置 Agent：仅返回未安装且未弃用项。
- 查询历史 Agent 展示信息：私有页面可按 AgentID 解析已删除记录。
- 安装内置 Agent：只接收 AgentID，返回安装输出、安装复检和验证结果。
- 添加、编辑、恢复自定义 Agent：执行本文规定的校验、安装判定、验证和修订切换。
- 启动定义占用冲突：返回冲突定义、当前归属或正在执行的管理操作及完整状态，保证同一定义同一时刻最多由一个管理操作验证和提交。
- 重新验证：按 AgentID 和目标修订执行，默认当前修订，并强制绕过退避。
- 删除与强制删除：返回阻止任务、逐项停止结果、已清理配置和保留引用摘要。
- 删除影响查询：在确认前返回将清理的角色配置、Agent 默认值和环境变量，以及将保留的 GraphWorkflow、Schedule、Job 和会话引用。
- Job 消息及继续执行：按会话的 AgentID 和绑定修订获取执行权；拒绝时返回 AgentID、修订、状态和实际错误。
- Graph/Schedule 运行：GraphRun 基线和后续版本按节点锁定修订；后续版本默认继承未变 AgentID 的修订，只有更换 AgentID 或显式更新到当前修订才改变快照；节点实例按其执行版本或已有会话取得执行权，错误定位到具体 Graph 节点。
- 一次性生成配置：标题、群聊回复分别读写 AgentID；IM 会话独立读写 AgentID 和 ACP model/mode/thought level。
- Agent 相关设置：环境变量按 AgentID、Agent 默认值按 AgentID、标题生成、群聊回复和 IM 会话配置分别独立读写；通用 settings 保存不得覆盖这些字段。
- 公开 Job/会话读取：在 share token 校验下返回实际引用 Agent 的最小展示信息。

用量、版本查询、探测刷新和失败退避保持现有行为，但索引改为 AgentID；涉及启动定义的结果必须同时校验运行定义修订，涉及 ACP 可用性的结果还必须校验环境变量配置版本。

Agent 管理页显示只读 AgentID、当前修订、内置/自定义标识、安装状态、可用状态和最近错误；待验证、验证中、删除中及已弃用均有独立状态展示。历史修订只在单 Agent 详情中展示，不进入新增或普通选择列表。

管理页在删除前展示清理影响和保留引用，删除期间展示进度，完成后展示逐项停止结果与清理摘要；来源、状态、表单和结果文案均接入中英文 i18n。

## 11. 非目标

- 不管理 Agent CLI 包的语义版本、版本选择或自动升级；运行定义修订只用于避免 ACP 会话混用启动程序。
- 不为自定义 Agent 自动安装 CLI。
- 不允许自定义定义覆盖内置 Agent。
- 不重做 ACP 环境变量设置页。
- 不自动删除 Graph、Schedule、Job 或历史会话引用。
- 不增加多用户或资源权限控制。

## 12. 验收

### 12.1 构建与 UI

- `make build-all`、`make test` 通过。
- 管理页静态资源、鉴权进入、设置导航，以及环境变量和默认值加载失败时的完整错误、只读状态与零写请求已完成浏览器验证；新增、安装、编辑、验证、删除、恢复及其他新管理接口尚缺专门的自动化覆盖，并需在后端重启加载本次代码后完成真实 Agent 冒烟。
- 桌面 Graph 画布的概览图不截获节点和边的点击；相关 undo、删除边和冻结节点编辑 E2E 通过。

### 12.2 目录、安装与状态

- 私有列表顺序、状态和禁用规则正确；公开列表只含可用项且不泄露内部字段。
- 自动安装只能执行内置预置流程，并完整展示输出；退出成功但 PATH 不满足时仍为未安装。
- 自动安装、升级和卸载的单步执行超时覆盖全部子进程；超时或取消后只允许追加有界回收时间，接口完成前必须回收完整进程树，且不存在仍在运行的下载、脚本或包管理进程。
- 超时回收期间安装占用保持有效；只有进程树和输出管道完成有界回收后，后续安装、升级或卸载请求才可开始。
- 包运行器场景仍以 Bin 判定安装。
- 路径形式的 Bin 不经 `PATH` 直接判定存在且可执行；仅能通过包运行器动态拉取、无可执行 Bin 的自定义 Agent 不予添加并完整提示。
- Agent 变为未安装后管理目录仍展示其最近结果与完整错误；只有删除才清除探测缓存。
- 未登录等 ACP 验证失败显示已安装但不可用；登录后强制重新验证可恢复为可用。
- 删除或废弃缓存后依次显示待验证、验证中、最终结果；有匹配结果的后台刷新保留原状态并显示刷新中。
- 内置目录后台刷新不会清除自定义 Agent 或被引用历史修订的 selector 状态；匹配的 model、mode 和 thought level 缓存继续可用。

### 12.3 自定义 Agent

- 未安装时不自动安装、不入库；临时环境变量可支持首次验证，成功后写入现有设置并可跨重启使用。
- 空格路径和参数按单值传递，shell 语义无效。
- 同一 Bin 的不同参数定义可共存；完整定义重复被拒绝或引导恢复已删除记录。
- 两个并发的相同定义新增、编辑或恢复操作只有一个能取得候选定义占用，其他操作收到完整冲突；失败、超时、取消或请求中断后占用可释放并重试。
- 同一 Agent 的编辑、恢复、删除和环境变量保存互斥；环境配置不能在运行定义验证和目录提交之间变化，成功提交的新当前修订保留与当前环境版本匹配的验证结果。
- `bin -p prompt` 关闭时只支持 ACP；开启时可进入一次性生成选择器并注入 AgentID 环境变量，且不传 ACP model。
- 编辑失败保留原配置；运行字段编辑成功生成新当前修订。
- 修改有效环境变量后，旧验证结果立即失效，当前修订经历待验证和重新验证；历史修订在下次使用时按新环境验证。仅修改禁用项或调整配置顺序时保存配置但不递增环境版本、不清缓存、不回收会话。运行中的执行不被中断，空闲会话在下次执行时使用新环境恢复原 ACP Session。
- 交互式消息从入口解析目标 Agent 开始持有执行权，直到 Session 绑定持久化并且本轮执行结束；删除检查通过后不能再产生新的目标 Agent Session。
- 通用设置页或并发旧页面保存不能覆盖新 Agent 的环境变量，也不能重新写回 deleting 或 deleted Agent 的环境变量、默认值和角色配置。
- Agent 目录或设置快照任一加载失败时，环境变量和默认值页面展示完整错误与重试入口，不展示可保存表单、不发送写请求；重试成功后才恢复编辑。
- 设置快照加载失败时不得出现空默认值或默认代理模板；服务端已有收藏、默认模型、模式、思考等级及环境变量保持不变。
- Agent 默认值页面修改一个 Agent 后只写入该 Agent；其他 Agent 的配置即使在页面打开后被别处更新也不得被旧快照覆盖。

### 12.4 修订与会话

- AgentID 跨运行定义变化保持不变。
- 新会话和新独立运行使用当前修订；旧会话继续使用绑定修订。
- GraphRun 基线版本按节点保存修订；新 GraphRunVersion 对未变 AgentID 默认继承上一版本修订，更换 AgentID 或显式更新到当前修订时才改变快照。显式更新即使没有其他配置变化也会生成版本；已经进入执行批次、开始执行或创建会话的实例保持原修订。
- Graph 实例重试或恢复时，复用已有会话的实例保持会话修订；没有会话且按新 GraphRunVersion 重新调度的实例使用该版本快照。
- Graph 恢复或继续在改变运行状态前验证当前版本的 Agent 修订和所有待复用 Session 的绑定；任一目标已删除、未知、未安装或验证失败时保持原运行状态并完整报错。
- Schedule 每次触发创建新的 GraphRun 并使用触发时生成的基线修订快照，不在 Schedule 定义上长期锁定修订。
- 新程序不会 resume/load 旧修订的 ACP Session。
- 旧修订无法启动时完整报错，不自动切换或重建。
- 被引用的内置与自定义旧修订重启后仍能解析和按需启动；无引用后均可清理。

### 12.5 标题与 IM

- 标题生成、群聊回复和 IM 会话配置互不覆盖。
- 前两者只保存 AgentID 并使用 CLI 默认模型；IM 会话继续传递 ACP model、mode、thought level。
- 群聊回复配置变化不影响 IM 私聊 Job。
- 标题失败错误写入 Job 且不被回退标题覆盖；群聊失败完整回复实际错误。

### 12.6 删除、并发与恢复

- 有运行中任务时删除被拒绝并列出阻止项；并发删除与新执行只有一方取得权利。
- Session、GraphRun 或历史 Agent 标识无法完整读取时删除被拒绝并展示实际错误，不得在引用不确定时进入清理。
- 强制删除逐项停止任务，任一失败都中止删除。
- 清理中退出后，重启可幂等继续；失败保持 deleting、完整错误和重试能力。
- 删除后所有选择器、运行权限、环境变量、缓存和可清理配置同步移除；Graph/Schedule 和历史记录保留引用。
- 删除取得独占权后，并发设置写入被拒绝；已打开的旧页面不能重新写回已清理配置。
- 历史页面只读并显示「已删除」；直接调用执行接口也被后端拒绝。
- 恢复沿用 AgentID，重新验证当前修订，历史会话仍绑定原修订。

### 12.7 历史、公开与迁移

- 私有和公开历史均能显示已删除 Agent；公开响应只含该 Job 实际引用的最小展示信息。
- 公开 Graph 响应不包含继承节点隐藏且不参与执行的 Agent 配置，只包含运行快照和实际 Session 绑定引用。
- Graph/Schedule 的失效错误包含 AgentID 和具体节点位置。
- 存量引用迁移为 AgentID；存量会话和可恢复运行绑定由旧命令/快照确定的历史修订。
- 同一 Agent 的多个旧 key 按目录声明的稳定优先级合并；环境变量冲突、Agent 默认值和收藏模型的结果确定且重复迁移不变。
