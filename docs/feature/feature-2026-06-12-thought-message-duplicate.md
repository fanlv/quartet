# Bug Fix: 新一轮对话后历史「思考」气泡重复显示

日期：2026-06-12

## 问题现象

在一个已完成（completed）的 ACP 任务上继续回复新消息后，聊天界面会重复出现**上一轮的某条「思考(thinking)」内容**，看起来像是同一条 AI 回复被反复收到。

典型现场：某个使用 ACP 后端的 job，第 1 轮回复中包含一段思考文字（例如「The icon masks are only applied above 1280px…」）。用户在该 job 上回复第 2 条消息后，这段属于第 1 轮的思考又作为一条独立气泡出现，且每次再发消息、再同步一次历史就可能再叠一次。

## 排查结论

经过对持久化数据、后端日志和前后端链路的核对，确认：

1. **这段内容不是模型重新生成的。** 它只存在于第 1 轮那条 assistant 消息的思考字段里，整个会话持久化文件中只出现一次；第 2、3 轮新生成的消息里完全没有这段内容。
2. **不是后端把它当作新事件重新推送的。** 后端日志中找不到这条思考对应的消息 ID 的任何二次下发记录。
3. **不是 ACP 会话重放(replay)导致的。** 第 2 轮全程复用同一个活动 ACP 会话，没有发生重连、重建或重置；并且会话历史重放只把消息正文和工具调用拼成上下文，**根本不包含思考字段**。

因此这是**前端在重新加载历史时，把同一段历史思考当成了新气泡叠加渲染**的问题，而非模型或后端的重复输出。

## 根因分析

用户在已有 job 上发送新消息后，前端会通过状态同步流程重新拉取会话历史。

后端的历史接口对「带有独立思考标识(`thought_msg_id`)」的 assistant 消息，会把**思考拆成一条独立的历史条目**返回，前端据此渲染成一个独立的思考气泡，并与界面上已有的消息做合并。

关键在于：**前端消息合并只按消息 ID 去重**，而同一段思考的两个来源 ID 对不上：

- **直播推送阶段**：思考气泡的 ID 是事件处理器在「思考开始」时临时生成的随机 ID。
- **落盘 / 历史回放阶段**：思考气泡的 ID 取自最终持久化到消息里的 `thought_msg_id`。

二者本应是同一个 ID，但在「思考与正文交错、提前刷新(eager-flush)」等时序场景下，落盘记录的思考 ID 与直播时前端已经拿到的那个临时 ID 发生了**错位**。一旦两个 ID 不一致：

- 历史回放出来的思考气泡（ID 来自 `thought_msg_id`）**绕过了按 ID 的去重**；
- 它与界面上已存在的那条直播思考气泡同时存在，于是同一段思考被重复显示；
- 每次再回复、再触发一次历史同步，就可能再叠加一次，表现为「反复收到同一条回复」。

这与历史上「Loop 模式用户消息重复」「SSE 重连消息重复」属于同一类问题：**直播态消息与历史态消息因 ID 口径不一致，导致按 ID 去重失效**。

## 修复方案

经实测确认：在持久态、消息 ID 自洽时不会重复（用 agent-browser 检查问题页面，45 个思考气泡中该内容只出现一次）。重复只发生在「直播事件已发出、但后端尚未把该思考 ID 稳定落盘」的瞬态窗口内，恰好触发一次历史重新拉取时——历史侧与直播侧的思考气泡 ID 失配，绕过了「按 ID 去重」。

因此采用**前端语义去重兜底**（而非改动后端流式 ID 时序，后者牵涉提前刷新、ID 捕获时机、容错等多条链路，改动面大、回归风险高）：

在所有「历史消息与现有消息合并」的去重逻辑中，对**纯思考气泡**（assistant 角色、有思考内容、正文为空）增加一层语义去重，以 `sessionId + 思考内容` 作为去重键——当历史中已存在等价思考气泡时，丢弃直播残留的那一条。这与既有的「合成 loop 用户消息按 `sessionId + content` 去重」「工具消息按 toolCallId 去重」是同一成熟模式。

落地改动：
- 消息合并工具函数：新增思考气泡的语义去重键与过滤规则（被绝大多数历史合并路径复用，一处修改即覆盖）。
- 会话 Hook 中一处未复用该工具函数、仅按 ID 手写去重的初始化加载路径：改为复用统一的合并函数，使各路径去重行为一致。
- 为合并函数补充单元测试：ID 不同但内容相同的思考气泡被去重；内容不同的思考气泡都保留；带正文的 assistant 消息不被误判为思考气泡。

该方案不影响 ID 一致时的正常合并，语义去重仅在「ID 不同但内容等价」时额外生效，不会误删不同内容的思考气泡。

## 影响范围

- 前端：历史与直播消息合并、去重逻辑（消息合并工具函数 + 会话 Hook 的历史加载路径）。
- 影响场景：使用 ACP 后端、且单轮回复中带有思考内容、并在同一 job 上多轮追加消息并触发历史重新拉取的交互式会话。
