# SSE 消息流重构归档

> 方案日期：2026-05-13
> 最后校验：2026-06-11
> 状态：已落地，本文仅保留功能层面的归档说明。

---

## 当前结论

SSE 消息流已经从旧的“事件总线主动推送 + 订阅者独立队列”模式，切换为“每个 job 一份事件缓冲 + 订阅者游标读取”的模式。

当前权威说明拆分为：

- 当前设计：`docs/arch/sse-event-buffer-design.md`
- 历史背景：`docs/arch/sse-event-buffer-history.md`

## 本次重构解决的问题

1. 慢客户端不再通过订阅者队列反压 job 执行。
2. 终态事件不再因为旧的独立队列写入超时而静默丢失。
3. 客户端短暂断线后可以按事件序号续接；如果续接范围已经不可用，则重新拉取当前快照。
4. 长任务的大量流式事件由缓冲生命周期管理，不再依赖固定重放窗口。
5. 首屏状态由持久化状态和消息历史重建，SSE 只承担首屏之后的实时增量。

## 保留约束

- 所有客户端可见错误必须完整透出，不能用笼统错误替代真实原因。
- 运行状态变更必须先形成可恢复的持久化状态，再发布对应实时通知。
- 每轮执行必须有明确开始和结束边界，取消、超时和异常也必须关闭当前轮次，避免恢复边界悬挂。
- 同一运行边界的持久化状态和实时事件必须使用一致的时间语义，避免刷新前后显示不一致。
- 慢客户端不能阻塞 job 执行；极端内存保护场景下允许断开滞后客户端，并要求客户端走恢复路径。
