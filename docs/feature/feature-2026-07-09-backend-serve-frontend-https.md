# 后端托管前端静态包并支持 HTTPS

日期：2026-07-09

## 背景

改造前，`make web` 会同时拉起两个进程：后端二进制（HTTP，当时默认 `127.0.0.1:8090`）和 vite 开发服务器（前端，dev 模式，有证书时监听 443、无证书时 5173，并通过 proxy 把 `/api` 转发到后端）。当前无证书默认监听已调整为 `0.0.0.0:8090`。

这套方式在部署/使用场景下有几个不理想的点：

1. 前端跑的是 dev 模式，而非正式构建产物，性能和稳定性都不适合当作对外服务。
2. 需要两个进程 + 端口 + proxy 协同，运维面变大（前端进程、vite 日志、watchdog 需要分别守护）。
3. HTTPS 由前端进程承担，后端本身只有明文 HTTP。

## 目标

改成「**只跑后端一个进程，由后端直接托管前端正式构建产物**」：

1. 前端用正式构建（`vite build`）产出静态包，输出到仓库根的 `static/` 目录。
2. 后端新增静态资源服务能力：
   - `/` 返回 `static/` 下的首页。
   - 其余路径按请求路径回源 `static/` 下的静态文件。
   - 非 `/api` 的未知路径回退到首页（SPA 兜底）。
3. 后端自身根据证书是否存在决定协议与端口：
   - 能读到 `certs/` 下的证书 → 启动 HTTPS，监听 443（对齐现在前端服务的行为）。
   - 读不到 → 明文 HTTP，默认 `0.0.0.0:8090`。
4. `make web` 相应调整：先构建前端到 `static/`，再启动后端；不再单独启动前端进程。

## 关键前提（已确认）

- 后端使用的 Web 框架原生支持 TLS：开启 TLS 会自动切换到支持 TLS 的网络库，只需提供证书配置即可；开启后为纯 HTTPS，不再接受明文请求（与现在 vite 的 443 行为一致）。
- 框架提供「静态目录 + 找不到文件时的兜底钩子」，配合「无匹配路由兜底」入口，可实现静态资源服务 + SPA 首页回退，且该兜底会经过全局中间件（CORS / 日志）但**不经过** `/api` 分组的鉴权中间件。
- 不能用「根路径通配静态服务」的方式：它会与 `/api/v1/*` 在路由树上冲突，因此走「无匹配路由兜底」入口。
- 前端所有 API 调用都是相对路径（`/api/v1/...`），由后端同源托管后无需改动任何前端请求代码，也不再需要 proxy 与跨域配置。
- 后端启动流程中的「预绑定端口探测 → 释放 → 框架绑定 → 就绪自检」都基于同一个监听地址，切换端口/协议时是单点改动。

## 决策记录

- **监听地址优先级**：显式设置的监听地址环境变量优先级最高；未设置时按「有证书 → `0.0.0.0:443`，无证书 → `0.0.0.0:8090`」。选用 `0.0.0.0` 是为了能通过域名或局域网地址访问。
- **TLS 与地址解耦**：是否加载 TLS 只取决于证书是否存在；即使显式指定了自定义监听地址，只要证书存在就照常在该地址上启用 HTTPS。
- **证书存在但加载失败**：直接启动失败并打印完整错误（遵循「错误信息全量显示」），不静默降级为 HTTP，避免「以为在跑 HTTPS 实际没起来」的困惑。
- **静态目录/证书目录可配置**：静态目录默认 `static`、证书目录默认 `certs`（均相对启动工作目录，即仓库根），各自提供环境变量覆盖入口。
- **端口绑定权限**：沿用现有「非 root 且有证书 → 借助提权」的模式来绑定 443；以 root 运行时直接绑定。
- **保留开发模式**：`make run-frontend`（vite dev）保留不动，供本地前端开发使用；本次只改「生产启动」路径 `make web`。
- **周边一并更新（全量范围）**：除核心改动外，同步更新后端重启脚本、守护脚本（watchdog）、`make web-status` / `web-stop` 与相关文档，避免遗留「双进程」时代的冗余逻辑。

## 改动分项

### 前端构建产物输出（`web/` 构建配置）

- 增加构建输出配置，使正式构建产物直接落到仓库根的 `static/`，并在构建前清空该目录。
- 开发服务器相关配置（端口、证书、proxy）保持不变。

### 后端静态服务（`cmd/web`）

- 在路由注册末尾增加「无匹配路由兜底」：
  - 命中 `/api/` 前缀但未匹配到路由的请求，按接口风格返回 404。
  - 其余请求交给静态目录服务；找不到对应文件时回退首页，实现 SPA 兜底。
- 静态目录来源：默认 `static`，支持环境变量覆盖。

### 后端 HTTPS 与监听（`cmd/web`）

- 增加监听解析：得出最终监听地址与「可选的 TLS 配置」。
  - 证书目录下证书齐备 → 加载证书得到 TLS 配置，默认地址切到 `0.0.0.0:443`。
  - 否则 → 无 TLS，默认 `0.0.0.0:8090`。
  - 显式监听地址环境变量始终优先于上述默认。
- 服务器构建处：存在 TLS 配置时启用 TLS 选项；预绑定探测与就绪自检复用同一监听地址。

### 启动脚本（`Makefile` 的 `web` 目标及相关脚本）

- `web` 目标流程调整为：环境检查 → **构建前端到 `static/`** → 构建后端 → 启动/重启后端（按证书决定 443 / 8090 与是否提权）→ 就绪等待 → 打印访问地址。
- 移除单独启动 vite 及其就绪等待、前端日志提示。
- 后端端口不再写死 8090：按证书存在与否推导，并贯穿端口探测、就绪等待与后端重启脚本；对特权端口的端口探测复用提权前缀。
- 结尾打印的访问地址统一为后端地址。

### 周边联动

- 后端重启脚本：接收后端端口参数（当前面向固定端口），使 HTTPS 模式下的重启与就绪判断准确。
- 守护脚本（watchdog）：生产模式下已无独立前端进程，调整为只守护后端。
- `make web-status` / `web-stop`：由「双进程/双端口」模型更新为「单服务」模型。
- 文档：更新 `make web` 的说明（不再是「启动 vite dev server」）。

## 边界与风险

- **纯 HTTPS，无明文回退**：开启 TLS 后不接受明文请求，且不做 HTTP→HTTPS 跳转（与现状前端一致，跳转能力如需可后续单列）。
- **监听地址环境变量与 Makefile 端口推导**：若通过环境变量改用非默认端口，Makefile 的端口探测按默认端口推导，可能与实际不一致；作为已知限制，面向单人本地使用场景可接受。
- **绑定 443 需权限**：非 root 环境依赖提权，与现在前端 443 的处理方式一致。
- **静态目录依赖启动工作目录**：默认相对工作目录取 `static`，当前启动路径均在仓库根；如从其它目录启动需用环境变量指定。
