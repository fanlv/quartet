# Loop Config 页面交互与 UI 重设计方案

日期：2026-05-25

状态：方案讨论中，尚未实施

本文是 Loop Config 页面的产品交互与界面设计方案，仅描述功能体验、布局和用户流程，不包含代码实现细节。

## 背景

Loop Config 是创建 Loop Job 前配置执行流程的核心页面。当前页面已经覆盖模板、变量、循环组、Prompt 步骤、Shell 步骤、会话策略、Agent / Model 选择、JSON 导入导出和模板保存等能力。

现有问题主要不在能力缺失，而在信息组织方式：所有配置项集中在同一个纵向弹窗内，用户需要在大量展开卡片和次级设置中寻找当前要编辑的内容。流程越复杂，阅读成本越高。

## 当前问题

1. 页面信息密度过高，模板、变量、流程树、步骤内容、Shell 预览和底部操作同时抢占注意力。
2. 主路径不清晰，用户很难快速判断“下一步该编辑哪里”。
3. 启动 Loop 的主按钮不够直观，复制、导入、保存等低频动作与主操作混在一起。
4. 校验反馈不够明确，页面只提示不可启动或用状态点表达，但没有把问题和具体节点强关联起来。
5. 变量插入入口不够顺手，编辑 Prompt 时变量信息和输入内容之间的关系不够直接。
6. 多层循环组主要依赖缩进和颜色边线表达，复杂流程下难以快速看清执行顺序。
7. Shell 步骤的脚本预览容易占据过多空间，影响用户关注真正需要配置的内容。

## 设计目标

1. 把页面从“配置表单弹窗”调整为“Loop 流程编排器”。
2. 让用户先看清执行流程，再编辑当前选中的节点。
3. 降低默认状态的信息密度，低频能力通过更多菜单、抽屉或折叠区承载。
4. 让校验错误可见、可定位、可修复。
5. 保持工具型产品的克制视觉风格，突出效率和可扫描性。
6. 首版优先改善主流程，不引入复杂画布式工作流。

## 推荐方案

推荐采用“左侧流程大纲 + 右侧节点配置 + 顶部模板栏 + 底部执行栏”的布局。

### 顶部模板栏

顶部负责全局状态和低频操作：

- 显示页面标题、当前模板名称、未保存状态。
- 提供模板选择入口，支持从已有模板中快速切换。
- 提供“更多”菜单，收纳复制 JSON、导入 JSON、保存为新模板、更新当前模板、删除模板和重置配置。
- 关闭按钮固定在右侧。

### 左侧流程大纲

左侧展示完整执行顺序，是页面的主要导航区域：

- 循环组、Prompt Step、Shell Step 按执行顺序展示。
- 每个节点展示类型、名称或摘要、重复次数、校验状态。
- 支持展开和收起循环组。
- 支持在当前层级添加步骤或循环组。
- 支持选择节点，右侧同步展示该节点的配置。
- 支持错误定位，用户可以从问题列表跳转到第一个错误节点。

首版建议先提供明确的添加、删除、复制、上移和下移操作。拖拽排序可以作为后续增强项，不放进首版必做范围。

### 右侧节点配置

右侧只编辑当前选中的节点，避免用户在长列表里查找配置项。

选中循环组时展示：

- 循环组名称。
- 迭代次数。
- 子节点数量和实际执行步数。
- 该组内的校验问题。

选中 Prompt Step 时展示：

- 步骤类型切换。
- Prompt 消息内容。
- 插入变量入口。
- 重复次数。
- 会话策略。
- Agent / Model 配置。
- 失败处理选项。

选中 Shell Step 时展示：

- 步骤类型切换。
- Shell 脚本选择。
- 脚本摘要和变量检测结果。
- 可折叠的脚本预览。
- 重复次数。
- 会话策略。
- 失败处理选项。

### 变量面板

变量不再作为页面顶部的常驻大块内容，而作为独立能力呈现：

- 顶部或底部显示变量数量摘要。
- 点击变量摘要可打开变量面板。
- 变量面板分组展示自定义变量、Shell 产生的变量和内置变量。
- Prompt 输入区保留“插入变量”按钮，编辑内容时可以直接选择并插入变量。

### 底部执行栏

底部只承载执行前最关键的信息和动作：

- 左侧展示配置摘要：节点数、执行步数、变量数量、错误数量。
- 出现错误时，展示第一条错误摘要和定位入口。
- 右侧展示明确的文字按钮：取消、保存模板、开始 Loop。
- 开始 Loop 是唯一主按钮；配置无效时禁用，并显示不可启动原因。

## 关键交互

1. 默认创建“主循环 + 第一步 Prompt”，并自动选中第一步。
2. 用户点击左侧任意节点，右侧立即切换为该节点配置。
3. 新增节点后自动选中新节点。
4. 删除非空循环组前需要二次确认。
5. 页面始终保持最多一个主要编辑对象，避免多个 Step 同时展开。
6. 校验错误在流程大纲、右侧字段和底部执行栏同步展示。
7. 点击错误定位入口后，自动选中并滚动到对应节点。
8. Prompt 输入区的变量插入能力保持常驻可用。
9. Shell 脚本预览默认折叠，需要时再展开。
10. 会话策略使用更直白的文案：复用当前会话、每轮新会话、每次重复新会话。

## 视觉风格

整体采用安静、克制、工具型的视觉方向：

- 背景使用浅灰，主面板使用白色。
- 边框和分割线尽量轻，减少多层卡片嵌套。
- 左侧大纲使用稳定行高、缩进线和类型标记表达层级。
- 类型颜色保持固定：Prompt 使用蓝色，Shell 使用琥珀色，循环组使用绿色，变量使用灰蓝色，错误使用红色。
- 关键动作必须使用文字按钮，低频动作可以使用图标或更多菜单。
- 页面字号保持紧凑但可读，避免过大的标题和营销式视觉。
- 移动端优先保证内容不挤压、不重叠、不依赖 hover。

## 分阶段落地建议

### 第一阶段：结构重组

完成四区布局：

- 顶部模板栏。
- 左侧流程大纲。
- 右侧节点配置。
- 底部执行栏。

第一阶段的目标是解决信息架构和主路径问题。

### 第二阶段：交互补齐

补齐节点级操作：

- 添加步骤。
- 添加循环组。
- 删除节点。
- 复制节点。
- 上移和下移节点。
- 错误定位。
- 变量面板。

第二阶段的目标是让复杂流程编辑更顺手。

### 第三阶段：视觉和移动端完善

完善视觉细节和响应式体验：

- 类型标记。
- 校验状态。
- 空状态。
- 更多菜单。
- 移动端分段视图。
- 输入区和下拉面板的移动端适配。

第三阶段的目标是让页面达到稳定可用的生产体验。

## 暂不做的事

1. 不做画布式工作流。
2. 首版不强制做拖拽排序。
3. 不改变 Loop Config 的功能语义。
4. 不改变模板、变量、Prompt、Shell、会话策略和 Agent / Model 的用户概念。
5. 不引入重量级组件库。

## 待确认问题

1. 首版是否需要节点复制功能，还是只保留添加、删除、上移、下移。
2. 变量面板默认是否展开，还是只显示变量摘要。
3. Shell 脚本预览默认折叠后，是否需要提供“快速查看前几行”的摘要。
4. 移动端分段视图的默认 tab 是“流程”还是“配置”。
5. 开始 Loop 前，是否需要展示一次完整执行摘要确认。
