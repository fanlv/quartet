# 技术方案：任务结束 Hook（图工作流终点 + 对话每轮结束）

## 背景

设置页原有一个「图工作流终点默认 Hook（Shell）」：图工作流走到终点结点（Hook 模式=默认）时执行一段用户自配脚本，用来发通知（飞书 / 微信 / Webhook）。但同样的诉求在普通对话（interactive）里完全没有：Agent 跑一轮几分钟到几十分钟，用户离开电脑后没有任何提醒手段，只能盯着页面。

结果是同一个「跑完了叫我一声」的需求，只有走图工作流的那一半能被满足。

## 目标

把这段全局默认脚本从「图工作流专属」升级为「任务结束通用 Hook」：图工作流终点、对话每一轮结束，都执行同一段脚本；脚本通过环境变量判断本次是哪种结束、结果如何。

## 范围

**做**：

- 设置项语义与文案由「图工作流终点默认 Hook」改为「任务结束默认 Hook」（Web 设置页 + iOS 用户配置页同步）。
- 对话每一轮结束后触发该脚本：完成、失败、用户停止都触发，一轮只触发一次。
- 给脚本补充「本次是什么结束」的上下文环境变量（触发来源、会话、任务模式与状态、本轮结果、失败原因）。
- 两个触发点共用同一套 Hook 执行语义（超时、失败只打日志、输出忽略）。

**不做**：

- 不改图工作流终点结点自身的三态配置（默认 / 自定义 / 关闭），也不给对话增加同类开关：对话是否通知由脚本内部按环境变量自行判断。
- Hook 仍是纯副作用：不改任务状态、不产出变量、失败不影响对话或 run。
- 不为对话 Hook 增加前端展示位（图工作流仍在运行详情里展示 Hook 结果；对话侧只写日志）。
- 不做定时任务、IM 消息等其他入口的 Hook 触发。

## 关键设计前提

1. 对话轮次的终态判定（完成 / 失败 / 停止，以及「消息发给已完成任务时恢复原状态」的规则）必须先落定，Hook 才能读到正确的本轮结果，因此 Hook 是轮次生命周期的最后一步。
2. Hook 必须异步执行：轮次收尾后紧接着要释放运行资源、派发消息队列里的下一条消息，一个挂死脚本不能把队列卡住。
3. Hook 使用脱离取消的独立上下文并自带超时：用户「停止」的是对话，不该顺手杀掉已经触发的通知。
4. 全局脚本在触发时实时读取，改完设置下一轮生效，不做快照冻结。
5. 图工作流与对话两条链路物理隔离，共用同一个 Hook 执行器，保证两边的超时、环境变量注入规则、失败语义完全一致。

## 用户流程

1. 在设置页「通用」填一段脚本（例如把 `$QUARTET_JOB_TITLE` 推到微信）。
2. 跑一个图工作流：终点结点保持「使用全局默认脚本」，到达终点即执行。
3. 在任意对话里发一条消息：Agent 回复结束后同一段脚本执行，脚本里能读到本轮结果与助手回复。
4. 需要区分场景时，脚本按触发来源分支：图工作流结点 Hook 与对话轮次结束用不同的来源标识。

## 方案设计

### 1. 配置

- 全局设置里的脚本字段改名为「结束 Hook 脚本」，语义扩展到两个触发点；读取时兼容老键名，用户已配置的脚本不丢。
- 图工作流终点结点的 Hook 模式含义不变：默认＝跑这段全局脚本。

### 2. 触发点

- **图工作流**：不变（Prompt 结点 Hook、主图终点 Hook，终点按模式解析脚本）。
- **对话**：一轮交互到达终态后触发，覆盖完成 / 失败 / 停止；轮次内提前失败（例如会话初始化失败）同样触发，环境变量里带失败原因。图工作流任务里的结点会话聊天也算一轮对话，同样触发，由脚本按任务模式自行取舍。

### 3. 注入的环境变量

- 公共：触发来源（图工作流结点 / 对话）、任务标题、任务 ID、最近一条助手消息（对话侧过长会截断）。
- 图工作流额外：run 与结点标识、结点标题与类型、结点可见的业务变量。
- 对话额外：会话 ID、任务模式、任务最终状态、本轮结果（完成 / 失败 / 停止）、失败原因（全量，不截断）。
- 上下文变量保留 `QUARTET_` 命名空间并最后注入，用户变量无法覆盖。

### 4. 失败与可观测性

- 非零退出、超时、拉起失败：只记一条告警日志（含 stdout / stderr）；图工作流侧仍额外落一条 Hook 事件供详情面板展示，对话侧只记日志。
- 成功记一条 info 日志，带触发来源与任务标识，便于区分两个入口。

## 风险

- **通知变吵**：对话每轮都触发，高频聊天会产生大量通知。缓解方式是脚本按环境变量（本轮结果、任务模式）自行过滤；如后续仍嫌吵，再考虑增加开关。后续已按此补了「无人实时查看该任务时才通知」的开关，见 `feature-2026-08-29-end-hook-skip-when-watched.md`。
- **脚本挂死**：异步 + 超时兜底，不阻塞轮次收尾与消息队列派发。
- **进程退出丢通知**：对话 Hook 不纳入优雅退出等待，重启瞬间触发的通知可能被中断；纯副作用场景可接受。

## 验收标准

- 设置页（Web / iOS）文案为「任务结束默认 Hook」，脚本可编辑并持久化；升级前已配置的脚本仍在。【手工】
- 对话发一条消息，Agent 回复结束后脚本执行一次，环境变量里的任务标题、会话、本轮结果正确。【手工】
- 对话中途点停止：脚本执行一次且本轮结果为「停止」。【手工】
- 对话运行失败：脚本执行一次，失败原因完整可读。【手工】
- 图工作流终点 Hook 行为不回归：默认 / 自定义 / 关闭三态、续跑不重复触发、Hook 结果仍在运行详情展示。【手工 + 既有用例】
- 脚本非零退出或超时时，对话与 run 都正常结束，仅有告警日志。【手工】
- 后端 `make build-all`、前端 `npm run build` 通过，既有 graph / job 用例（含 race）不回归。
