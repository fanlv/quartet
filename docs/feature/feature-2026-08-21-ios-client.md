# Quartet iOS 客户端功能方案

## 1. 概述

Quartet 当前 Web 端已覆盖工作空间、Job、Agent 对话、Graph 工作流、定时任务、文件查看、统计与系统配置。iOS 客户端不应复刻整套桌面管理界面，而应定位为“局域网内的随身操作与运行监控端”：用户离开电脑但仍处于同一局域网时，可发起或继续 Agent 对话、查看运行进度，并处理需要人工介入的工作流。

客户端连接用户自己运行的 Quartet 后端，仅用于个人内部分发，不上架 App Store。产品上只连接一个可配置的后端实例，默认地址为 `https://devbox.fanlv.fun/`；不在 iPhone 本地运行 Agent，也不在本地直接访问后端机器的文件系统。

## 2. 目标

- 覆盖移动场景中最高频的闭环：连接后端、选择工作空间、发消息、看流式结果、停止任务、继续历史对话。
- 让用户能够在手机上快速判断 Job 或 Graph run 是否仍在运行、已经完成或为何失败。
- 支持 Graph 工作流的移动端监控与轻控制，但把复杂编排留在 Web。
- 与 Web 共享服务端数据和运行状态，用户可在两端无缝接续同一个 Job。
- 优先复用现有 HTTP API 与 SSE，不为 iOS 复制业务接口；只有明确属于手机端的能力才考虑新增接口。

## 4. 产品原则

1. **移动优先，而非页面搬运**：围绕单手查看、短输入和快速确认设计。
2. **服务端为唯一事实来源**：Job、消息、工作流和文件均以 Quartet 后端状态为准，不做两套业务数据。
3. **执行与展示分离**：Agent 和工作流继续在 Quartet 所在电脑或沙箱运行，iOS 只负责控制和展示。
4. **完整呈现错误**：连接、请求、Agent、工具调用与工作流错误不得只显示笼统提示；主界面可摘要，但必须能展开查看完整信息。
5. **高风险操作显式确认**：停止、删除、恢复执行等动作展示影响范围并要求确认。
6. **弱网可恢复**：短暂断网不丢输入；恢复连接后主动校准 Job 快照和后续事件。结果未知的请求沿用原幂等标识，已经明确终止后由用户发起的新执行使用新标识。
7. **状态语义不混用**：Job 状态以服务端 `status` 为准；最近一次交互结果仅用于收口该轮消息，不覆盖 Job 的权威状态。失败详情应从持久化进度中恢复，重新进入页面后仍可查看。
8. **异步结果与上下文一致**：可能跨越连接或工作空间切换的请求必须校验当前上下文；旧上下文的迟到响应不得覆盖当前列表、分页游标、缓存或连接状态。
9. **授权凭证最小暴露**：任何可独立授权请求的 bearer token 都按敏感凭证处理；需要持久化时只进入系统安全存储，普通缓存只保存展示所需的非敏感数据。

## 5. 阶段定义

为避免混用 `MVP`、`P1/P2`、`阶段 A/B/C`，后续统一使用以下阶段编号：

- **阶段 0：当前代码状态**。指仓库中已经实现的能力，但不自动等同于已完成平台验证或达到发布条件。
- **阶段 1：核心纵切**。连接、工作空间、Job、基础对话、图片、Graph 监控与关键控制。
- **阶段 2：随身操作扩展**。分享、工作流模板、定时任务轻控制、文件只读浏览、长对话效率工具。
- **阶段 3：运营与个性化**。统计、配额、轻量创建、快捷指令、细粒度提醒与 iPad 优化。

## 7. 信息架构

目标信息架构中，首次启动进入“连接设置”；连接成功后围绕以下入口组织：

- **对话**：最近 Job、新建对话、工作空间筛选、运行状态。
- **工作流**：Graph run 监控；阶段 2 增加工作流模板和定时任务。
- **设置**：后端连接、Token、显示偏好、诊断信息和退出连接。

工作空间作为全局筛选条件，不单独占用底部入口。用户可在对话首页或导航栏快速切换，也可选择“全部工作空间”。

当前代码使用“运行台”和“设置”两个 tab。`Graph run` 从对应 Graph Job 进入。目标信息架构仍是后续方向，不应误解为当前已经全部实现。

## 8. 阶段 1：核心纵切

### US-001：连接 Quartet 后端

**用户故事：** 作为用户，我希望保存 Quartet 服务地址和访问 Token，以便安全地从手机访问自己的实例。

**当前实现状态：** 已实现，待平台验证。已实现默认地址、健康检查、按需鉴权、连接验证与首次数据刷新分离、HTTP 明文风险提示、按完整服务地址隔离的 Keychain Token，以及重配/清除连接；尚未完成 macOS 构建与真机验收。

**验收标准：**

- [ ] 服务地址默认填入 `https://devbox.fanlv.fun/`，用户可修改并发起连接测试。
- [ ] 客户端先读取服务健康状态，再在需要鉴权时验证 Token；只有这两步通过才标记连接验证成功。
- [ ] 连接验证与首次工作空间/Job 刷新分别呈现结果；验证成功但首刷失败时仍保留已连接状态，展示缓存或空态、完整首刷错误和重试入口，不回退到连接设置，也不误报 Token 无效。
- [ ] 连接验证失败时显示请求地址、HTTP 状态和服务返回的完整错误。
- [ ] 主实例 Token 按完整规范化服务地址隔离；修改为另一地址时不得沿用旧地址凭证或接受旧连接请求的迟到结果。主实例 Token 及其他可独立授权请求的 bearer token 如需持久化，只能保存在系统安全存储中，界面默认隐藏。
- [ ] 客户端只保存一个后端地址和对应 Token，可编辑或清除当前连接。
- [ ] 在真机上验证首次连接、Token 错误、服务不可达和重新连接流程。

### US-002：浏览工作空间与 Job

**用户故事：** 作为用户，我希望按工作空间查看最近的 Job，以便快速回到正在进行或刚完成的任务。

**当前实现状态：** 已实现，待平台验证。已实现工作空间筛选、Job 分页、切换时的请求隔离、Job 初始执行来源、详情、停止、置顶、重命名和删除；Graph Job 删除会等待相关执行退出后再清理。不同尺寸 iPhone 适配仍待验证。

**验收标准：**

- [ ] 支持“全部工作空间”和单个工作空间筛选。
- [ ] Job 列表按最近更新时间展示，并支持继续加载。
- [ ] 快速切换工作空间时，列表、分页游标、加载态、错误和缓存只接受当前筛选条件的请求结果；已取消或已过期请求即使稍后返回也不得污染当前页面。
- [ ] 每项至少显示标题、工作空间、执行来源、更新时间、运行模式和状态。普通 Job 优先显示创建时持久化的初始 Agent，没有 Agent 时显示初始模型，因此尚无 session 的空 Job 也能正确归因；Graph Job 和定时触发 Job 分别显示 `GRAPH`、`SCHEDULE` 类型标记。不得用工作空间当前默认值猜测历史 Job。
- [ ] 可区分交互式 Job、Graph Job 和定时任务触发的 Job。
- [ ] 支持置顶、重命名和删除；删除前必须确认并说明将清理的运行与会话数据。
- [ ] 删除 Graph Job 时先阻止新的运行操作，停止并等待 Graph 与关联对话执行退出，再依次清理 Graph run、全部关联会话和 Job；清理流程完成后才报告成功。
- [ ] 删除中任一步失败时不得报告成功，并展示完整错误；该 Job 保持隐藏且不可继续执行，允许在当前服务进程中重试清理，服务重启后自动继续清扫持久化残留。
- [ ] Graph Job 删除成功后，Job、Graph run 和全部关联会话均不可再访问，旧执行的迟到写入不得使其重新出现。
- [ ] 列表刷新失败时保留最近一次成功内容，并显示完整错误。
- [ ] 在不同尺寸 iPhone 上验证筛选、分页和状态展示。

### US-003：新建 Agent 对话

**用户故事：** 作为用户，我希望从手机选择工作空间和 Agent 发起任务，以便不在电脑前也能启动工作。

**当前实现状态：** 已实现，待平台验证。已实现工作空间、Agent、模型、模式、思考等级选择，Agent 验证状态与有界自动重试，创建请求幂等，服务端共享默认 Agent/模型，以及照片库、相机、系统图片文件三种图片来源；创建或首条消息发送失败时保留输入和附件。仍需在 macOS/Xcode 和真机上验证。

**验收标准：**

- [ ] 用户可选择工作空间、可用 Agent、模型、模式和思考等级。
- [ ] Agent 列表加载中或 Agent 处于 `pending_validation`、`validating` 时展示明确的等待状态并执行有界自动重试；达到等待上限后停止自动请求，保留当前选择并提供“重新检查”，不得将验证中折算为“没有可用 Agent”，也不得在确认可用前创建 Job。
- [ ] Agent 列表请求失败时保留已输入的草稿和附件并显示完整错误；用户可重新进入页面发起请求。已有 Agent 快照但验证失败或超时时，页面内提供显式“重新检查”。
- [ ] 创建 Job 请求在首次提交前生成稳定的幂等标识；工作空间、Agent、模型、模式、思考等级和工作目录相同且结果未知时，重试必须复用该标识并返回同一 Job；任一创建参数变化或服务端明确拒绝后再提交时使用新标识。
- [ ] 创建 Job 与发送首条消息使用彼此独立的幂等标识，避免创建重试与消息执行相互冲突。
- [ ] 创建 Job 时保存初始 Agent、模型、模式和思考等级作为该 Job 的历史归因；后续修改工作空间默认值不得改写这些信息。
- [ ] 默认 Agent 和模型读取工作空间的服务端共享偏好；iOS 与 Web 修改后，另一端刷新即可看到一致结果。
- [ ] 用户可在 iOS 修改当前工作空间的默认 Agent 和模型，修改后不影响已创建 Job 的运行配置。
- [ ] 服务端只接受当前存在且处于 active、非 deprecated 状态的工作空间默认 Agent，并拒绝在没有默认 Agent 时单独保存默认模型；该校验不触发动态 Agent 探测。Web 与 iOS 只允许选择当前 available Agent 及其模型，Agent 或模型失效、错配时清空相应选择。
- [ ] 默认 Agent/模型通过字段级 `PATCH` 更新，只提交显式修改字段和必填 `expectedVersion`；陈旧版本返回 HTTP 409，跨端并发不得覆盖标题、描述、工作目录等未被本次操作修改的字段。
- [ ] Agent 删除成功后，所有引用该 Agent 的工作空间同时清空默认 Agent 及其配套默认模型；陈旧客户端不得将已删除 Agent 写回默认值，既有 Job 的历史归因不变。恢复同一 Agent 时不自动恢复已清空的工作空间默认值，需由用户重新选择。
- [ ] 支持输入文本，并从相册、相机或系统文件选择器添加图片。
- [ ] 创建 Job 或发送首条消息失败时保留草稿和附件，并显示完整错误。
- [ ] Agent 不可用时明确说明原因，不允许进入无法执行的假成功状态。
- [ ] 在真机上验证纯文本、图片和中英文输入法发送。

### US-004：查看并继续实时对话

**用户故事：** 作为用户，我希望实时查看 Agent 的回复和工具执行过程，并能继续追问。

**当前实现状态：** 已实现，待平台验证。已实现普通 Job 全部 session 的历史合并、SSE 流式消息与真实连接状态、Markdown、安全链接、代码块复制、思考内容、工具调用和完整错误；消息与命令具备持久化幂等语义。运行中的页面内存队列支持取消待发送、结果未知重试和失败恢复，队列不跨页面或进程持久化。

**验收标准：**

- [ ] 支持历史消息、流式增量消息、Markdown、代码块、图片、思考内容、工具调用和工具结果。
- [ ] 普通非 Loop Job 存在多个 session 时，首次打开、重连校准和全量恢复均按服务端顺序合并全部 session 的历史；切换 Agent 形成的新旧会话都不得丢失，重复消息不得重复展示。
- [ ] 继续发送默认使用服务端记录的最新有效 session 及其 Agent、模型配置，不以工作空间当前默认值改写既有会话。
- [ ] 长消息可复制，代码块可单独复制；链接交由系统安全打开。
- [ ] 普通交互式 Job 运行时可继续输入并排队发送，用户可取消尚未执行的排队消息。
- [ ] 每条待发送消息在首次请求前生成稳定的 `clientMessageId`；超时、断线和其他结果未知场景下的重试复用该标识，服务端已明确返回失败、停止或中断后由用户发起的重新执行使用新标识。
- [ ] 服务端按 Job 与 `clientMessageId` 对完整发送语义做幂等处理；相同标识和相同消息、session、Agent、模型、模式及思考等级只执行一次，并返回已持久化的处理状态，相同标识对应不同语义时明确拒绝并显示冲突。
- [ ] 本地待发送消息、HTTP 处理结果和持久化历史使用稳定消息标识收敛为一条消息；SSE 终态触发快照与历史校准，重复响应或恢复不得触发第二次执行。
- [ ] Slash 命令按所属 Job 和客户端消息标识持久化去重；重复请求返回首次命令结果，不重复执行跳转、切换或创建等副作用。命令触发创建 Job 时使用独立的创建幂等标识。
- [ ] 用户可停止当前生成；停止动作需要清楚标识作用对象。
- [ ] 网络中断时编辑区仍可输入，未发送草稿不会丢失。
- [ ] 重连后客户端先获取最新快照，再续接事件；同一消息不得重复显示。
- [ ] 对话页连接徽标区分“连接中”“实时已连接”“重连中”和“已断开/已结束”；只有 SSE 实际建立且尚未断开时才能显示实时已连接，不得根据后端总体可达或“未在重连”推断为在线。
- [ ] 服务端返回的错误信息可完整展开和复制。
- [ ] 在真机上验证后台切换、锁屏后返回、网络切换和长对话滚动。

## 12. 接口复用与必要调整

阶段 1 优先复用 Web 已使用的 HTTP API 和 SSE，并增加跨客户端通用的 Job 状态观察与幂等能力；不复制仅供 iOS 使用的业务语义：

1. **连接与鉴权**：复用健康检查和轻量 Token 验证接口，不通过 Agent 列表探测连接是否有效；验证结果与验证后的业务数据首刷结果分别处理，凭证按完整规范化服务地址隔离。
2. **工作空间与 Job**：复用工作空间列表、Job 列表、详情、重命名、置顶、删除和运行控制接口；Job 摘要提供创建时保存的初始 Agent/模型归因。Graph Job 删除须阻止新的运行操作，等待关联执行退出后再清理 run、会话和 Job；清理失败时保留隐藏且不可执行的删除状态并返回完整错误，支持当前进程重试和服务重启后的残留清扫。
3. **消息同步**：复用会话历史、Job 快照和现有 SSE 事件续接能力；普通 Job 恢复时读取全部 session，从后台返回时先拉取快照，再恢复事件流。
4. **Graph 与定时任务**：复用现有 Graph run、节点会话和 schedule 接口，不为移动端复制一套动作语义；Graph run 的 `timedOut` 保留“已超时”展示。
5. **文件与统计**：阶段 2/3 继续复用现有只读文件和统计接口。
6. **工作空间共享偏好**：默认 Agent、默认模型作为服务端工作空间数据由 Web 与 iOS 共用。服务端校验 Agent 是否存在且处于 active、非 deprecated 状态，但不为偏好写入触发动态探测；客户端将模型选择限制在当前 available Agent 的模型范围。通过 `PATCH /api/v1/workspace/:id` 仅提交显式修改字段和必填 `expectedVersion`，陈旧版本返回 HTTP 409 且不覆盖其他字段。删除 Agent 及启动恢复删除流程时成对清除引用它的默认 Agent 和默认模型；恢复 Agent 不恢复旧默认值。
7. **创建幂等**：创建 Job 使用独立的稳定幂等标识；相同创建语义在结果未知时重试返回同一 Job，任一创建参数变化或服务端明确拒绝后的新提交使用新标识。创建与首条消息使用不同标识。
8. **消息与命令幂等**：普通消息按完整发送语义持久化去重，结果未知的重试沿用原标识，明确终止后的重新执行使用新标识；Slash 命令按所属 Job 与消息标识去重，重复请求返回首次结果且不重复执行副作用。
9. **其他动作防重复**：运行控制期间锁定重复操作；网络结果未知时先读取服务端状态再决定是否重试。

## 13. 非功能要求

### 13.1 兼容性

- 阶段 1 以 iPhone 为主要设备，当前最低版本固定为 iOS 26.0，不兼容更早版本。
- 当前版本不承诺兼容尚未提供状态观察、创建幂等、消息幂等或服务端工作空间默认值能力的旧后端，也不要求旧客户端理解新增契约。
- 支持浅色、深色模式和动态字体。
- 关键操作在窄屏和横屏下均不得被键盘遮挡。

### 13.2 安全与隐私

- 主实例访问 Token、分享 Token、临时资源 Token 以及后续新增的任何 bearer token 均按敏感凭证处理；确需持久化时只能进入系统安全存储。
- 普通偏好、离线快照和业务模型缓存不得保存 bearer token；除用户主动复制分享链接外，也不得写入日志、诊断导出或剪贴板。
- bearer token 可在当前连接生命周期内保留在内存中，但不得进入普通持久化存储。主实例 Token 按完整规范化服务地址隔离；清除、重新配置或切换服务地址时清除旧凭证、相关内存状态和旧凭证上下文下的缓存，且旧请求结果不得写回新连接。
- 默认服务地址使用 HTTPS，并允许用户自行修改；若填写局域网 HTTP 地址，连接前需显式确认风险。
- 错误展示遵循“全量给用户看”，诊断日志导出前仍需自动排除 Token 等认证字段。
- 生物识别锁作为阶段 2 可选项，不阻断阶段 1。

### 13.3 性能与可靠性

- 冷启动后优先展示本地缓存的工作空间和 Job 摘要，再后台刷新。
- Job 列表采用分页；普通 Job 当前仍一次加载全部 session 历史，长对话增量加载与列表虚拟化保留为后续优化。
- 可能跨越服务地址、凭证或工作空间切换的异步请求，在结果落地前校验其上下文仍然有效；上下文切换后丢弃旧请求的迟到结果。
- 应用进入后台后不假设长连接持续存活；回前台必须重新校准。
- 所有时间以服务端记录为准，并按设备时区显示。

### 13.4 可访问性

- 所有状态不能只靠颜色区分。
- 控件提供 VoiceOver 标签和足够的点击区域。
- 流式新增内容不应持续抢占 VoiceOver 焦点。

### 13.5 构建与验证边界

- Linux 环境可执行后端单元测试和 iOS 源码契约检查，但不能完成 Swift/Xcode 构建、签名、Simulator 或真机验证。
- iOS 工程的构建、安装、照片访问、Keychain 行为、网络联通和后台恢复结果，必须在 macOS + Xcode 环境重新验证。
- 文档中的“已实现，待平台验证”仅表示功能代码已落地并通过当前环境可执行的自动化检查；只有完成 macOS 构建和真机或 Simulator 验证后，才能标记为“已验证”或“可发布”。

## 14. 成功指标

- 90% 以上的已配置用户能在 30 秒内完成“打开应用—选择工作空间—发送消息”。
- 常规网络下，从服务端产生消息到前台展示的延迟中位数不超过 2 秒。
- 前后台切换或短暂断网后，消息重复率和可观测消息丢失率均为 0。
- 阶段 1 中所有服务端错误都可在客户端查看完整内容，不出现只有“未知错误”的失败页。

## 16. 已确认决策

1. 客户端仅用于个人内部分发，不上架 App Store。
2. 最低系统版本采用开始开发时 Apple 最新正式发布的大版本，当前固定为 iOS 26.0。
3. 客户端仅要求在与 Quartet 后端相通的局域网内使用，不建设公网访问能力。
4. 优先使用 HTTPS，默认服务地址为 `https://devbox.fanlv.fun/`；允许用户修改地址。
5. 只配置一个 Quartet 后端实例，产品行为与当前 Web 保持一致。
6. 工作空间默认 Agent 和模型改为服务端共享偏好，由 Web 与 iOS 共用。
7. iOS 优先复用现有接口；除手机特有能力或跨端一致性所需的通用调整外，不新增接口。
