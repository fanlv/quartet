# Quartet iOS 客户端功能方案

## 1. 概述

Quartet 当前 Web 端已覆盖工作空间、Job、Agent 对话、Graph 工作流、定时任务、文件查看、统计与系统配置。iOS 客户端不应复刻整套桌面管理界面，而应定位为“局域网内的随身操作与运行监控端”：用户离开电脑但仍处于同一局域网时，可发起或继续 Agent 对话、查看运行进度、处理需要人工介入的工作流，并在客户端观测到关键状态变化时收到提醒。

客户端连接用户自己运行的 Quartet 后端，仅用于个人内部分发，不上架 App Store。产品上只连接一个可配置的后端实例，默认地址为 `https://devbox.fanlv.fun/`；不在 iPhone 本地运行 Agent，也不在本地直接访问后端机器的文件系统。

## 2. 目标

- 覆盖移动场景中最高频的闭环：连接后端、选择工作空间、发消息、看流式结果、停止任务、继续历史对话。
- 让用户能够在手机上快速判断 Job 或 Graph run 是否仍在运行、已经完成或为何失败。
- 支持 Graph 工作流的移动端监控与轻控制，但把复杂编排留在 Web。
- 在应用能够观测运行状态时，通过应用内提醒和系统本地通知减少用户持续盯着页面的需要。
- 与 Web 共享服务端数据和运行状态，用户可在两端无缝接续同一个 Job。
- 优先复用现有 HTTP API 与 SSE，不为 iOS 复制业务接口；只有明确属于手机端的能力才考虑新增接口。

## 4. 产品原则

1. **移动优先，而非页面搬运**：围绕单手查看、短输入、快速确认与及时通知设计。
2. **服务端为唯一事实来源**：Job、消息、工作流和文件均以 Quartet 后端状态为准，不做两套业务数据。
3. **执行与展示分离**：Agent 和工作流继续在 Quartet 所在电脑或沙箱运行，iOS 只负责控制和展示。
4. **完整呈现错误**：连接、请求、Agent、工具调用与工作流错误不得只显示笼统提示；主界面可摘要，但必须能展开查看完整信息。
5. **高风险操作显式确认**：停止、删除、恢复执行等动作展示影响范围并要求确认。
6. **弱网可恢复**：短暂断网不丢输入；恢复连接后主动校准 Job 快照和后续事件，消息重试沿用同一客户端消息标识，避免重复执行或遗漏。
7. **状态语义不混用**：Job 状态以服务端 `status` 为准；最近一次交互结果仅用于收口该轮消息，不覆盖 Job 的权威状态。失败详情应从持久化进度中恢复，重新进入页面后仍可查看。
8. **异步结果与上下文一致**：工作空间、Job 和会话切换后，旧上下文的迟到响应不得覆盖当前页面、分页游标、缓存或错误状态。
9. **授权凭证最小暴露**：任何可独立授权请求的 bearer token 都按敏感凭证处理；需要持久化时只进入系统安全存储，普通缓存只保存展示所需的非敏感数据。

## 5. 阶段定义

为避免混用 `MVP`、`P1/P2`、`阶段 A/B/C`，后续统一使用以下阶段编号：

- **阶段 0：当前代码状态**。指仓库里已经存在实现代码，但不自动等同于发布或验收完成。
- **阶段 1：核心纵切**。连接、工作空间、Job、基础对话、图片、Graph 监控与关键控制。
- **阶段 2：随身操作扩展**。分享、工作流模板、定时任务轻控制、文件只读浏览、长对话效率工具。
- **阶段 3：运营与个性化**。统计、配额、轻量创建、快捷指令、细粒度提醒与 iPad 优化。

## 7. 信息架构

目标信息架构中，首次启动进入“连接设置”；连接成功后使用四个一级入口：

- **对话**：最近 Job、新建对话、工作空间筛选、运行状态。
- **工作流**：Graph run 监控；阶段 2 增加工作流模板和定时任务。
- **通知**：保存客户端已观测到的完成、失败、等待人工、断线等事件；带 Job 目标的通知进入对应 Job，Graph 等待人工通知进入节点会话，连接异常通知仅标记已读。
- **设置**：后端连接、Token、通知偏好、显示偏好、诊断信息和退出连接。

工作空间作为全局筛选条件，不单独占用底部入口。用户可在对话首页或导航栏快速切换，也可选择“全部工作空间”。

当前代码使用“运行台”和“设置”两个 tab。`Graph run` 从对应 Graph Job 进入；通知中心从运行台铃铛或设置页以 sheet 打开。目标四入口仍是后续信息架构方向，不应误解为当前已经存在四个 tab。

## 8. 阶段 1：核心纵切

### US-001：连接 Quartet 后端

**用户故事：** 作为用户，我希望保存 Quartet 服务地址和访问 Token，以便安全地从手机访问自己的实例。

**当前实现状态：** 已有码。已实现默认地址、健康检查、按需鉴权、HTTP 明文风险提示、Keychain Token 存储以及重配/清除连接；尚未完成 macOS 构建与真机验收记录。

**验收标准：**

- [ ] 服务地址默认填入 `https://devbox.fanlv.fun/`，用户可修改并发起连接测试。
- [ ] 客户端先读取服务健康状态，再在需要鉴权时验证 Token；只有这两步通过才标记连接验证成功。
- [ ] 连接验证与首次工作空间/Job 刷新分别呈现结果；验证成功但首刷失败时仍保留已连接状态，展示缓存或空态、完整首刷错误和重试入口，不回退到连接设置，也不误报 Token 无效。
- [ ] 连接验证失败时显示请求地址、HTTP 状态和服务返回的完整错误。
- [ ] 主实例 Token 及其他可独立授权请求的 bearer token 在需要持久化时只保存在系统安全存储中，界面默认隐藏。
- [ ] 客户端只保存一个后端地址和对应 Token，可编辑或清除当前连接。
- [ ] 在真机上验证首次连接、Token 错误、服务不可达和重新连接流程。

### US-002：浏览工作空间与 Job

**用户故事：** 作为用户，我希望按工作空间查看最近的 Job，以便快速回到正在进行或刚完成的任务。

**当前实现状态：** 已有码。已实现工作空间筛选、Job 分页、状态摘要、详情、置顶、重命名、删除和停止；是否满足不同尺寸 iPhone 适配仍待验证。

**验收标准：**

- [ ] 支持“全部工作空间”和单个工作空间筛选。
- [ ] Job 列表按最近更新时间展示，并支持继续加载。
- [ ] 快速切换工作空间时，列表、分页游标、加载态、错误和缓存只接受当前筛选条件的请求结果；已取消或已过期请求即使稍后返回也不得污染当前页面。
- [ ] 每项至少显示标题、工作空间、执行来源、更新时间、运行模式和状态。普通 Job 优先显示创建时持久化的初始 Agent，没有 Agent 时显示初始模型，因此尚无 session 的空 Job 也能正确归因；Graph Job 显示 Graph 运行类型，定时触发 Job 显示定时任务来源。不得用工作空间当前默认值猜测历史 Job，来源无法确认时明确显示未知。
- [ ] 可区分交互式 Job、Graph Job 和定时任务触发的 Job。
- [ ] 支持置顶、重命名和删除；删除前必须确认并说明将清理的运行与会话数据。
- [ ] 删除 Graph Job 时，先使仍可能继续执行的 Graph run 停止并完成状态收口，再级联删除 run 事件/输出、节点会话与 Job；仅在全部清理完成后报告成功。
- [ ] Graph Job 删除失败时展示完整错误并允许安全重试，不得报告成功或留下仍可访问的孤立 run、节点会话；删除成功后 Job、run 和相关会话均不可再打开。
- [ ] 列表刷新失败时保留最近一次成功内容，并显示完整错误。
- [ ] 在不同尺寸 iPhone 上验证筛选、分页和状态展示。

### US-003：新建 Agent 对话

**用户故事：** 作为用户，我希望从手机选择工作空间和 Agent 发起任务，以便不在电脑前也能启动工作。

**当前实现状态：** 已有码。已实现工作空间、Agent、模型、模式、思考等级选择、服务端共享默认 Agent/模型，以及照片库、相机、系统图片文件三种图片来源；创建或首条消息发送失败时保留输入和附件。仍需在 macOS/Xcode 和真机上验证。

**验收标准：**

- [ ] 用户可选择工作空间、可用 Agent、模型、模式和思考等级。
- [ ] Agent 列表加载中或 Agent 处于 `pending_validation`、`validating` 时展示明确的等待状态并继续刷新；不得将其折算为“没有可用 Agent”，也不得在确认可用前创建 Job。
- [ ] Agent 列表请求或验证失败时保留工作空间、选择项、草稿和附件，显示完整错误并提供显式重试。
- [ ] 创建 Job 时保存初始 Agent、模型、模式和思考等级作为该 Job 的历史归因；后续修改工作空间默认值不得改写这些信息。
- [ ] 默认 Agent 和模型读取工作空间的服务端共享偏好；iOS 与 Web 修改后，另一端刷新即可看到一致结果。
- [ ] 用户可在 iOS 修改当前工作空间的默认 Agent 和模型，修改后不影响已创建 Job 的运行配置。
- [ ] Agent 删除成功后，所有引用该 Agent 的工作空间同时清空默认 Agent 及其配套默认模型；既有 Job 的历史归因不变。恢复同一 Agent 时不自动恢复已清空的工作空间默认值，需由用户重新选择。
- [ ] 支持输入文本，并从相册、相机或系统文件选择器添加图片。
- [ ] 创建 Job 或发送首条消息失败时保留草稿和附件，并显示完整错误。
- [ ] Agent 不可用时明确说明原因，不允许进入无法执行的假成功状态。
- [ ] 在真机上验证纯文本、图片和中英文输入法发送。

### US-004：查看并继续实时对话

**用户故事：** 作为用户，我希望实时查看 Agent 的回复和工具执行过程，并能继续追问。

**当前实现状态：** 已有码。已实现历史消息、SSE 流式消息、Markdown、安全链接、代码块复制、思考内容、工具调用、完整错误，以及运行中的页面内存队列、取消待发送、失败恢复和重试。队列不跨页面或进程持久化。

**验收标准：**

- [ ] 支持历史消息、流式增量消息、Markdown、代码块、图片、思考内容、工具调用和工具结果。
- [ ] 普通非 Loop Job 存在多个 session 时，首次打开、重连校准和全量恢复均按服务端顺序合并全部 session 的历史；切换 Agent 形成的新旧会话都不得丢失，重复消息不得重复展示。
- [ ] 历史消息保留所属 session 及 Agent/模型归因；继续发送默认使用当前有效 session，不以工作空间当前默认值改写既有会话。
- [ ] 长消息可复制，代码块可单独复制；链接交由系统安全打开。
- [ ] 普通交互式 Job 运行时可继续输入并排队发送，用户可取消尚未执行的排队消息。
- [ ] 每条待发送消息在首次请求前生成稳定的 `clientMessageId`；超时、断线和结果未知后的重试必须复用该标识，不能因重试生成新标识。
- [ ] 服务端按 Job 与 `clientMessageId` 对发送请求做幂等处理：相同标识和相同内容只执行并持久化一次，并返回原结果；相同标识对应不同内容时明确拒绝并显示冲突。
- [ ] 本地待发送消息、SSE 事件和历史记录使用同一 `clientMessageId` 收敛为一条消息；重复响应或恢复不得触发第二次执行。
- [ ] 用户可停止当前生成；停止动作需要清楚标识作用对象。
- [ ] 网络中断时编辑区仍可输入，未发送草稿不会丢失。
- [ ] 重连后客户端先获取最新快照，再续接事件；同一消息不得重复显示。
- [ ] 对话页连接徽标区分“连接中”“实时已连接”“重连中”和“已断开/已结束”；只有 SSE 实际建立且尚未断开时才能显示实时已连接，不得根据后端总体可达或“未在重连”推断为在线。
- [ ] 服务端返回的错误信息可完整展开和复制。
- [ ] 在真机上验证后台切换、锁屏后返回、网络切换和长对话滚动。

### US-005：监控和控制 Graph run

**用户故事：** 作为用户，我希望在手机上判断工作流走到哪一步，并在需要时停止、恢复或完成人工讨论。

**当前实现状态：** 已有码。已实现 run 详情、活跃态 2 秒/等待态 4 秒轮询、节点阶段列表、Prompt/Clarify 节点对话、Shell 节点输出，以及停止、步骤后停止、取消停止、恢复和讨论完成动作。当前不使用 Graph SSE，仍需真机和 Web/iOS 并发验证。

**验收标准：**

- [ ] 显示 run 总体状态、当前节点、完成/失败节点数、开始时间、持续时长和完整错误。
- [ ] 节点按适合竖屏的阶段列表展示，支持进入 Prompt 或 Shell 节点的会话/输出。
- [ ] 可执行“停止”“当前步骤后停止”“取消停止”“恢复”和“讨论完成”，仅在对应状态下展示可用动作。
- [ ] 高风险动作要求确认，并显示将影响的 run 和当前节点。
- [ ] 等待人工、已停止、失败、已完成状态在列表和详情页上可一眼区分。
- [ ] 同一个 run 在 Web 与 iOS 同时打开时，两端最终状态一致。
- [ ] 在真机上验证运行中、等待人工、恢复、失败和完成流程。

### US-006：接收应用内运行提醒

**用户故事：** 作为用户，我希望客户端观测到 Job 关键状态变化时及时提醒我，并在重新打开应用后看到最新状态。

**当前实现状态：** 已有码，待验证。已实现四类通知偏好、应用内通知记录、本地通知授权与投递、记录持久化和按运行事件去重；点击普通通知进入 Job，Graph 等待人工通知进入对应节点会话。事件来自普通对话终态事件、Job 列表和 Graph run 状态刷新；系统挂起或终止期间不保证实时。

**验收标准：**

- [ ] 用户可分别开关完成、失败、等待人工和连接异常通知。
- [ ] 应用在前台或仍获准后台运行并观测到事件时，可生成系统本地通知；通知至少包含 Job 标题、工作空间、状态和发生时间。
- [ ] 运行状态观察覆盖全部工作空间和全量分页，不受当前工作空间筛选或 Job 列表当前页限制；任一页的 Job 状态变化都能进入相同的去重与通知流程。
- [ ] 应用保持前台且后端可达时，从状态变化发生到写入应用内通知的目标延迟不超过 5 秒。
- [ ] 点击通知可直接进入对应 Job；Graph 等待人工通知进入对应节点会话。
- [ ] 同一状态变化不得重复通知。
- [ ] 普通 Job 或 Graph run 进入 `timedOut` 时按失败事件通知，并在状态或正文中明确标识“超时”，不得静默丢弃或归为主动停止。
- [ ] 未授权系统通知时，应用内通知中心仍保留客户端已经观测到的事件。
- [ ] 通知正文不得包含 Token、密钥或完整敏感输出。
- [ ] 应用从后台或终止状态重新打开时，使用现有状态接口同步最新 Job 状态，并明确标识当前数据是否过期；若产品要求逐条补发离线期间的历史事件，需另行增加服务端事件游标或推送能力。
- [ ] 文案明确说明：不接入 APNs 或常驻通知中继时，应用被系统挂起或终止期间不保证实时通知。
- [ ] 在前台、短时后台、系统挂起和重新启动场景下完成真机验证。

### US-007：处理离线、后台和错误

**用户故事：** 作为用户，我希望应用在移动网络不稳定和系统挂起后能可靠恢复，不让我误判任务状态。

**当前实现状态：** 部分实现。当前代码保存工作空间和 Job 摘要缓存，显示连接状态、最近成功同步时间和过期/待同步提示；进入后台时停止 SSE，回前台后重读 Job 快照并重连事件流。尚未完成弱网、系统挂起、重启恢复与去重验收。

**验收标准：**

- [ ] 页面持续显示当前连接状态和最近一次成功同步时间。
- [ ] 进入后台前记录事件位置，回到前台后重新校准当前 Job 状态。
- [ ] 无法确认最新状态时明确显示“状态待同步”，不得继续展示过期的“运行中”。
- [ ] 网络请求提供可取消和可重试入口；重复点击不得重复创建 Job 或执行控制动作。
- [ ] 错误详情支持复制，并包含服务端返回的全部错误内容。
- [ ] 在飞行模式、Wi-Fi/蜂窝切换和服务端短暂重启场景完成真机验证。

## 12. 接口复用与必要调整

阶段 1 直接复用 Web 已使用的 HTTP API 和 SSE。除工作空间共享偏好外，不新增 iOS 专用业务接口：

1. **连接与鉴权**：复用健康检查和轻量 Token 验证接口，不通过 Agent 列表探测连接是否有效；验证结果与验证后的业务数据首刷结果分别处理。
2. **工作空间与 Job**：复用工作空间列表、Job 列表、详情、重命名、置顶、删除和运行控制接口；Job 摘要提供创建时保存的初始 Agent/模型归因，Graph Job 删除覆盖绑定 run 及其关联数据的完整生命周期。
3. **消息同步**：复用会话历史、Job 快照和现有 SSE 事件续接能力；普通 Job 恢复时读取全部 session，从后台返回时先拉取快照，再恢复事件流。
4. **Graph 与定时任务**：复用现有 Graph run、节点会话和 schedule 接口，不为移动端复制一套动作语义；`timedOut` 统一作为可展示、可通知的失败终态。
5. **文件与统计**：阶段 2/3 继续复用现有只读文件和统计接口。
6. **工作空间共享偏好**：将默认 Agent、默认模型从 Web 浏览器本地偏好迁移为服务端工作空间数据，并由 Web 和 iOS 共用；删除 Agent 时清除引用它的默认 Agent 和默认模型，恢复 Agent 不恢复旧默认值。
7. **消息幂等**：每次用户发送生成稳定的 `clientMessageId`，客户端重试沿用原标识，服务端持久化去重结果；请求响应、SSE 和历史记录均用该标识收敛同一条消息。
8. **其他动作防重复**：创建 Job 和运行控制期间锁定重复操作；网络结果未知时先读取服务端状态再决定是否重试。

通知不新增后端接口：iOS 根据普通对话终态事件、全局分页的 Job 列表和 Graph run 状态刷新在本地记录提醒，并在重新打开应用时同步最新状态。应用被系统挂起或终止后无法持续监听，这是阶段 1 已接受的产品边界。

## 13. 非功能要求

### 13.1 兼容性

- 阶段 1 以 iPhone 为主要设备，当前最低版本固定为 iOS 26.0，不兼容更早版本。
- 支持浅色、深色模式和动态字体。
- 关键操作在窄屏和横屏下均不得被键盘遮挡。

### 13.2 安全与隐私

- 主实例访问 Token、分享 Token、临时资源 Token 以及后续新增的任何 bearer token 均按敏感凭证处理；确需持久化时只能进入系统安全存储。
- 普通偏好、离线快照、业务模型缓存和通知记录不得保存 bearer token；除用户主动复制分享链接外，也不得写入日志、诊断导出、通知正文或剪贴板。
- bearer token 只在发起对应请求所需的最短时间内保留在内存；清除或更换连接时同步清除旧实例的安全存储项和含敏感字段的内存状态。
- 默认服务地址使用 HTTPS，并允许用户自行修改；若填写局域网 HTTP 地址，连接前需显式确认风险。
- 错误展示遵循“全量给用户看”，诊断日志导出前仍需自动排除 Token 等认证字段。
- 生物识别锁作为阶段 2 可选项，不阻断阶段 1。

### 13.3 性能与可靠性

- 冷启动后优先展示本地缓存的工作空间和 Job 摘要，再后台刷新。
- Job 列表采用分页；普通 Job 当前仍一次加载全部 session 历史，长对话增量加载与列表虚拟化保留为后续优化。
- 所有异步请求在结果落地前校验其工作空间、Job、session 或连接上下文仍然有效；上下文切换后丢弃旧请求的迟到结果。
- 应用进入后台后不假设长连接持续存活；回前台必须重新校准。
- 所有时间以服务端记录为准，并按设备时区显示。

### 13.4 可访问性

- 所有状态不能只靠颜色区分。
- 控件提供 VoiceOver 标签和足够的点击区域。
- 流式新增内容不应持续抢占 VoiceOver 焦点。

### 13.5 构建与验证边界

- Linux 环境只作为代码阅读、文档维护和静态工程检查环境；不能在此完成 Xcode 构建、签名、Simulator 或真机验证。
- iOS 工程的构建、安装、权限弹窗、照片访问、Keychain 行为、网络联通、后台恢复和系统通知结果，必须在 macOS + Xcode 环境重新验证。
- 文档中的“已有码”仅表示仓库中存在对应实现代码；只有经过 macOS 构建和真机或 Simulator 验证后，才能标记为“已验证”或“可发布”。

## 14. 成功指标

- 90% 以上的已配置用户能在 30 秒内完成“打开应用—选择工作空间—发送消息”。
- 常规网络下，从服务端产生消息到前台展示的延迟中位数不超过 2 秒。
- 前后台切换或短暂断网后，消息重复率和可观测消息丢失率均为 0。
- 客户端在前台、后端可达并已观测状态变化时，应用内提醒重复率低于 0.5%，目标延迟不超过 5 秒；监控覆盖全部工作空间和所有 Job 分页。
- 由应用内提醒或系统本地通知进入正确 Job 或 Graph 节点会话的成功率达到 99%。
- 阶段 1 中所有服务端错误都可在客户端查看完整内容，不出现只有“未知错误”的失败页。

## 15. 发布门槛

### 阶段 1 发布门槛

完成单实例连接、工作空间/Job 列表、新建与继续对话、图片、流式消息、停止、Graph 监控与控制、应用内提醒的范围闭环。使用个人内部分发渠道验证真实后端、局域网、弱网与长任务；在完成 macOS 构建和真机验证前不得宣称阶段 1 已发布。

### 阶段 2 发布门槛

补齐 Job 分享、工作流手动运行、定时任务轻控制、文件只读预览、步骤大纲和命令补全；不引入公网推送。

### 阶段 3 发布门槛

增加统计、配额、轻量定时任务创建、快捷指令、细粒度通知和 iPad 优化。是否继续扩展系统配置能力，应根据实际移动端使用数据决定。

每个阶段发布前必须完成：

- 与当前 Web 同时操作同一 Job 的一致性验证。
- 真机前台、短时后台、锁屏、系统挂起和重新启动后的状态同步验证。
- 服务不可达、Token 错误、SSE 中断、后端重启和 Agent 不可用验证。
- 动态字体、VoiceOver、深色模式和不同尺寸 iPhone 验证。

## 16. 已确认决策

1. 客户端仅用于个人内部分发，不上架 App Store。
2. 最低系统版本采用开始开发时 Apple 最新正式发布的大版本，当前固定为 iOS 26.0。
3. 客户端仅要求在与 Quartet 后端相通的局域网内使用，不建设公网访问或远程通知中继。
4. 优先使用 HTTPS，默认服务地址为 `https://devbox.fanlv.fun/`；允许用户修改地址。
5. 只配置一个 Quartet 后端实例，产品行为与当前 Web 保持一致。
6. 工作空间默认 Agent 和模型改为服务端共享偏好，由 Web 与 iOS 共用。
7. iOS 优先复用现有接口；除手机特有能力或跨端一致性所需的通用调整外，不新增接口。
