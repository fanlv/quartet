# Quartet iOS 客户端功能方案

## 1. 概述

Quartet 当前 Web 端已覆盖工作空间、Job、Agent 对话、Graph 工作流、定时任务、文件查看、统计与系统配置。iOS 客户端不应复刻整套桌面管理界面，而应定位为“局域网内的随身操作与运行监控端”：用户离开电脑但仍处于同一局域网时，可发起或继续 Agent 对话、查看运行进度、处理需要人工介入的工作流，并在客户端观测到关键状态变化时收到提醒。

客户端连接用户自己运行的 Quartet 后端，仅用于个人内部分发，不上架 App Store。首版与 Web 一样只连接一个可配置的后端实例，默认地址为 `https://devbox.fanlv.fun/`；不在 iPhone 本地运行 Agent，也不在本地直接访问后端机器的文件系统。

## 2. 目标

- 覆盖移动场景中最高频的闭环：连接后端、选择工作空间、发消息、看流式结果、停止任务、继续历史对话。
- 让用户能够在手机上快速判断 Job 或 Graph run 是否仍在运行、已经完成或为何失败。
- 支持 Graph 工作流的移动端监控与轻控制，但把复杂编排留在 Web。
- 在应用能够观测运行状态时，通过应用内提醒和系统本地通知减少用户持续盯着页面的需要。
- 与 Web 共享服务端数据和运行状态，用户可在两端无缝接续同一个 Job。
- 优先复用现有 HTTP API 与 SSE，不为 iOS 复制业务接口；只有明确属于手机端的能力才考虑新增接口。

## 3. 产品原则

1. **移动优先，而非页面搬运**：围绕单手查看、短输入、快速确认与及时通知设计。
2. **服务端为唯一事实来源**：Job、消息、工作流和文件均以 Quartet 后端状态为准，不做两套业务数据。
3. **执行与展示分离**：Agent 和工作流继续在 Quartet 所在电脑或沙箱运行，iOS 只负责控制和展示。
4. **完整呈现错误**：连接、请求、Agent、工具调用与工作流错误不得只显示笼统提示；主界面可摘要，但必须能展开查看完整信息。
5. **高风险操作显式确认**：停止、删除、恢复执行等动作展示影响范围并要求确认。
6. **弱网可恢复**：短暂断网不丢输入；恢复连接后主动校准 Job 快照和后续事件，避免重复或遗漏消息。

## 5. 信息架构

首次启动进入“连接设置”；连接成功后使用四个一级入口：

- **对话**：最近 Job、新建对话、工作空间筛选、运行状态。
- **工作流**：Graph run 监控；P1 增加工作流模板和定时任务。
- **通知**：保存客户端已观测到的完成、失败、等待人工、断线等事件；进入对应 Job 或节点会话。
- **设置**：后端连接、Token、通知偏好、显示偏好、诊断信息和退出连接。

工作空间作为全局筛选条件，不单独占用底部入口。用户可在对话首页或导航栏快速切换，也可选择“全部工作空间”。

## 6. MVP 功能范围

### US-001：连接 Quartet 后端

**用户故事：** 作为用户，我希望保存 Quartet 服务地址和访问 Token，以便安全地从手机访问自己的实例。

**验收标准：**

- [ ] 服务地址默认填入 `https://devbox.fanlv.fun/`，用户可修改并发起连接测试。
- [ ] 客户端先读取服务健康状态，再在需要鉴权时验证 Token。
- [ ] 连接失败时显示请求地址、HTTP 状态和服务返回的完整错误。
- [ ] Token 保存在系统安全存储中，界面默认隐藏。
- [ ] 客户端只保存一个后端地址和对应 Token，可编辑或清除当前连接。
- [ ] 在真机上验证首次连接、Token 错误、服务不可达和重新连接流程。

### US-002：浏览工作空间与 Job

**用户故事：** 作为用户，我希望按工作空间查看最近的 Job，以便快速回到正在进行或刚完成的任务。

**验收标准：**

- [ ] 支持“全部工作空间”和单个工作空间筛选。
- [ ] Job 列表按最近更新时间展示，并支持继续加载。
- [ ] 每项至少显示标题、工作空间、Agent 或模型、更新时间、运行模式和状态。
- [ ] 可区分交互式 Job、Graph Job 和定时任务触发的 Job。
- [ ] 支持置顶、重命名和删除；删除前必须确认。
- [ ] 列表刷新失败时保留最近一次成功内容，并显示完整错误。
- [ ] 在不同尺寸 iPhone 上验证筛选、分页和状态展示。

### US-003：新建 Agent 对话

**用户故事：** 作为用户，我希望从手机选择工作空间和 Agent 发起任务，以便不在电脑前也能启动工作。

**验收标准：**

- [ ] 用户可选择工作空间、可用 Agent、模型、模式和思考等级。
- [ ] 默认 Agent 和模型读取工作空间的服务端共享偏好；iOS 与 Web 修改后，另一端刷新即可看到一致结果。
- [ ] 支持输入文本，并从相册、相机或系统文件选择器添加图片。
- [ ] 创建 Job 或发送首条消息失败时保留草稿和附件，并显示完整错误。
- [ ] Agent 不可用时明确说明原因，不允许进入无法执行的假成功状态。
- [ ] 在真机上验证纯文本、图片和中英文输入法发送。

### US-004：查看并继续实时对话

**用户故事：** 作为用户，我希望实时查看 Agent 的回复和工具执行过程，并能继续追问。

**验收标准：**

- [ ] 支持历史消息、流式增量消息、Markdown、代码块、图片、思考内容、工具调用和工具结果。
- [ ] 长消息可复制，代码块可单独复制；链接交由系统安全打开。
- [ ] 普通交互式 Job 运行时可继续输入并排队发送，用户可取消尚未执行的排队消息。
- [ ] 用户可停止当前生成；停止动作需要清楚标识作用对象。
- [ ] 网络中断时编辑区仍可输入，未发送草稿不会丢失。
- [ ] 重连后客户端先获取最新快照，再续接事件；同一消息不得重复显示。
- [ ] 服务端返回的错误信息可完整展开和复制。
- [ ] 在真机上验证后台切换、锁屏后返回、网络切换和长对话滚动。

### US-005：监控和控制 Graph run

**用户故事：** 作为用户，我希望在手机上判断工作流走到哪一步，并在需要时停止、恢复或完成人工讨论。

**验收标准：**

- [ ] 显示 run 总体状态、当前节点、完成/失败节点数、开始时间、持续时长和完整错误。
- [ ] 节点按适合竖屏的阶段列表展示，支持进入 Prompt 或 Shell 节点的会话/输出。
- [ ] 可执行“停止”“当前步骤后停止”“取消停止”“恢复”和“讨论完成”，仅在对应状态下展示可用动作。
- [ ] 高风险动作要求确认，并显示将影响的 run 和当前节点。
- [ ] 等待人工、已停止、失败、已完成状态在列表和详情页上可一眼区分。
- [ ] 同一个 run 在 Web 与 iOS 同时打开时，两端最终状态一致。
- [ ] 在真机上验证运行中、等待人工、恢复、失败和完成流程。

### US-006：接收应用内运行提醒

**用户故事：** 作为用户，我希望客户端观测到 Job 关键状态变化时及时提醒我，并在重新打开应用后看到最新状态。

**验收标准：**

- [ ] 用户可分别开关完成、失败、等待人工和连接异常通知。
- [ ] 应用在前台或仍获准后台运行并观测到事件时，可生成系统本地通知；通知至少包含 Job 标题、工作空间、状态和发生时间。
- [ ] 点击通知可直接进入对应 Job；Graph 等待人工通知进入对应节点会话。
- [ ] 同一状态变化不得重复通知。
- [ ] 未授权系统通知时，应用内通知中心仍保留客户端已经观测到的事件。
- [ ] 通知正文不得包含 Token、密钥或完整敏感输出。
- [ ] 应用从后台或终止状态重新打开时，使用现有状态接口补齐最新 Job 状态，并明确标识离线期间发生的变化。
- [ ] 文案明确说明：不接入 APNs 或常驻通知中继时，应用被系统挂起或终止期间不保证实时通知。
- [ ] 在前台、短时后台、系统挂起和重新启动场景下完成真机验证。

### US-007：处理离线、后台和错误

**用户故事：** 作为用户，我希望应用在移动网络不稳定和系统挂起后能可靠恢复，不让我误判任务状态。

**验收标准：**

- [ ] 页面持续显示当前连接状态和最近一次成功同步时间。
- [ ] 进入后台前记录事件位置，回到前台后重新校准当前 Job 状态。
- [ ] 无法确认最新状态时明确显示“状态待同步”，不得继续展示过期的“运行中”。
- [ ] 网络请求提供可取消和可重试入口；重复点击不得重复创建 Job 或执行控制动作。
- [ ] 错误详情支持复制，并包含服务端返回的全部错误内容。
- [ ] 在飞行模式、Wi-Fi/蜂窝切换和服务端短暂重启场景完成真机验证。

## 7. P1：完整随身操作端

### 7.1 Job 分享

- 创建只读分享、复制系统分享链接、停止分享。
- Universal Link 可打开公开 Job；无权访问时提示原因，不自动要求主实例 Token。
- 分享页只暴露服务端公开接口允许的数据和动作。

### 7.2 工作流模板与定时任务

- 浏览已有 Graph 工作流，查看名称、所属工作空间、节点摘要和最近运行。
- 从已保存模板手动发起 run，可选择允许覆盖的工作空间或工作目录。
- 查看定时任务的启用状态、计划、上次结果和下次运行时间。
- 支持启停与立即运行；创建、删除或改 cron 留到 P2。

### 7.3 文件只读浏览

- 从 Job 或工作空间进入目录树。
- 预览文本、代码和图片，显示路径、大小与修改时间。
- 支持复制相对路径、复制文本内容、调用系统分享或导出。
- 不提供文件保存、目录创建和任意路径浏览。

### 7.4 长对话效率

- 提供步骤大纲和跳转。
- 支持系统搜索定位消息内容。
- 提供 Slash 命令与已安装 Skill 的搜索补全。
- 支持创建、复制和停止 Job 分享。

## 8. P2：运营与个性化

- 提供今日、近 7 日、近 30 日的时长、轮次、Token 估算和工具调用摘要。
- 展示 Agent 配额、重置时间和用量预警。
- 支持基于已有工作流创建轻量定时任务，优先提供常用时间预设。
- 允许查看 AGENTS.md，但编辑仍跳转或提示使用 Web。
- 支持应用图标角标、通知免打扰时间和按工作空间设置应用内提醒。
- 支持 Siri/快捷指令发起预设对话或运行已有工作流。

## 9. 明确不做

- 不在 iPhone 或 iPad 本地安装、升级或运行 ACP Agent。
- 不提供 Graph 画布的创建、拖拽、连线、嵌套和脚本编辑。
- 不管理后端机器上的工作空间目录、文件写入、目录创建或 AGENTS.md 编辑。
- 不迁移 Eino、ACP 环境变量、Prompt、Skill、Lark、微信、日志级别等系统配置页面。
- 不提供后端重启入口。
- 不承诺离线执行 Agent 或离线发送任务；离线仅保留草稿与最近一次成功读取的数据。
- 首版不支持多用户、团队空间或角色权限。
- 首版不支持保存和切换多个 Quartet 后端实例。
- 不建设公网推送或远程通知中继；应用被系统挂起或终止期间不承诺实时通知。
- 首版不以 iPad 桌面级编排为目标；iPad 先使用响应式 iOS 界面。

## 10. 接口复用与必要调整

首版直接复用 Web 已使用的 HTTP API 和 SSE。除工作空间共享偏好外，不新增 iOS 专用业务接口：

1. **连接与鉴权**：复用健康检查和轻量 Token 验证接口，不通过 Agent 列表探测连接是否有效。
2. **工作空间与 Job**：复用工作空间列表、Job 列表、详情、重命名、置顶、删除和运行控制接口。
3. **消息同步**：复用会话历史、Job 快照和现有 SSE 事件续接能力；从后台返回时先拉取快照，再恢复事件流。
4. **Graph 与定时任务**：复用现有 Graph run、节点会话和 schedule 接口，不为移动端复制一套动作语义。
5. **文件与统计**：P1/P2 继续复用现有只读文件和统计接口。
6. **工作空间共享偏好**：将默认 Agent、默认模型从 Web 浏览器本地偏好迁移为服务端工作空间数据，并由 Web 和 iOS 共用；优先扩展现有工作空间读写能力，而不是新增 iOS 专用接口。
7. **客户端防重复**：创建 Job、发送消息和运行控制期间锁定重复操作；网络结果未知时先读取现有状态再决定是否重试。若真实场景仍无法避免重复执行，再评估增加仅用于请求去重的通用能力。

通知不新增后端接口：iOS 根据现有 SSE 和状态查询在本地记录提醒。应用被系统挂起或终止后无法持续监听；用户重新打开应用时再同步状态。这是首版已接受的产品边界。

## 11. 非功能要求

### 11.1 兼容性

- 首版以 iPhone 为主要设备，以开始开发时 Apple 最新正式发布的 iOS 版本作为最低版本，不兼容更早版本。
- 支持浅色、深色模式和动态字体。
- 关键操作在窄屏和横屏下均不得被键盘遮挡。

### 11.2 安全与隐私

- Token 只进入系统安全存储，不写入普通偏好、日志、通知正文或剪贴板历史。
- 默认服务地址使用 HTTPS，并允许用户自行修改；若填写局域网 HTTP 地址，连接前需显式确认风险。
- 错误展示遵循“全量给用户看”，诊断日志导出前仍需自动排除 Token 等认证字段。
- 生物识别锁作为 P1 可选项，不阻断 MVP。

### 11.3 性能与可靠性

- 冷启动后优先展示本地缓存的工作空间和 Job 摘要，再后台刷新。
- 长对话采用增量加载和列表虚拟化，避免一次加载全部消息。
- 应用进入后台后不假设长连接持续存活；回前台必须重新校准。
- 所有时间以服务端记录为准，并按设备时区显示。

### 11.4 可访问性

- 所有状态不能只靠颜色区分。
- 控件提供 VoiceOver 标签和足够的点击区域。
- 流式新增内容不应持续抢占 VoiceOver 焦点。

## 12. 成功指标

- 90% 以上的已配置用户能在 30 秒内完成“打开应用—选择工作空间—发送消息”。
- 常规网络下，从服务端产生消息到前台展示的延迟中位数不超过 2 秒。
- 前后台切换或短暂断网后，消息重复率和可观测消息丢失率均为 0。
- 客户端在线并已观测到状态变化时，应用内提醒重复率低于 0.5%，95% 在事件发生后 5 秒内出现。
- 由应用内提醒或系统本地通知进入正确 Job 或 Graph 节点会话的成功率达到 99%。
- MVP 中所有服务端错误都可在客户端查看完整内容，不出现只有“未知错误”的失败页。

## 13. 发布阶段与门槛

### 阶段 A：内部 Alpha

完成单实例连接、工作空间/Job 列表、新建与继续对话、图片、流式消息、停止、Graph 监控与控制、应用内提醒。使用个人内部分发渠道验证真实后端、局域网、弱网与长任务。

### 阶段 B：完整 MVP

补齐 Job 分享、工作流手动运行、定时任务轻控制、文件只读预览、步骤大纲和命令补全；不引入公网推送。

### 阶段 C：增强版本

增加统计、配额、轻量定时任务创建、快捷指令、细粒度通知和 iPad 优化。是否继续扩展系统配置能力，应根据实际移动端使用数据决定。

每个阶段发布前必须完成：

- 与当前 Web 同时操作同一 Job 的一致性验证。
- 真机前台、短时后台、锁屏、系统挂起和重新启动后的状态同步验证。
- 服务不可达、Token 错误、SSE 中断、后端重启和 Agent 不可用验证。
- 动态字体、VoiceOver、深色模式和不同尺寸 iPhone 验证。

## 14. 已确认决策

1. 客户端仅用于个人内部分发，不上架 App Store。
2. 最低系统版本采用开始开发时 Apple 最新正式发布的 iOS 版本。
3. 客户端仅要求在与 Quartet 后端相通的局域网内使用，不建设公网访问或远程通知中继。
4. 优先使用 HTTPS，默认服务地址为 `https://devbox.fanlv.fun/`；允许用户修改地址。
5. 只配置一个 Quartet 后端实例，产品行为与当前 Web 保持一致。
6. 工作空间默认 Agent 和模型改为服务端共享偏好，由 Web 与 iOS 共用。
7. iOS 优先复用现有接口；除手机特有能力或跨端一致性所需的通用调整外，不新增接口。
