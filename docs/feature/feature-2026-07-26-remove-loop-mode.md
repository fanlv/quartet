# PRD: Loop 任务模式整体下线

## 1. Introduction/Overview

Loop 是 graph 工作流上线前的循环执行任务形态：用户通过 LoopConfig 编辑器编排一棵 prompt/shell/evaluator 步骤树，后端按树循环执行并逐轮产出会话。graph 工作流上线后，Loop 的全部能力（循环、条件、shell 步骤、变量注入、定时调度）已被 graph 覆盖，Loop 的创建与执行链路成为无人使用的遗留代码，且与普通对话、graph 任务共享大量运行时设施，维护成本高。

本需求：将 Loop 的**创建、配置、执行、编辑**能力整体下线；历史 Loop 任务降级为**只读归档**——列表、详情、消息回放、轮次与进度展示保持可用，但不可再启动、继续、编辑或优雅停止。

## 2. Goals

- 删除 Loop 的创建入口、配置编辑器、执行引擎、模板库及 Loop 专属 HTTP 接口。
- 历史 Loop 任务的列表、详情、消息回放、轮次侧栏、进度展示 100% 可用（只读）。
- graph 工作流（含 graph 自有的 loop 容器节点）与普通对话功能零回归。
- 共享运行时设施（事件桥、停止、状态流转等）仅摘除 Loop 专属分支，主体保留。

## 3. User Stories

### US-001: 后端 Loop 专属接口与模板库下线

**Description:** 作为维护者，我希望 Loop 专属 HTTP 接口与模板库整组下线，使外部无法再创建、启动、继续或修改 Loop 任务。

**Acceptance Criteria:**
- [ ] 更新 Loop 配置、启动 Loop、继续 Loop 三个动作接口及其 handler 删除，请求返回 404
- [ ] 模板增删改查整组接口、模板服务、模板存储层删除（模板只服务 Loop 编辑器）
- [ ] 创建任务接口移除 `mode=loop` 分支；LoopConfig 入参字段删除（老客户端多传该字段被 JSON 静默忽略，无报错）
- [ ] 停止接口保留，仅移除优雅停止/取消优雅停止分支；graph 与对话模式的普通停止不受影响
- [ ] `make build-all` 与 `go test ./...` 通过

### US-002: 后端 Loop 执行引擎删除与共享代码摘分支

**Description:** 作为维护者，我希望删除 Loop 执行引擎并摘除共享代码中的 Loop 分支，同时完整保留 graph 桥接与历史数据兼容层。

**Acceptance Criteria:**
- [ ] Loop 循环主流程、flow 树遍历、运行中改配置、evaluator 停止判定、空步骤跳过、内置变量注入、Loop 专属 shell 执行链全部删除
- [ ] Loop 专属事件类型（迭代开始/完成/失败）、内置变量常量、Loop 专属错误与接口方法删除
- [ ] 共享的执行、停止、状态流转、重试、运行资源管理代码中仅摘除 Loop 分支，对话与 graph 路径行为不变
- [ ] 名为 loop 的事件处理器（实为全模式共用的 agent 事件转 SSE 桥）保留主体，仅移除 Loop 专属字段；本次不重命名
- [ ] graph 运行状态写入、失败落盘（复用任务进度 LastError）、会话关联等 graph 桥接口保留且行为不变
- [ ] 任务结构体上的 LoopConfig/进度/续跑游标字段及 Loop 类型定义全部保留（历史数据反序列化依赖）
- [ ] 历史消息正文的 `{{变量}}` 按 Loop 变量替换的只读渲染保留；"改标题同步回写 Loop 变量"的写路径删除
- [ ] `make build-all` 与 `go test ./...` 通过

### US-003: 前端 Loop 创建入口与编辑器删除

**Description:** 作为用户，我在界面上不再看到任何创建或编辑 Loop 任务的入口。

**Acceptance Criteria:**
- [ ] 聊天首页"Loop 任务"按钮、确认流程、Loop 面板挂载、任务列表 Loop 图标分支全部移除
- [ ] LoopConfig 编辑器面板整组组件与样式、只被它引用的 shell 编辑器删除
- [ ] 应用根组件创建 Loop 任务并跳转的流程、Loop 初始配置状态及透传全部移除
- [ ] 新建对话命令改为从任务的其他字段继承 agent（原从 Loop 配置读取）
- [ ] 会话钩子中 Loop 启动/继续/停止/取消停止/改配置动作函数、优雅停止事件处理删除
- [ ] 普通对话创建任务请求体中携带的 LoopConfig（多处调用点）一并清理
- [ ] 前端不再调用任何已下线的 Loop 接口
- [ ] TypeScript 检查、`npm run build`、`npm test` 通过
- [ ] 在浏览器中验证（dev-browser skill）：首页与会话页无 Loop 入口残留

### US-004: 历史 Loop 任务只读归档展示

**Description:** 作为用户，我可以正常打开历史 Loop 任务查看消息与进度，但无法对其执行任何动作。

**Acceptance Criteria:**
- [ ] 历史 Loop 任务（含新格式与 legacy 格式样本）在任务列表正常显示、详情页可打开
- [ ] 会话消息回放完整，消息中的变量占位符正确渲染
- [ ] 轮次侧栏正常展示；Loop 进度组件保留展示但无停止/继续/编辑按钮
- [ ] legacy 格式任务进度降级为纯计数展示，轮次侧栏与消息回放不受影响
- [ ] 会话钩子中 `mode === 'loop'` 的读取与恢复分支（进度重建、轮次会话重建）保留
- [ ] 会话侧栏组件与 loop 前缀布局样式保留（graph 复用），graph 任务页布局无破坏
- [ ] 在浏览器中验证（dev-browser skill）：打开历史 Loop 任务确认只读展示，页面上无任何动作入口

### US-005: 清理 i18n、测试与死代码

**Description:** 作为维护者，我希望 Loop 专属的文案、测试与死代码随功能一并清除。

**Acceptance Criteria:**
- [ ] i18n 顶层 loop 命名空间删除；graph 命名空间下的 loop 词条保留
- [ ] Loop 进度组件单元测试、消息合并中 Loop 用户消息去重的死代码、端到端测试的 Loop 用例清理
- [ ] 前端任务类型定义中 Loop 专属类型（LoopConfig、FlowNode、LoopTemplate 等）移除；任务模式字段保留（graph 也用）
- [ ] 后端 Loop 专属单元测试删除，共享测试中的 Loop 用例改写
- [ ] TypeScript 检查、`npm test`、`go test ./...` 通过

### US-006: 回归验证

**Description:** 作为维护者，我希望确认删除后 graph 工作流与普通对话功能零回归。

**Acceptance Criteria:**
- [ ] 创建一个 graph 工作流任务完整跑通：画布、graph loop 节点、事件流、会话侧栏正常
- [ ] 定时调度触发 graph 任务正常
- [ ] 普通对话的创建、发消息、停止正常
- [ ] 公开分享页正常打开
- [ ] 在浏览器中验证（dev-browser skill）：graph 任务全流程无异常

## 4. Functional Requirements

- FR-1: 系统不得再提供创建 Loop 任务的任何入口（前端按钮、创建接口的 loop 分支均移除）。
- FR-2: 系统不得再提供 Loop 的启动、继续、运行中改配置、优雅停止能力；对应接口下线返回 404。
- FR-3: 历史 Loop 任务在任务列表中正常显示，详情页可打开，会话消息完整回放。
- FR-4: 历史 Loop 任务详情页不展示任何动作按钮（启动/继续/编辑/优雅停止），仅保留只读的进度与轮次信息。
- FR-5: 历史 Loop 消息正文中的 `{{变量}}` 占位符在服务端出消息时按任务中保存的 Loop 变量替换渲染。
- FR-6: legacy 格式（无 flow 树、仅有迭代次数与轮次）的历史 Loop 任务可打开，进度降级为纯计数展示。
- FR-7: graph 工作流的全部功能（画布编辑、graph loop 容器节点、运行、事件流、会话侧栏、定时调度）不受影响。
- FR-8: 普通对话任务的创建、发消息、排队、停止行为不受影响。
- FR-9: 任务停止接口对 graph 与对话模式保持可用，仅 Loop 的优雅停止语义移除。
- FR-10: 后端启动加载历史任务后的回写不得丢失任务元数据中的 Loop 字段（保留字段定义即满足，禁止清洗式改写）。

## 5. Non-Goals (Out of Scope)

- 不做历史 Loop 数据的迁移或转换（不改写磁盘上的任务元数据，字段原样保留）。
- 不删除任务结构体上的 Loop 字段与 Loop 类型定义（历史数据反序列化兼容层保留）。
- 不重命名共享设施中以 loop 命名的状态、函数、样式类（被 graph 复用；命名重构留待后续单独进行）。
- 不改动 graph 自有的 loop 容器节点及其前后端实现（与老 Loop 同名不同物）。
- 不为历史 Loop 任务提供 flow 配置的可视化查看（原始 JSON 仍在任务元数据中，进度与轮次展示已足够）。
- 不改动 eino-cli、IM 接入、沙箱等与 Loop 无关的模块。

## 6. Design Considerations

- 历史 Loop 任务详情页的视觉形态：沿用现有布局，仅移除动作按钮，进度信息降级为纯展示。
- 会话侧栏与 loop 前缀样式被 graph 复用，删除 Loop 专属样式时须逐条确认引用方，避免破坏 graph 页布局。

## 7. Technical Considerations

- **同名撞车是最大风险**：前后端各有一套 graph 自己的 loop 概念（容器节点、进度组件、i18n 词条、事件类型），与老 Loop 零共享代码。删除时每一处以"是否被 graph 引用"为准绳，禁止按关键字批量删除。
- **graph 复用任务进度字段**：graph 运行失败时把错误写进任务进度的 LastError，进度类型定义必须保留。
- **前后端删除顺序自由**：普通对话创建任务的请求体也携带 LoopConfig，后端 JSON 反序列化静默忽略未知字段，先删哪边都安全。
- **事件处理器名不副实**：名为 loop 的事件处理器实为所有模式共用的 agent 事件转 SSE 桥，只摘 Loop 字段、保留主体。
- **定时任务并发槽释放**回调中"Loop 完成才驱逐会话"的特判需收敛为通用逻辑，graph 终态也走该回调。

## 8. Success Metrics

- 代码库中不再存在任何 Loop 创建/执行入口；已下线的接口请求返回 404。
- 历史 Loop 任务（新格式与 legacy 格式各取样本验证）只读展示全部正常。
- graph 工作流与普通对话的端到端回归全部通过。
- `make build-all`、`go test ./...`、`npm run build`、`npm test` 全绿。
