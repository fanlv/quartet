# 技术方案：Graph 工作流结点 Hook

## 背景

Graph 工作流的每个结点目前只能产出变量、推进 DAG，结点执行完之后没有「触发一个外部副作用」的能力。但很多真实诉求是结点跑完后要做点事：发通知（飞书 / Webhook）、把结果落盘、给外部系统打个标记。最典型的是「整个工作流跑完了发个飞书告诉我」。现在只能在画布里手动加一个 Shell 结点来凑，既污染主流程拓扑，又拿不到「当前是哪个 Job」这类运行时上下文。

不解决的话，这类「收尾通知 / 副作用」要么做不了，要么得在每个工作流里手搓 Shell 结点重复一遍，且无法统一配置一个默认通知。

## 目标

给结点增加 Hook 能力：结点执行完成后，执行一段用户配置的 Shell 脚本作为**纯副作用**。脚本里能读到当前 `job_title` 等运行时上下文。其中「终点结点」要支持配置一个**全局默认 Hook**（统一通知脚本），也允许单个终点改用自定义脚本或关闭。

## 范围

**做**：

- 只给两类结点加 Hook：**Prompt 结点** 和 **终点（end）结点**。
- Prompt Hook：结点配置的脚本非空就执行，空则跳过。
- 终点 Hook：三态选择——「使用全局默认脚本 / 自定义脚本 / 关闭」，新建终点默认「使用全局默认脚本」。
- 全局默认终点脚本：存在全局设置里，设置页「通用」标签可编辑。
- 向 Hook 脚本注入运行时上下文环境变量（含 `job_title`）。

**不做**：

- 不给 Loop 结点加 Hook（已明确放弃）。
- Hook 不产出变量、不改结点状态、不参与 DAG 走向——纯副作用。
- 不引入新的输出协议（不解析脚本输出，不复用 Shell 结点的 `quartet_set` 等控制能力）。
- 不改变其他结点类型（Shell / If-Else / Loop / start / Clarify）的语义。

## 术语

- **结点 Hook**：结点执行完成后运行的一段副作用 Shell 脚本。
- **终点 Hook 模式**：终点结点的三态配置——默认（跑全局脚本）/ 自定义（跑本结点脚本）/ 关闭。
- **全局默认终点脚本**：保存在全局设置中的脚本，被设为「默认」模式的终点结点共用。

## 关键设计前提（与现有机制的关系）

1. 调度器是单 goroutine、单写者。Prompt 结点完成、终点结点裁决都发生在这个调度 goroutine 上。因此 Hook **不能同步执行**——否则一个挂死/慢脚本会卡住整个调度循环，连并行结点的推进、停止信号都被阻塞。Hook 必须异步执行。
2. Graph 模块与 Job 模块物理隔离，Graph 不能直接依赖 Job。`job_title` 通过 Graph→Job 的既有边界接口取得，不打破隔离。
3. 全局默认脚本属于「副作用配置」，不影响执行的确定性，因此**不冻结进 run 快照**——在 Hook 执行时实时读取当前设置即可（改了设置下一次 Hook 立即生效）。
4. 终点结点不像业务结点那样会记录实例，调度器的「已完成实例幂等」保护覆盖不到它。续跑会重新裁决已到达的终点，因此终点 Hook 必须额外防重复触发。

## 用户流程

1. **Prompt Hook**：在画布选中 Prompt 结点，配置面板填入「完成后 Hook」脚本（例如发通知）。运行工作流，该结点成功后脚本自动执行。
2. **终点 Hook（默认）**：在设置页「通用」配置一段全局默认脚本（例如「工作流跑完发飞书」）。画布上的终点结点默认就是「使用全局默认脚本」，无需逐个配置；运行到达终点即触发。
3. **终点 Hook（自定义 / 关闭）**：选中终点结点，把模式改为「自定义脚本」并填入专属脚本，或改为「关闭」不触发。
4. 脚本里通过环境变量读取上下文，例如 `《$QUARTET_JOB_TITLE》执行完成。`

## 方案设计

### 1. 数据模型

- 结点配置新增两个字段：Hook 脚本、终点 Hook 模式（默认 / 自定义 / 关闭）。
- 全局设置新增一个字段：全局默认终点 Hook 脚本。
- 这两个结点字段对「控制结点不可配置业务动作」的既有校验透明——校验是按已知业务字段逐项判断的，新增的 Hook 字段不在其列，因此终点结点合法携带 Hook 配置，无需放宽校验。

### 2. Hook 执行（纯副作用）

- Hook 把脚本写入临时文件用 Shell 执行，注入环境变量后运行，**忽略输出**。
- 不注入 Shell 结点那套控制文件 / 输出解析 / 内置辅助函数——Hook 不产出变量，保持语义干净。
- 自带超时（默认 60 秒），防止挂死脚本长期占用资源。
- 失败语义：非零退出、超时、拉起失败一律只记一条告警日志，**不改结点状态、不失败 run、不中断流程**。

### 3. 注入的环境变量

- 结点当前可见的全部变量（如 `$Code`、`$Doc` 及用户自定义变量），与 Shell 结点注入规则一致（被禁用的变量注入为空）。
- 运行时上下文（保留命名空间，用户变量无法覆盖）：
  - `QUARTET_JOB_TITLE`：当前 Job 标题（即用户诉求里的 `job_title`）。
  - `QUARTET_JOB_ID` / `QUARTET_RUN_ID` / `QUARTET_NODE_ID` / `QUARTET_NODE_TITLE` / `QUARTET_NODE_TYPE`。
  - `QUARTET_LAST_ASSISTANT`：结点输出 / 最近一条助手消息（Prompt 结点尤其有用）。

### 4. 触发点与时机

- **Prompt Hook**：结点被记录为成功并持久化之后触发。仅 Prompt 类型，脚本空则跳过。
- **终点 Hook**：仅对**主图终点**（非循环体内部的终点）生效；每个被走到的主图终点各触发一次。循环体内部的终点是「每轮边界」，不触发，以免变相复活已放弃的「循环每轮 Hook」。
- 触发前按终点模式解析出最终脚本：关闭→不跑；自定义→本结点脚本（空则不跑）；默认→全局脚本（空则不跑）。

### 5. 异步与生命周期

- Hook 在独立 goroutine 执行；启动前在调度 goroutine 上完成所有上下文快照（克隆可见变量、取好 Job 标题），使 Hook goroutine 不触碰任何调度器内部状态。
- Hook 使用脱离 run 取消的独立上下文（结点已成功，副作用不应被「停止 run」打断），只受自身超时约束。
- run 结束前统一等待在飞的 Hook 收尾，避免 Hook goroutine 泄漏。Hook 不写 run 状态，因此 run 可以先落到完成态再等待 Hook——等待只为不泄漏，不阻塞 run 状态推进。

### 6. 防重复触发（续跑安全）

- Prompt Hook：成功的 Prompt 会记录实例，续跑时被「已完成实例幂等」保护跳过，不会重复触发；中途失败被重置的 Prompt 整体重跑、Hook 仅在真正成功时触发一次。天然安全。
- 终点 Hook：终点不记录实例，幂等保护覆盖不到。调度器维护一个「已触发终点」内存集合，每个终点只触发一次；续跑重建前沿时，把「上一轮已到达的主图终点」预先标记为已触发，使续跑重新裁决这些终点时不会再发一次。

## 风险

- **Hook 慢/挂死**：靠异步执行 + 超时 + run 结束统一等待规避，既不阻塞调度也不泄漏 goroutine。
- **终点 Hook 续跑重复发**：靠「已触发终点」集合 + 续跑预标记规避（本方案的核心正确性点）。
- **改全局脚本影响进行中的 run**：实时读取设计下，编辑全局脚本会影响同一 run 后续终点 Hook。对「通知 / 副作用」场景可接受，且更符合「修好脚本后续跑应使用修好的版本」的预期。

## 可观测性

- Hook 完成记一条 info 日志（含 run / 结点标识）。
- Hook 失败（非零退出 / 超时 / 拉起失败）记一条 warn 日志，带 stdout / stderr 便于排查；不升级为错误、不影响 run。

## 执行步骤

1. 数据模型：结点配置加 Hook 脚本与终点模式字段；全局设置加默认终点脚本字段。
2. Hook 执行器：实现纯副作用脚本执行（临时文件 + 环境注入 + 超时 + 失败仅告警）。
3. 打通 `job_title`：经 Graph→Job 既有边界接口取 Job 标题，注入环境变量。
4. 注入全局默认脚本：把全局设置的脚本以实时读取方式提供给调度器。
5. 调度器接入：新增异步 Hook 触发与生命周期等待；在 Prompt 完成点、主图终点裁决点接入；终点加防重复集合与续跑预标记。
6. 前端：结点配置面板（Prompt 加脚本框、终点加三态选择 + 自定义脚本框）；设置页「通用」加全局默认脚本编辑器；补中英文案。

## 验收标准

功能列表：

- Prompt 结点 Hook：脚本非空执行、空跳过。【手工 + E2E】
- 终点 Hook 三态：默认跑全局脚本、自定义跑本结点脚本、关闭不跑。【手工 + E2E】
- 全局默认终点脚本：设置页可编辑并持久化。【手工】
- 环境变量注入：`QUARTET_JOB_TITLE` 等可在脚本中读取且值正确。【手工 + E2E】
- 主图终点每个各触发一次；循环体内部终点不触发。【手工】
- **续跑不重复触发终点 Hook**（核心正确性点）：跑到主图终点的工作流配置终点 Hook，stop 后 resume，终点 Hook 仅触发一次。【手工 + E2E】
- 失败隔离：脚本非零退出 / 超时时，结点仍成功、run 正常完成，仅有告警日志。【手工】

- 后端 `make build-all`、前端 `npm run build` 通过；现有 graph 用例（含 race 检测）不回归。
