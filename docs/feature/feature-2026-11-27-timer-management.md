# 定时器管理重设计方案

## 背景与目标

目前 Quartet 的定时任务按 Cron 运行已保存的图工作流。Web 在首页管理定时任务，iOS 有独立入口，两端都从定时任务直接打开最近一次 Job。[现有定时任务说明](../../README.zh-CN.md#定时任务) · [现有 Skill 说明](../../skill/schedule/SKILL.md)

重设计后，用户可以在 Web、iOS 或通过 `quartet-schedule` 配置同一个后端的定时器。每个定时器可以执行一段 Prompt 或一个图工作流，支持单次、重复和按日期结束。用户在独立的「定时任务管理」页面管理计划，查看每次执行的结果及其 Session。

## 功能要求

### FR-1 定时器的创建与管理

- Web 主导航提供「定时任务」入口，打开独立的管理页面，iOS 沿用现有定时任务入口。界面和 `quartet-schedule` 均可创建、查看、编辑、启用、停用、删除定时器、立即运行和查询执行记录。三种入口使用同一份配置和调度规则。
- 创建时填写名称、执行内容和时间计划。具备 FR-6 要求的启用权限时，默认在当前连接的后端启用，也可先保存为停用。只有配置权限时，两类定时器均可保存为停用。保存成功时展示定时器名称、标识、计划状态，以及可用时的下次自动触发时间。操作失败时展示完整错误。
- Skill 可将「明天上午 9 点，在项目工作区用 Codex 执行『总结本周变更』」创建为单次 Prompt 定时器，也可将「每天 18 点运行『日报』工作流，到 12 月 31 日为止」创建为带结束日期的重复定时器。时间或目标有歧义时，Skill 先确认具体值。
- 编辑影响后续触发。停用暂停自动调度，删除将计划移出定时器列表并结束后续调度。已经受理的任务按各自的运行规则继续，用户可从执行记录停止任务或查看历史。

### FR-2 执行内容

| 类型 | 配置 | 每次触发 |
| --- | --- | --- |
| Prompt | 输入提示词，可选 Agent、模型、工作区、工作目录和单次运行超时。Agent 和模型可使用工作区的默认值，缺少可用默认值时需选择。保存时回显实际选项。 | 创建独立 Job，在新会话中以提示词发起一轮执行，记录回复、工具调用和错误。 |
| 图工作流 | 选择已保存的工作流，可指定工作区和工作目录。 | 以当前已获授权的工作流版本启动独立的工作流 Job，使用该次运行的工作流版本查看历史。遇到澄清节点时，可从执行记录进入对应运行处理。 |

未指定工作区时使用后端默认工作区，未指定目录时使用所选工作区的目录。保存时解析、校验并回显实际采用的默认值，获授权后按这些值触发。采用新的默认值按 FR-6 的执行配置变更处理。每次触发再次核对执行依赖，已确认的工作区、目录、Agent、模型或工作流不可用时，该次执行记录完整的触发错误。

### FR-3 时间计划与结束规则

| 计划 | 配置与行为 |
| --- | --- |
| 单次 | 指定一个将来的日期和时间。一次触发受理后，计划进入「已结束」，该次执行继续展示实际进度和结果。单次计划在未受理触发时错过时间，包括停用期间跨过执行时间，可改到未来时间后重新启用。 |
| 重复 | 选择每小时、每天、每周或自定义五段 Cron。可持续执行，也可设置最大执行次数、结束日期或两者。先达到的条件结束计划。编辑规则时保留已用次数。 |

- 时间精度为分钟。定时器默认使用创建时的后端本地时区，也可指定时区。Skill 按定时器时区解释「明天」等相对日期，界面与 Skill 按该时区展示计划和下次触发时间。
- 结束日期包含该时区的当天。从次日零点起停止受理新的触发，截止前已受理的任务按自身的运行规则完成。启用前校验有效期内是否还有触发机会。
- 已启用或手动停用的定时器在仍有执行机会且满足 FR-6 权限要求时可「立即运行」。「待确认」期间暂停立即运行。「立即运行」占用一次执行机会，单次定时器因此提前结束，重复定时器按原规则继续计算下一次自动触发。
- 次数按受理的触发计算，受理后启动失败或执行失败也计一次。错过和因并发已满而跳过的时刻只记录原因。重复定时器可通过延长结束日期或提高次数上限后重新启用，仍以累计受理次数为准。

### FR-4 首页调整与独立管理页

Web 首页移除整个「Scheduled Tasks」区块，包括定时任务数量、列表、新增按钮、启停、删除和最近 Job 链接。首页同时移除「隐藏定时任务」开关，普通任务列表仅展示其他来源的 Job。

「定时任务管理」页默认打开「定时器」视图，以「新增定时器」为主操作。三个视图都可从管理页直接进入。

| 视图 | 展示与操作 |
| --- | --- |
| 定时器 | 列出名称、执行类型、计划、启停状态、「待确认」原因或结束原因、下次触发时间和最近结果。进入详情可查看定时器标识、创建与更新时间、Prompt 或工作流、Agent 和模型（适用时）、工作区和目录、时区、执行次数与结束条件、并发和超时配置。用户可编辑配置、启停、立即运行或删除，也可打开按当前定时器筛选的执行记录和 Sessions。 |
| 执行记录 | 汇总自动触发和立即运行的记录，可按定时器、工作区和执行状态筛选。列表按触发时间倒序分页，未触发的记录按计划时间排序。每条记录展示定时器、目标、工作区、触发方式、计划时间（适用时）、实际起止时间和状态，并可打开 Job 详情或该次执行的 Sessions。触发失败、并发跳过和错过的机会在详情展示完整错误或原因。 |
| Sessions | 按创建时间倒序分页，可按定时器或某次执行筛选。每条会话展示所属定时器、执行记录、Agent、模型和创建时间。工作流会话同时展示所属节点及可用的循环轮次。选中会话可打开完整对话和工具调用记录，并返回对应的执行记录。 |

- 会话视图覆盖进行中和已结束的执行。Prompt 的会话与图工作流各节点实际产生的会话都可查看，同一次工作流执行有多个会话时可逐个打开。未创建会话的执行通过执行记录展示进度、输出或完整错误。
- 定时器重命名、编辑或删除后，通过执行记录仍可按原定时器查阅该次运行的配置、结果和 Session。Job 或会话内容已被删除时，执行记录保留摘要并显示详情不可用的原因。

## 调度与数据边界

### FR-5 后端触发、并发与恢复

- 定时器由所连接的 Quartet 后端调度，客户端关闭后仍按计划执行。计划配置可随现有配置同步，启停、「待确认」状态、次数和执行历史在运行它的后端持久保存。另一台机器首次收到计划时按停用处理，用户可按 FR-6 在本机启用。
- 单个定时器默认最多同时执行一个任务，并发上限可配置。已受理且待启动或正在执行的任务占用名额。自动触发和立即运行共用该限制，满额时自动触发记为「并发跳过」，手动请求返回原因。工作流进入等待输入时释放名额，继续时重新检查并发，沿用原执行记录和次数。
- 自动触发与立即运行走同一受理流程。后端在启动 Job 前持久记录每次受理及其执行配置。自动触发按定时器和计划时刻去重，手动触发按同一次提交去重。同一次受理只产生一条执行记录、只计一次，最多创建一个 Job。Job 一旦创建，即使执行记录还未显示关联，后端重启后也能按该次受理找回原 Job。编辑、配置同步、停用、删除与触发相遇时，以后端受理顺序决定本次采用的配置与状态。
- 后端重启后，已受理的执行沿用原记录、次数和配置。确认尚未创建 Job 时，按已受理配置创建并启动。已有 Job 时先恢复关联，确认尚未启动的执行复用原 Job 继续启动，已创建的工作流运行或待发 Prompt 一并复用。确认已经启动的执行按原有 Job 恢复规则处理，可续跑的工作流沿用原有恢复入口。无法确认是否已经启动时，将原执行标记为「已中断」，在记录中显示完整原因并停止自动重试。并发名额按恢复后的状态计算，已中断的执行释放名额。
- 停机前已启用的定时器，恢复时将已过且未受理的计划分钟记为「已错过」，重复机会可合并显示为一个时间范围。重复计划从下个有效时刻继续，错过的单次计划进入「已结束」。

### FR-6 权限与存量数据

- Skill、Web 和 iOS 共用后端鉴权。查看定时器及执行摘要、管理配置、立即运行分别沿用现有定时任务权限。查看 Job 详情、Session 列表和内容，以及控制 Job，按相应的 Job 权限校验。
- 启用定时器（含创建时直接启用），或修改已启用定时器的执行配置或时间计划，须有定时任务配置权限（`schedule.write`）及目标类型的执行权限。Prompt 要求 `job.execute`，图工作流要求 `workflow.execute`。立即运行须有 `schedule.execute` 及目标类型的执行权限。权限不足时，后端拒绝操作并返回具体原因，保留原配置和启停状态。
- 启用授权只适用于当前后端已批准的实际执行配置和时间计划，包括 Prompt 内容或工作流版本、实际采用的工作区和目录、适用的 Agent 和模型、并发与超时、时区和结束条件。后端在受理触发时核对这些值。若配置同步或所引用的工作流更新导致已启用计划采用未获本机批准的配置，后端将计划标记为「待确认」，显示变更原因并暂停自动触发与立即运行。具备相应权限的账号须在当前后端核对实际配置并重新启用。已经受理的执行沿用原配置。
- 现有 Cron 工作流定时任务承接为重复型工作流定时器，保留原有名称、时间和执行配置。原来停用的计划保持停用。已启用且能核对实际配置的计划，以迁移时核对的工作流版本和执行配置作为本机已有授权，继续启用。已启用但无法核对的计划进入「待确认」并显示具体原因。已有定时任务 Job 按原归属进入执行历史，已有最近触发失败摘要可一并查看。

## 验收

### US-1 从 Skill 和界面管理同一计划（FR-1、FR-5、FR-6）

- [ ] 通过 Skill 新建 Prompt 定时器，在浏览器编辑并停用，在 iOS 查看修改后的配置。在浏览器新建图工作流定时器，Skill 可查询到同一记录。
- [ ] 用只读账号可以查询配置和历史，管理与执行操作按权限拒绝，并返回具体错误。
- [ ] 用只有 `schedule.write` 的账号将两类定时器保存为停用。分别尝试创建并启用、启用已保存的定时器、修改已启用定时器的执行配置或时间计划、将已启用定时器切换为另一种执行类型，以及立即运行。后端均拒绝并返回具体原因，配置和启停状态保持原值，未产生新的执行记录或 Job。另用具备 `schedule.write` 和 `job.execute`、缺少 `workflow.execute` 的账号验证启用 Prompt 成功，启用图工作流被拒绝。
- [ ] 在 A 后端启用两类定时器，在 B 后端停用对应计划。用只有配置权限的账号在 B 修改 Prompt 内容、图工作流目标或时间计划。同步后在 A 的浏览器确认显示「待确认」及原因。到达触发时刻、尝试立即运行或重启 A，均未产生新的执行记录或 Job。只有配置权限的账号无法重新启用，具备相应执行权限的配置账号确认并启用后，下一次有效触发采用已确认的配置。
- [ ] 用有 `workflow.write`、无 `workflow.execute` 的账号更新已启用定时器引用的工作流。确认该定时器进入「待确认」，到达触发时刻时没有启动 Job。授权账号确认并重新启用后，核对下一次运行采用新版本。另修改已启用 Prompt 定时器所在工作区的默认值，验证下次仍使用原先确认的值，改用新值时按执行配置变更校验权限。

### US-2 执行 Prompt 和工作流（FR-2、FR-4）

- [ ] Prompt 连续触发两次，产生两个独立 Job，每次只提交配置的一轮提示词。在浏览器打开两条记录和对应输出。
- [ ] 在浏览器从工作流定时器的记录打开对应运行，并处理澄清节点。删除显式绑定的工作流后，在下一次的记录中查看完整触发错误。

### US-3 按时执行与结束（FR-3、FR-5）

- [ ] 一次性计划在目标分钟只触发一次。对另一条单次计划在浏览器先点「立即运行」，到原定时刻时执行总数仍为一次。
- [ ] 重复计划分别验证次数先用完、结束日期先到两种情况。结束日 23:59 可受理合规触发，次日零点后停止受理。在浏览器确认跨过零点的 Job 可正常完成。
- [ ] 同一计划时刻重复调度或同一手动请求重试时，已受理的触发各保留一条记录、只计一次，最多创建一个 Job。并发满额时可查跳过原因，停机错过的周期和单次计划分别展示后续时刻和结束原因。
- [ ] 对 Prompt 和图工作流分别在「已受理、尚未创建 Job」和「Job 已创建、执行尚未启动」时重启后端，第二种情况覆盖执行记录尚未关联 Job。确认沿用原执行记录和配置，次数仅增加一次，每次受理只有一个 Job。已存在的 Job 被复用并启动，可查到该次 Prompt 或工作流的结果。
- [ ] 在「执行已启动、关联尚未写回」及「无法确认是否已经启动」时重启后端。前者找回原 Job 并按原有规则恢复，后者在原记录显示完整中断原因，重启或重试同一次提交均不会再次启动该次执行。在默认并发上限为一的重复计划中，确认中断的执行释放名额，下一次有效触发可以受理并启动。

### US-4 从独立页面管理定时任务（FR-4、FR-6）

- [ ] 在浏览器确认 Web 首页的「Scheduled Tasks」区块和「隐藏定时任务」开关均已移除，普通任务列表仅展示其他来源的 Job。通过主导航可进入独立的管理页面。
- [ ] 在浏览器打开某个定时器的元数据，核对执行目标、工作区、时区和结束条件。修改配置后重新打开页面，确认显示保存值。浏览器及 iOS 模拟器均可从定时器详情进入该定时器的执行历史。
- [ ] 同一定时器的多次执行按时间可查，运行结束顺序不同仍各自显示正确状态。在触发失败未生成 Job 时能读取完整错误，删除定时器后仍可打开已生成的 Job。
- [ ] 迁移后核对原来停用的计划保持停用，能核对实际配置的已启用计划继续运行，无法核对的已启用计划显示「待确认」及原因。核对已有 Job 的归属，前端类型检查、Lint 和对应构建检查通过。

### US-5 查看一次或多次执行的 Session（FR-4、FR-6）

- [ ] 在浏览器打开「Sessions」视图，找到多次 Prompt 执行产生的会话，以及同一次工作流执行中多个节点的会话。按指定执行筛选后逐个打开，确认消息、工具调用及所属执行正确。
- [ ] 在浏览器及 iOS 模拟器从执行记录进入当前运行和历史运行的 Sessions。删除定时器后，已有会话仍可从历史打开。触发失败且尚未创建会话时，可从执行记录读到完整错误。
