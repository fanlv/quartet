# Codex 账号登录态管理

> 创建日期：2026-10-17
> 状态：功能已实现；验证范围见第 11 节
> 范围：Quartet 后端、Web、iOS

## 1. 背景与目标

用户通过上传 Codex 的 `auth.json` 与 `config.toml` 保存多套账号配置，并选择其中一套应用到后端机器的 `~/.codex/`，减少手工替换文件的操作。

- 每条账号记录保存登录态及可选配置；切换时可以只替换登录态，也可以一并应用该账号的配置。
- Web 与 iOS 管理同一后端上的账号库和当前状态。
- 切换不打断正在执行的任务，不清空已有对话上下文。
- 保存 Codex 在使用过程中更新的登录态，避免再次切换时恢复旧凭据。
- 文件切换、账号可用性分别展示；失败时能够明确判断当前实际状态。

本功能管理的是后端机器的 Codex 账号，与登录 Quartet 的用户账号分开。账号库属于实例共享数据，不按 Quartet 用户或工作空间隔离，同一时刻只有一套当前配置。

## 2. 页面入口与展示

### 2.1 Web

在「设置 → Agent 管理」新增「Codex 账号」tab，放在「安装与升级」之后，沿用现有设置页样式。

页面由当前状态、账号列表和操作反馈组成：

- 当前状态：账号名称、可识别的邮箱或账号标识、实际目标目录、文件是否完整、最近一次应用结果和可用性检查结果。
- 主操作：「导入账号」「登录新账号」「保存本机当前账号」「刷新状态」。存在恢复快照时，提供「恢复上次切换前状态」。
- 账号列表：名称、认证类型、可识别的账号信息、配置中的模型与提供商摘要、更新时间、最近使用时间；当前记录显示「当前使用」。无法识别的信息不编造。
- 每条记录支持「切换到此账号」「编辑名称与备注」「更新文件」「删除」。当前记录保留编辑入口，附带配置时可以重新应用配置。
- 空列表说明两个文件的用途，同时提供上传和保存本机账号的入口。
- 加载失败展示完整错误与重试入口，不能以空列表替代失败结果。

### 2.2 iOS

iOS 当前在设置页的「Agent 管理」分组直接展示各功能入口。本次增加同名「Codex 账号」入口，进入独立页面，功能和状态与 Web 一致，沿用现有原生导航。

导入和更新使用系统「文件」选择器，可以分别选择两个文件；支持来自「我的 iPhone」和 iCloud Drive 的文件。账号操作沿用现有 Sheet，错误详情支持完整展示和复制，提供中英文、VoiceOver 与动态字体支持。

两端明确说明「本机」是当前连接的 Quartet 后端机器。iOS 不访问手机上的 `~/.codex/`，浏览器也不直接写入用户电脑的目录。

## 3. 账号记录与导入

### FR-1：保存内容

每条记录包含独立且稳定的记录标识、必填名称、可选备注、完整登录态、可选配置，以及创建、更新和最近使用时间。邮箱和账号标识用于辅助识别，不作为记录唯一键。

支持 ChatGPT 登录态及文件中自带凭据的 API Key 登录态。只能从环境变量取得密钥的配置不视为一套可独立切换的完整账号。

### FR-2：上传导入

1. 用户填写名称、备注并选择必需的 `auth.json` 与可选的 `config.toml`；Web 同时支持拖入两个文件，两个客户端均允许分别选择。
2. 保存前检查登录态是否齐全、上传的 JSON/TOML 能否解析，以及是否包含所支持认证方式必需的凭据。错误指出文件和具体原因。
3. 用户保存后，在账号列表展示可识别的账号与配置摘要。
4. 导入只新增管理记录，不改变当前目录内容，不启动登录或自动切换账号。

上传文件按原样保存和应用，保留未知字段与配置注释。默认只替换登录态；勾选同时应用配置时，说明将整份替换该账号保存的用户级配置，不做隐式合并。当前账号也可以重新应用配置。

同样文件重复导入时提示已有记录；同一账号使用不同配置时允许另存，不按邮箱自动合并或覆盖。更新已有记录必须由用户显式选择。

### FR-3：保存本机与更新

「保存本机当前账号」读取后端目标目录中的双文件，填写名称后存入账号库；不要求先把文件下载到客户端。缺登录态或解析失败时完整报错；本机没有配置文件时仍可保存为仅登录态记录。

「更新文件」允许更换其中一个或两个文件；只更新一个时，与该记录保存的另一个文件组成完整配置后重新检查。更新其他记录不影响当前目录；更新当前记录的文件必须走与账号切换相同的应用流程，不能只改存档却仍标记已经应用。被占用或应用失败时，保留原记录和原生效文件。

### FR-4：删除

删除非当前记录只删除该记录及其文件，不影响当前 Codex 登录。删除当前记录时，明确确认「从管理中移除，保留本机当前登录」；完成后当前状态变为「本机账号，未纳管」。删除不执行 Codex 退出登录。

## 4. 应用目录与生效条件

### FR-5：明确目标

默认管理后端运行用户的 `~/.codex/`；已配置 `CODEX_HOME` 时沿用 Codex 的实际目录，页面展示解析后的绝对路径。目标目录不存在时可在应用时创建，只替换 `auth.json` 与 `config.toml`，保留会话、历史、插件、Skills 等其他内容。

首期同一时刻只管理 Codex 当前实际使用的一个目录；备份归属原目录，环境切换到其他目录后不允许跨目录恢复。用量查询与账号管理使用相同目录。

设备码登录可以关闭窗口后继续运行；返回页面或重新进入时可查看正在进行的登录并取消。

文件切换要求 Codex 实际从文件读取凭据。系统钥匙串、自动选择到钥匙串、仅进程内凭据，以及更高优先级的认证配置，都可能使上传文件无法成为实际登录来源。检测到这些冲突时保留记录、阻止应用并提供具体调整指引，不静默改写上传配置或删除钥匙串凭据。环境变量只展示相关键名和来源，不回传值。

模型和其他配置仍遵循 Codex 自身优先级。用户级文件已经应用，不代表它一定覆盖项目配置、命令行参数或受管理策略。

## 5. 切换与恢复

### FR-6：切换流程

1. 重新检查目标记录、当前磁盘状态、生效条件和占用情况，不能仅相信客户端上一次读取的状态。
2. 在停止接收针对该目录的新执行后，再确认没有正在使用它的任务、认证或验证操作。
3. 将当前受管账号的最新双文件回存到对应记录，并保留本次覆盖前的恢复快照；原本不存在的文件也必须记录为不存在。
4. 释放已空闲的旧 Codex 进程，应用目标登录态及用户选中的账号配置，并检查写入结果。
5. 确认两份文件完整应用后更新当前记录、最近使用时间和操作结果，再恢复后续调度。
6. 使用全新 Codex 进程重新检查可用性，刷新 Agent 列表、模型选择与当前用量展示，丢弃切换前尚未完成的旧查询结果。

两份文件应用期间，Quartet 不得启动读取该目录的新 Agent 操作。任一文件写入或应用结果保存失败，恢复覆盖前状态；不能留下新账号凭据配旧账号配置的状态。如果检测到外部程序在此期间写入，停止应用并报告冲突；不能以自动回滚覆盖外部新文件，无法安全恢复时阻止相关执行并保留恢复入口。

不重启 Quartet 后端。复用已有会话时恢复原有 Codex 会话，保留上下文；恢复失败展示完整错误，不通过重置会话或创建空会话掩盖失败。

### FR-7：区分应用与可用性

「当前使用」表示当前目录已应用该记录；「未检查／检查中／可用／不可用」单独表示最近一次 Agent 可用性检查结果，并展示时间和完整错误。导入成功或文件可解析不能直接标记账号可用。

写入失败会回滚；文件已经完整应用后的可用性检查失败，不自动切回旧账号，明确展示「文件已应用，验证失败」。用户可以重试验证、切换其他账号或恢复。断网、额度不足、身份失效和模型不可用要保留各自实际错误，不能统一解释为需要重新登录。

沿用现有 Agent 可用性检查，不额外发送计费测试消息；检查通过也不承诺下一次实际请求一定成功。首期只刷新当前账号用量，不为全部存档账号轮流切换、验证或请求额度；版本号仍先于套餐和额度展示。

### FR-8：占用与并发

- 使用该目录的交互轮次、Graph 节点、停止中的执行，以及仍占用进程的工具或权限确认，均阻止切换；展示执行占用数量或具体进程占用信息，提示结束后重试。
- 登录、安装升级、环境变量修改和后台验证等相关操作不得与应用过程交错修改运行状态；自动验证可延后，显式冲突完整返回。
- 不自动停止任务，不通过重置会话解决冲突。其他 Agent 的任务继续执行。
- 已结束的对话、尚未开始的 Graph 节点、后续定时任务及排队请求，在下一次真正执行时使用新的全局账号；不为历史 Job 固定绑定账号。
- Web 与 iOS 同时切换、更新或恢复时只允许一个操作提交。另一端拿旧状态发起的操作返回状态冲突，刷新后由用户决定，不自动覆盖。
- 提交后遇到客户端超时或断网，可重新查询该次操作结果；重复提交不能再次切换、覆盖备份或回存到错误账号。

切换作用于共享目录。Quartet 只能协调自身管理的进程；用户应先退出仍使用该目录的外部 Codex CLI 或 IDE 会话。页面提供一次清楚的作用范围说明，不承诺外部进程热切换，也不自动关闭外部应用。

### FR-9：恢复能力

保留最近一次覆盖前状态，包括首次覆盖未纳管本机文件的状态，支持「恢复上次切换前状态」。恢复沿用切换的占用检查、并发规则和错误反馈，不能覆盖恢复过程中其他来源的新修改。恢复后对应记录已被删除时，显示为「本机账号，未纳管」，不自动重建已删除记录。

应用中断或后端异常退出后，下一次启动先恢复到一套完整状态，再允许相关 Codex 执行。恢复失败时阻止相关执行并显示原始错误和恢复错误；其他 Agent 不受影响。

恢复快照独立于账号记录，删除或更新记录不使已有恢复能力立即消失；后续成功切换可以替换上一份快照。该快照仅用于最近一次文件替换的恢复，不作为长期备份历史。

## 6. 登录态更新与外部修改

### FR-10：保存最新登录态

Codex 自己负责令牌刷新，Quartet 不另行调用刷新接口。当前受管账号在一轮使用结束、显式刷新状态及切换离开前，检查并回存最新文件。后端重新启动时也重新核对磁盘状态，不将存档里的旧文件自动覆盖回当前目录。

只有确认磁盘上的身份仍属于当前记录，才自动回存；令牌正常刷新不能被当作换了账号。账号身份与令牌内容分开判断，不能仅凭文件字节是否相同判断当前账号。

如果用户在外部重新登录为另一个账号，显示「本机登录已在外部变更」，不把新凭据写进旧记录。用户可保存为新记录、明确更新选定记录或重新应用某条记录；应用前仍保留当前文件快照。无法可靠确认身份时也不自动覆盖存档。

当前记录已经应用账号配置时，同一身份下外部修改的用户配置随当前受管记录回存；只切登录态的记录不接管机器上的共享配置。检测到文件缺失、损坏或应用期间被再次修改时，完整报错并保留已有存档，不将损坏内容覆盖进去；文件已全部被外部移除时显示未登录或文件缺失。

Web 在进入页面、重新获得焦点及操作结束后刷新；iOS 在进入页面、返回前台和下拉刷新时读取后端状态。切换服务器后重新加载，旧服务器的异步结果不得覆盖新状态。

## 7. 权限与凭据保存

### FR-11：权限

账号管理页面及其查看、导入、更新、切换、恢复和删除能力统一复用「管理 Agent」权限，与现有 Agent 登录能力保持一致。只有「查看 Agent」权限时不提供账号库入口。

所有访问走 Quartet 私有鉴权；修改操作沿用现有 CSRF 要求，不提供公开分享入口。共享账号库不代表匿名可访问。

### FR-12：保存与错误

账号文件和恢复快照保存在 Quartet 的持久数据区域，独立于生效目录，限制为后端运行用户可读写；不得进入仓库、普通附件或公开文件分享。应用后的凭据文件采用同样的权限要求。

客户端只获取账号元信息和操作状态，不通过账号管理接口下载原始凭据；不把文件内容写入浏览器持久存储、iOS 缓存或诊断日志。首期不提供原文预览、在线编辑或凭据导出。

错误详情保留完整原因、底层错误链和可复制内容，不截断或吞掉响应。错误生成与请求日志不主动附带上传原文或凭据值；这不影响完整展示实际错误信息。

## 8. 用户故事与验收

### US-001：保存多个账号

作为用户，我可以导入两套完整文件，分别命名，稍后选择使用。

- [ ] Web 支持选择和拖入，iOS 支持系统文件选择；两个文件可以分别补齐。
- [ ] 导入不改变当前文件；缺文件、无效 JSON/TOML、凭据缺失均明确报错。
- [ ] 上传内容、配置注释和未知字段保留；同邮箱不会自动合并不同记录。
- [ ] 可以保存后端当前账号、改名、更新文件和删除；重启后记录仍存在。
- [ ] Web 在浏览器实测；iOS 在模拟器验证导入流程，并在真机验证 iCloud 文件读取。

### US-002：切换并继续对话

作为用户，我可以从账号 A 切到 B，并在下一轮使用 B，同时保留原对话。

- [ ] 两份文件均来自 B，其他 Codex 文件不变，无需重启 Quartet。
- [ ] 运行中、等待确认及停止中的 Codex 执行会阻止切换，其他 Agent 不受影响。
- [ ] 下一轮使用新凭据并恢复原会话；恢复失败不会创建空会话顶替。
- [ ] 当前标识、Agent 可用性、模型和用量更新，迟到的旧查询不覆盖新结果。
- [ ] Web 在浏览器验证，iOS 在模拟器验证；真实账号切换与续聊在可信后端实测。

### US-003：保留刷新后的凭据

作为用户，我切走再切回时可以使用 Codex 最近刷新后的登录态。

- [ ] A 使用中产生新令牌后切到 B，再切回 A，不恢复 A 的旧凭据。
- [ ] 外部改成另一账号时不会覆盖 A 的存档；正常令牌刷新不会误报换号。
- [ ] 文件缺失或损坏不会破坏已保存记录；后台重启不反向覆盖当前文件。
- [ ] Web 浏览器与 iOS 前后台刷新均显示后端实际状态。

### US-004：从失败中恢复

作为用户，我可以知道操作是否生效，并在替换失败时恢复原状。

- [ ] 模拟任一文件写入失败，均恢复旧双文件；原本不存在的文件恢复为不存在。
- [ ] 完整应用后断网或验证失败，仍准确显示当前文件归属与完整验证错误。
- [ ] 首次覆盖本机未纳管配置后可以恢复；恢复失败明确展示全部错误。
- [ ] 后端在应用途中退出，重启先恢复，再接受相关执行。
- [ ] Web 与 iOS 并发操作只有一个提交；超时重试不重复应用或覆盖备份。
- [ ] 两端错误详情完整可复制；Web 在浏览器、iOS 在模拟器验证全部反馈状态。

### US-005：权限与跨端一致

作为管理员，我可以在两端管理同一账号库，普通查看者不能操作。

- [ ] 管理权限、私有鉴权和 CSRF 规则生效，无权限请求被后端拒绝。
- [ ] iOS 切换后，Web 刷新显示相同结果；反向操作也一致。
- [ ] 切换后端地址时，列表、操作结果和未完成请求不串到其他服务器。
- [ ] 中文、英文、窄屏、深浅主题及 VoiceOver 均可完成核心操作。
- [ ] 列表响应、客户端缓存和日志不包含凭据原文。

交付时运行相应 Go、Web 与 iOS 已有检查。iOS 原生构建与 UI 验证在 macOS/Xcode 完成；Linux 上的静态检查不能替代该验证。

## 9. 首期边界

首期提供手动管理一个后端目录中的多套文件，不包含按工作空间或 Job 绑定账号、多账号并行执行、按额度自动轮换、跨机器账号同步、长期令牌保活、钥匙串管理，以及新的自建 OAuth 协议。新增“登录新账号”入口，在独立目录运行 Codex 官方设备码登录，完成后保存新账号，保留现有账号登录。已有 Agent 登录能力继续使用。

上传文件不等于凭据永久有效；外部机器继续使用同一套令牌，可能影响后续刷新。遇到实际认证失效时，沿用已有登录入口重新登录并更新记录。

- Codex 可以使用文件或系统凭据存储，文件位置受 `CODEX_HOME` 影响，管理员可强制认证要求。[Authentication](https://learn.chatgpt.com/docs/auth)
- Codex 会在正常使用时刷新并回写 `auth.json`，应保留更新后的文件；多处同时使用同一份登录态可能引发刷新冲突。[Maintain Codex account auth in CI/CD](https://learn.chatgpt.com/docs/auth/ci-cd-auth)
- 用户级配置与项目、命令行及其他配置层存在优先级关系。[Config basics](https://learn.chatgpt.com/docs/config-file/config-basic)
