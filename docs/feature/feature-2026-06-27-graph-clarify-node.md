# 技术方案：Graph 工作流「交互澄清结点」

## 背景与目标

Graph 工作流是有向无环图，每个结点是一次确定性执行：Prompt 结点一次提问、一次回复、写输出变量，然后结束。但很多真实任务的第一步是「方案澄清」——目标明确，但具体怎么做没想好，需要模型先给方案，再和人反复多轮讨论、确认，讨论收敛后才进入执行。这种交互轮数事先不确定，硬拆成 N 个固定结点是反模式（轮数写死、不灵活）。

关键事实：一次开放式多轮讨论天然属于「一个会话」，不属于「N 个结点」。当前图引擎缺一个能停下来、保持会话开放、接受人多轮输入、直到人点「讨论完成」才继续的原语。

**目标**：新增一种业务结点——**交互澄清结点（clarify）**。它在被调度到时跑出初版方案并开出会话，随后把整个 run 停到「等待人工」态；人在该结点会话里自由多轮讨论；人点「讨论完成」后，run 续跑、DAG 继续往下执行。

**明确不做**：不强制下游执行结点继承（inherit）这个澄清会话。澄清结点把「讨论结论」以输出变量的形式对外暴露，下游是否引用、是否继承会话，完全由用户在画布上自行决定（与现有 Prompt 结点的会话策略保持一致，无任何特殊耦合）。

## 范围

**做**：

- 新增结点类型 `clarify`（业务结点，单入单出，无 yes/no 分支）。
- 新增运行态「等待人工输入」（resumable 终态语义），以及对应的实例态。
- 澄清结点执行：可选初始 prompt 跑一轮产出初版方案、开出会话、早现会话到侧边栏。
- 停泊：当 run 的可调度前沿排空且存在等待人工的澄清实例时，整个 run 落到「等待人工」态，Job 置为可继续状态，使既有 Chat 链路能向该会话追加多轮对话。
- 续跑：人点「讨论完成」后，把澄清结点的「讨论结论」固化为输出变量、置该实例为成功、解析其出边，DAG 继续；其余前沿沿用既有续跑重建。
- 前端：画布新增 clarify 结点类型与配置面板、运行区新增「讨论完成 / 继续」操作、会话侧边栏纳入该结点会话并允许在「等待人工」期间输入。

**不做**：

- 不强制下游 inherit 澄清会话（用户自行决定）。
- 不引入新的聊天接口（复用既有「向已有会话追加消息」的能力）。
- 不改变其他结点类型（Shell/Prompt/If-Else/循环/start/end）的语义。
- 不覆盖 Graph 类型 Job 的公开分享。

## 术语

- **交互澄清结点（clarify）**：本方案新增的业务结点，运行到时产出初版方案、开会话、把 run 停到等待人工态，人多轮讨论后续跑。
- **等待人工态**：run 的一个可续跑终态（语义类比暂停/停止），表示调度器已退出、等待人点「讨论完成」。
- **讨论结论**：澄清结点对外暴露的结果，默认取该会话最后一条助手消息，写入保留变量 `_last_assistant_msg` 与可选别名变量、以及结点声明的输出变量。

## 与现有机制的关系（设计前提）

1. 调度器是单 goroutine、单写者；暂停时调度器会退出，靠续跑重新拉起新调度器。因此「等人」不能靠阻塞 goroutine 实现，只能落到一个可续跑终态、再用续跑机制继续。
2. 既有 Chat「向已有会话追加消息」的链路已能给 graph 结点会话追加多轮对话；但 Job 处于运行中时该操作会被拒绝。因此 run 必须先停到「等待人工」态（Job 置为可继续状态），讨论才能进行。
3. 出边续跑机制已存在：续跑会从持久化的实例/边状态重建就绪前沿并继续裁决。本方案的「讨论完成」复用这套机制，不另造一套并行逻辑。
4. If-Else 已证明「在调度 goroutine 内同步裁决、不占并发名额、解析出边」是成立的；澄清结点的停泊与续跑沿用同类思路。

## 用户流程

1. 在画布添加「交互澄清结点」，配置其 Agent / 模型、可选的初始 prompt、可选的输出变量与 `_last_assistant_msg` 别名。
2. 运行工作流。澄清结点被调度到时：若配置了初始 prompt 则先跑一轮产出初版方案并开出会话；否则只开一个空会话。该会话即时出现在 Chat 会话侧边栏。
3. 当该澄清结点成为当前可调度前沿的尽头（其余并行分支也已停下或无可调度项），整个 run 落到「等待人工」态，运行区显示等待状态与「讨论完成」操作。
4. 人在该结点会话里自由多轮讨论、追问、修改方案（这些对话都追加进同一会话）。
5. 人点「讨论完成」。系统把该会话当前的讨论结论固化为澄清结点的输出，置该实例为成功，解析其出边，run 续跑、DAG 继续往下执行。
6. 下游结点按各自配置执行：可用 `{{...}}` 引用澄清结点的输出变量，也可完全不引用；是否继承澄清会话由下游自身的会话策略决定，本结点不强制。

## 方案设计

### 1. 数据模型

- 结点类型新增 `clarify`，归类为业务结点（计入进度分母、占调度名额、可声明输出变量与 `_last_assistant_msg` 别名）。
- 结点配置复用 Prompt 同款字段：Agent 类型、模型、ACP 模式/思考级别、会话策略、初始 prompt（本结点语义下「可选」）、输出变量、别名、结点超时。
- 端口：单入单出，不使用 yes/no 分支端口（与 Prompt 一致）。
- 运行态新增「等待人工输入」：归入可续跑终态集合（可被续跑、可被静态版本编辑、可被删除），不归入「在飞」集合。
- 实例态新增「等待人工输入」：表示该澄清实例已开会话、正等待人讨论，属于非终态持有。

### 2. 结点执行（产出初版方案 + 开会话）

- 澄清结点被裁决为激活后，作为业务结点入就绪队列，由工作线程执行。
- 执行时按会话策略开会话（默认新建），若配置了初始 prompt 则跑一轮、产出初版方案；prompt 为空则只开会话不跑模型。
- 会话一经创建即「早现」到侧边栏，并加入该 Job 的会话白名单，使后续 Chat 追加消息能命中它。

### 3. 停泊为「等待人工」态

- 结点这一轮执行结束后，**不立即解析出边、不推进下游**，而是把该实例标记为「等待人工输入」并持有其出边。
- 当 run 的可调度前沿排空、且在飞工作线程清空、且存在「等待人工」实例时，整个 run 落到「等待人工」态：持久化运行状态、把绑定 Job 置为可继续状态（使既有 Chat 追加消息链路不再因 Job 运行中而被拒）。
- 该机制与既有「优雅暂停/停止」收尾同源：调度器退出、状态可续跑，区别仅在于落点是新的「等待人工」态、且触发条件是存在等待人工的澄清实例。

### 4. 多轮讨论

- run 停在「等待人工」态期间，人通过既有 Chat「向已有会话追加消息」的能力，在该澄清结点会话里多轮讨论。无需新增任何聊天接口。

### 5. 讨论完成 / 续跑

- 运行区提供「讨论完成 / 继续」操作。触发后：对每个「等待人工」的澄清实例——读取该会话当前的讨论结论（默认取最后一条助手消息），写入 `_last_assistant_msg`、可选别名变量与结点声明的输出变量；将该实例置为成功；解析其先前持有的出边，从而触发下游裁决。
- 随后按既有续跑机制重建其余就绪前沿并继续运行，直到下一处「等待人工」或自然结束。
- 下游对结论的获取只通过输出变量（`{{...}}` 引用）。是否继承澄清会话由下游会话策略自定，本结点不强制 inherit。

### 6. 校验

- 澄清结点纳入业务结点的通用结构校验（须有入边、出边，不得使用 yes/no 分支端口）。
- 复用 Prompt 的会话校验：新建会话时须指定 Agent；继承策略豁免。
- 输出变量/别名复用既有保留命名空间与重名校验。

### 7. 续跑与边界

- 「等待人工」实例属于不可重置终态语义：续跑（含失败续跑）不会把它当作可重置项清掉，而是按「讨论完成」路径固化结论后推进。
- 等待人工期间，允许对 run 的未开始部分做静态版本编辑、允许删除非在飞 run。
- 多分支并行时，只有当其余分支均已停下或无可调度项、run 才落到「等待人工」态；澄清结点本身在其所在前沿停泊，不影响其它已完成分支的既有结论。

## 前端设计

- 结点类型联合、画布结点渲染、调色板、检查器配置面板、结点创建默认值均新增 clarify 一项，配置面板复用 Prompt 同款字段并把初始 prompt 标注为可选。
- 运行区在「等待人工」态展示等待提示与「讨论完成 / 继续」按钮，调用续跑/继续动作。
- 会话侧边栏纳入澄清结点会话；在该结点处于「等待人工」态时，放开会话输入框，使人能在其会话中多轮讨论（现状仅对已结束会话放开输入）。
- 运行状态徽标、进度展示、SSE 流终止判定均纳入新的「等待人工」态。

## 后端落点（按现有分层）

- `types/model`：新增 clarify 结点类型、等待人工运行态与实例态。
- `services/graph`：结点执行分支（开会话 + 可选初版方案）、停泊收尾（落「等待人工」态）、续跑入口（固化结论 + 解析出边 + 复用既有前沿重建）、校验、控制/续跑状态判定集合。
- `cmd/web/handler` 与路由：新增「讨论完成 / 继续」动作入口；SSE 流终止判定纳入新态。
- 复用既有「向已有会话追加消息」「读取会话末条助手消息」的能力，无需新增聊天接口。

## 验证

- 后端 `make build-all`、前端 `npm run build` 通过。
- 端到端：构造 `start → clarify → shell(echo {{plan}}) → end`，clarify 配置初始 prompt「给个方案」；运行后确认 run 落到「等待人工」态、该结点会话出现在侧边栏；在会话内多轮追问改方案；点「讨论完成」，确认 DAG 续跑、下游看到末轮结论、run 走到完成。
- 边界：等待人工期间删除 run / 静态版本编辑可用；多分支并行时仅在其余前沿停下后才落「等待人工」态。
- 按仓库约定，开发期不加单测，除非显式要求。
