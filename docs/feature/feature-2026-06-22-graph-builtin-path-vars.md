# 技术方案：工作流全局变量内置 Code / Doc 路径变量

## 背景

当前 graph workflow 的全局变量是一张纯字符串键值表，用户需要手动敲变量名和值。

实际使用中，几乎每个工作流都要把「代码所在位置」和「文档所在位置」交给 Shell / Agent 节点使用。用户每次都得手动新建同名变量、手敲绝对路径，既重复又易错（路径敲错、漏建、命名不统一）。

## 目标

在全局变量里固定预置 `Code`、`Doc` 两个内置变量，开箱即用；其值既能手动输入任意字符串，也能通过选择器挑选一个真实的目录或文件，把其绝对路径回填进来。

## 范围

做：
- 全局变量固定内置 `Code`、`Doc` 两个变量，新建与打开已有工作流都自动具备。
- 为这两个内置变量提供「浏览」入口，弹出选择器，可选目录或文件，选中后其绝对路径回填为变量值；也可直接在输入框手敲字符串。
- 选择器复用现有目录选择能力，并扩展为既能选目录也能选文件。

不做：
- 不改变量的存储形态（仍是字符串键值表），不引入「变量类型」元数据。
- 不改运行时变量注入 / 替换逻辑（内置变量与普通全局变量在运行时完全等同）。
- 不限制这两个变量的取值（可为空、可为任意字符串，不强校验路径是否存在）。
- 后端不改动。

## 方案设计

### 内置变量语义

`Code`、`Doc` 是两个名字固定的全局变量，约定分别承载「代码位置」「文档位置」。它们与用户自建的全局变量在运行时没有任何区别——同样作为环境变量注入 Shell 节点、同样支持 `{{Code}}` / `{{Doc}}` 文本替换。「内置」只体现在编辑器层面：固定存在、不可改名、不可删除。

### 固定预置

工作流的全局变量在进入编辑器时统一补齐 `Code`、`Doc`：新建工作流默认带上这两个变量（初值为空），打开缺少它们的旧工作流时自动补齐。

补齐属于规范化行为，不应被判定为「未保存改动」——用户未实际编辑前，编辑器不提示「有改动」；只有用户真正改了值（或其他内容）才算改动。保存时这两个变量随全局变量一并持久化。

### 编辑器交互

全局变量面板分两区：
- 内置变量区：固定展示 `Code`、`Doc` 两行。每行有变量名（只读，不可改名 / 删除）、值输入框（可自由输入字符串）、一个「浏览」按钮、以及与普通变量一致的「禁用」勾选框（禁用后下游替换为空串）。
- 自定义变量区：维持现状的增删改表格，但不再展示 `Code` / `Doc`（它们归内置区管理），且禁止用户新建与内置变量重名的自定义变量，避免冲突。

点击「浏览」弹出路径选择器，初始定位到当前工作流的工作目录（无则用默认根），用户在其中导航并选定一个目录或文件，确认后把该绝对路径写回对应变量值。

### 路径选择器

复用现有目录选择器，扩展出「可选文件」能力：在原有目录导航 / 面包屑 / 最近目录 / 新建文件夹的基础上，列表额外展示文件项；单击目录进入下级，单击文件将其选为当前选中项；确认时返回当前选中的目录或文件路径。

该增强对原有「只选目录」的调用方（工作区设置等）保持兼容（默认仍只选目录）。后端列目录接口已支持返回文件列表，无需改动。

## 风险

- 内置变量补齐若处理不当会让旧工作流「打开即提示未保存」。通过让补齐后的编辑器状态与保存基线一致来规避，使补齐对用户无感。
- 用户仍可能把变量值留空或填入不存在的路径。沿用现有「不强校验、按字符串处理」的约定，由工作流自身逻辑负责，不在此拦截。

## 可观测性

纯前端编辑器改动，无后端逻辑、无新增日志。

## 执行步骤

1. 路径选择器：扩展现有目录选择器，支持选择文件（列表展示文件、单击文件选中、确认返回目录或文件路径），保持「只选目录」旧调用兼容。
2. 编辑器内置变量区：在全局变量面板新增内置变量区，固定渲染 `Code`、`Doc`（只读变量名、值输入框、浏览按钮、禁用勾选）；自定义变量区排除内置变量并禁止重名。
3. 固定预置与基线一致：工作流进入编辑器时补齐 `Code`、`Doc`，并保证补齐不触发「未保存改动」；保存时随全局变量持久化。
4. 文案：补充内置变量区相关中英文案。
5. 校验：前端 build / lint 通过，无回归。

## 验收标准

（以手工验证为主，按现有前端 build / lint 校验不引入回归；按仓库约定不新增单元测试。）

- 新建工作流：全局变量默认含 `Code`、`Doc` 两个内置变量，初值为空。
- 打开旧工作流（原本无 `Code` / `Doc`）：自动补齐两个内置变量，且不被提示「有未保存改动」。
- 内置变量不可改名、不可删除；可手动输入任意字符串作为值。
- 点击「浏览」可弹出选择器，既能选目录也能选文件，确认后绝对路径回填到对应变量值。
- 内置变量的「禁用」勾选生效：禁用后下游 `{{Code}}` / `{{Doc}}` 与环境变量替换为空串。
- 自定义变量区不再展示 `Code` / `Doc`；尝试新建同名自定义变量被阻止。
- 运行工作流时，`Code`、`Doc` 与普通全局变量行为一致（Shell 环境变量注入、Prompt 文本替换）。
- 选择器作为目录选择器的原有调用方（工作区设置等）行为不回归。
