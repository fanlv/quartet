# Bug Fix: 图片消息气泡右侧空白

日期：2026-05-20

## 问题描述

用户消息包含图片时，聊天界面里的黑色用户气泡右侧会出现明显空白。消息整体已经靠右对齐，问题不是消息行位置错误，而是气泡本身被撑得过宽。

在问题页面中，图片实际展示宽度约为 480px，但用户气泡宽度约为 879px，因此图片右侧留下了大面积黑色空白。

## 触发场景

该问题主要出现在用户消息中的图片通过 Markdown 内容渲染时。历史消息或非多模态消息路径可能把图片和文本一起放进同一段用户消息内容中展示。

当图片宽高比例较宽、原始尺寸较大，并且页面对图片展示高度或宽度做了限制时，问题会更加明显。

## 根因分析

用户气泡宽度依赖内容自身尺寸进行收缩计算，而图片展示又只设置了最大展示限制，没有在布局阶段提供明确的最终展示宽度。

浏览器计算气泡宽度时，会参考图片的原始尺寸或内容最大宽度；但图片真正绘制时又会被最大宽度、最大高度和视口限制缩小。结果就是：

1. 气泡先按照偏大的内容宽度完成布局。
2. 图片随后按展示规则缩小。
3. 气泡宽度和图片实际展示宽度不一致。
4. 图片右侧出现看起来像“气泡空白”的黑色区域。

这不是图片加载失败，也不是消息右对齐失败，而是父级气泡的内容宽度计算和图片最终渲染尺寸不一致。

## 修复方案

修复方向是让图片在完成加载后，按图片真实宽高、当前页面展示限制和视口高度计算出最终展示宽度，并把这个宽度作为图片的明确布局宽度。

这样用户气泡在收缩宽度时，拿到的是图片最终会占用的宽度，而不是图片原始尺寸或偏大的内容宽度。气泡宽度会跟随图片和文字内容自然收缩，右侧不会再保留多余空白。

同时保留原有图片展示上限：

- 用户消息图片仍保持较小的最大展示尺寸。
- Markdown 内容图片仍可以按现有规则展示。
- 图片点击查看、加载失败占位和认证访问行为不变。

## 影响范围

影响范围仅限聊天消息中图片的前端展示布局。

不改变消息数据结构，不改变图片上传、服务端文件访问、历史消息读取、Agent 消息发送和多模态消息处理逻辑。

## 验证结果

已在问题页面确认气泡过宽来自用户气泡自身布局宽度，而不是消息行对齐问题。

前端构建已通过，说明本次改动没有引入 TypeScript 或构建层面的错误。
