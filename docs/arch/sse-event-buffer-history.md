# SSE 消息流历史背景

> 最后校验：2026-06-11

## 旧链路问题

旧事件链路同时依赖共享重放窗口和每个订阅者自己的队列。这个结构在普通短任务下可以工作，但在长时间、高事件量 job 中会暴露根本矛盾：系统既不希望慢客户端阻塞 job 执行，又希望客户端断线后能恢复完整实时过程。

当事件产生速度长期高于某个客户端的消费速度时，旧链路会出现三类问题：

1. 终态通知可能在慢连接上投递失败，前端看不到真实结束状态。
2. 重放窗口可能被大量实时事件覆盖，断线客户端无法恢复完整过程。
3. 非终态实时事件可能因为订阅者队列堆满而被静默丢弃。

这些问题不是单纯调大容量就能解决的。容量越大，只能推迟问题出现；只要仍然为每个订阅者维护独立有界队列，慢消费者和完整恢复之间的冲突就会存在。

## 重构方向

新设计把“当前状态”“已完成消息历史”和“实时增量”拆开：

- 当前状态用于刷新、恢复和列表展示。
- 消息历史用于重建已经完成的对话内容。
- 实时增量只用于当前连接之后发生的变化和短期续接。

订阅者不再拥有独立事件队列，而是通过游标读取共享缓冲。这样慢客户端不会反压 job 执行，也不会迫使服务端在正常路径中静默丢事件。
